# 主要模块与接口说明

> 状态：现行
> 更新日期：2026-07-26
> 适用范围：`src/` 下主要模块的稳定职责与入口，含 2026-07-26 新增的外部辅助模块与 TUI 管理入口
> 注意：本文只列稳定职责和主要入口，不承诺完整 Python API；准确签名以源码和测试为准。

## 1. 模型管理

文件：`src/model_module.py`、`src/llama_engine.py`、`src/model_config.py`

`ModelManager` 统一管理 PyTorch 与 llama.cpp 引擎：

- `select_engine(profile)`：结合显式配置、CUDA 和设备画像选择引擎。
- `load_model(...)` / `unload_model()` / `switch_model(...)`：加载、卸载和切换注册模型。
- `load_layer_range(...)` / `ensure_layer_range(...)`：加载或确认 PyTorch 连续层段及 Embedding/LM Head 权重。
- `ensure_full_model(...)`：在回退完整推理前确认完整模型已加载。
- `forward_layers(...)`：执行 PyTorch 层段前向。
- `chat(...)` / `chat_stream(...)`：完整模型对话入口。

模型注册信息由 `model_config.py` 管理。模型文件存在不等于可以进入分布式流水线，还需模型身份同步、能力检查和层配置 ready ACK。

## 2. TCP 通信

文件：`src/tcp_comm.py`

- `TCPServer.start(...)`：主节点监听并处理注册、认证、心跳和业务消息。
- `TCPServer.send_to_client(...)` / `broadcast(...)`：向已注册节点发送消息。
- `TCPClient.connect(...)` / `disconnect()`：从节点建立或关闭连接，并负责重连状态。
- `TCPClient.send_data(...)` / `recv_data(...)`：发送和接收协议消息。
- `serialize_tensor_fast(...)` / `deserialize_tensor_fast(...)`：层流水线张量序列化。
- `MessageType`：注册、配置、推理转发、层前向、结果、取消和心跳等消息类型。

TCP 连接成功、节点注册成功、模型同步成功和流水线 ready 是四个不同状态，UI 和调度器不能互相替代。

2026-07-26 修正了以下行为，读代码或排查“节点假在线”时应以现行实现为准（均经双节点实测验证）：

- 客户端 `_recv_loop` 的清理放入 `finally` 并补齐兜底 `except`：此前帧解析异常会让接收线程静默退出，形成心跳仍在发、主节点仍视其在线、且永不重连的“僵尸连接”。
- `recv_exact()` 区分**空闲超时**与**帧中途超时**：帧读到一半超时不再丢弃已读字节并 `continue`（会造成字节流失步），而是抛 `ConnectionError` 走重连。
- 连接代数在**注册成功后**才推进：此前注册失败会把心跳与重连线程按旧代数淘汰成孤儿，恢复延迟最长可达 60 秒。
- 服务端 per-socket 收包超时在注册后放宽到 `HEARTBEAT_INTERVAL*(MAX_HEARTBEAT_MISSED+1)+2`：此前固定 5 秒的超时架空了 12 秒心跳容忍，从节点卡顿 6 秒即被误踢并触发重新分层。

## 3. 调度与层编排

文件：`src/scheduler.py`、`src/graph_orchestrator.py`

`Scheduler` 负责节点生命周期、主从连接、模型同步、层配置、请求队列、流水线执行、取消、指标和回退。主要入口包括：

- `start(...)` / `stop()`：启动或停止调度器。
- `init_nodes()`：初始化节点状态。
- `compute_layer_assignment(...)`：生成满足能力和层覆盖约束的分配结果。
- `run_pipeline_safe(...)`：带就绪检查和回退边界的 PyTorch 流水线入口。
- `start_infer_task(...)` / `stop_infer_task()`：任务生命周期控制。

`PipelineQueue` 提供 FIFO/MLFQ 请求排队、老化、取消和结果管理。`GraphOrchestrator.orchestrate()` 只为 PyTorch 层流水线生成候选路径与层分配，不负责完整 Worker、任务链或张量并行的内部调度。

补充说明：`compute_layer_assignment()` 会按 `device_info.island.enabled` 排除 TP 孤岛网关节点（孤岛承担整请求推理，不参与层拆分）；节点排序打分对孤岛节点按声明的聚合显存与 GPU 数上浮权重。三处 ACK 已改为经 `_send_lock` 保护的 `send_data` 通道发送，不再直接 `sock.sendall`（与心跳并发写会导致帧交叉损坏）。`Scheduler.__init__` 现显式初始化 `_tcp_client`，错误路径不再抛 `AttributeError`；健康监控首轮不再把启动态判为“恢复”，避免误打“已自动重连”日志并对健康链路做多余重连。

## 4. KV Cache

文件：`src/paged_kv_cache.py`、`src/model_module.py`、`src/scheduler.py`

`PagedKVCache` 提供固定页、追加、读取和清理能力。分布式 PyTorch 前向实际使用的模型 `past_key_values` 按任务和层段由调度器持有，任务完成或中止时清理。两者不能在文档中混写成同一个实现状态。

## 5. API 与客户端

文件：`src/api_server.py`、`frontend/`、`android/`

- FastAPI 暴露聊天、流式聊天、模型、节点、队列、集群状态和 bootstrap 等接口。
- `POST /api/chat`、`POST /api/chat/stream` 新增 `allow_external` / `prefer_external` 两个可选布尔字段，缺省均为 `false`，旧客户端行为不变。
- `POST /api/experimental/speculative` 是投机解码的独立实验端点；`QLH_SPEC_ENABLED` 默认关闭时返回 404。它不写会话历史、不入对话统计，是测量入口不是产品路径。
- `/api/status` 在对应功能启用时增加 `island` / `external` / `speculative` 段，端点与凭据一律脱敏。
- `/api/cluster/connect` 等 9 个同步阻塞的集群管理端点已移入 `run_in_threadpool`；此前它们在 async handler 内直接阻塞，连接不可达主节点时会冻结整个事件循环最长约 50 秒，导致前端整站假死。
- React PC 前端展示聊天、模型、节点、层分配和执行指标。
- Android Full 支持本地 GGUF 与远程 PC 模式；Lite 保持轻量远程入口。
- Android 当前不注册为 PyTorch `pipeline_worker`。完整 Worker 与任务链仍属于规划能力。

## 6. 外部辅助引擎与 Provider（阶段 1 PoC）

文件：`src/island_engine.py`、`src/external_provider.py`、`src/speculative.py`

三条路线的背景与取舍见[张量并行外部辅助与混合拆分调研方案](张量并行外部辅助与混合拆分调研方案.md)。**它们都是 PoC，不得按生产能力引用。**

- `IslandEngine`（路线 A，已实施并双节点验证）：接口与 `LlamaCppEngine` 对齐（`load_model`/`chat`/`chat_stream`），后端是 OpenAI 兼容端点（vLLM/SGLang/llama.cpp rpc 聚合）。“加载模型” = `GET /v1/models` 健康检查 + 解析后端模型名。engine 名 `island`，配置前缀 `QLH_ISLAND_*`（含聚合 GPU 数、显存与 TP 规模，用于设备画像 `island` 段与主节点排序加权）。另提供 `post_json()` 供其他模块复用其凭据脱敏、BasicAuth 与错误分类。接入见 [TP孤岛接入指南](TP孤岛接入指南.md)。
- `external_provider`（路线 B，已实施）：`ExternalOpenAIProvider` 实现 `ExecutionProvider` 契约（声明 `full_inference`/`aggregate`）；纯路由函数 `decide_external_route(...)` 与作用域门控 `ensure_external_scope_allowed(...)` 可独立测试；探活结果带 30 秒单飞缓存。engine 与 `execution_mode` 名均为 `external_api`，配置前缀 `QLH_EXTERNAL_*`。**门控是硬约束**：`QLH_EXTERNAL_DATA_SCOPE` 取 `deny`/`opt_in`（默认）/`allow_all`，取值非法一律 fail-closed 回落 `deny` 并告警；除 `allow_all` 外请求必须显式带 `allow_external`，且需 `prefer_external` 或消息长度超过 `QLH_EXTERNAL_MIN_PROMPT_CHARS` 才真正触发。门控在路由决策与发出请求前各执行一次。接入见 [外部推理服务Provider接入指南](外部推理服务Provider接入指南.md)。
- `speculative`（路线 C-1，**已实施但未接生产路径**）：包含投机采样纯核心、`SpeculativeSession` 状态机与 `ExternalVerifyClient`。**未接入 `model_module` 的生产解码循环**，唯一入口是上文的实验端点；数据作用域复用路线 B 的门控（草稿 token 由用户内容派生，确实出网）。`PagedKVCache.truncate(n)` 基础回滚已完成，真实 draft/verify 与生产接线边界见[投机解码外部辅助实施说明](投机解码外部辅助实施说明.md)。

`island`、`external_api`、`speculative_assisted` 三个取值已加入 `task_provider.py` 的 `ModelIdentity` engine 集合与 `task_worker_protocol.py` 的校验集合。

## 7. TUI 管理入口

文件：`src/tui_admin.py`、`start_tui.sh`、`start_tui.bat`

跨平台终端管理菜单，纯 Python 标准库、零第三方依赖，支持 Windows 10+/Linux/macOS。7 个屏幕：系统状态总览、节点管理（连接主节点、注销、角色转让、备用主节点）、分布式与分层、请求队列 MLFQ、设备画像、日志查看、设置。方向键加回车导航，非 tty 或老终端自动降级为编号菜单（`--plain`）；`--host/--port` 可直接管理远程 Tailscale 主节点。界面为中文并做 CJK 宽度对齐。

它通过现有 HTTP 接口操作集群，不新增控制协议，也不是新的执行 Provider。

跨模块的目标架构和未来 Provider 接口见[混合分布式推理体系规划](混合分布式推理体系规划.md)。
