## 1. 审计背景与分类切换说明

本次审计旨在对测试质量进行全面复盘，**切换分类策略**以避免杀虫剂效应（pesticide effect）：先前按功能模块（如 scheduler、diffusion、qwen3_pipeline 等）分类，导致测试逐渐针对特定实现细节而变得脆弱、冗余且难以覆盖全貌。

**本次新分类策略**（按测试目的/策略分类）：
- **契约/协议测试**：验证 API 契约、协议、schema（如 qwen3_pipeline 相关）
- **单元/逻辑测试**：纯函数、核心逻辑、无副作用
- **集成/组件测试**：模块间交互、API 端点、worker 适配
- **系统/端到端测试**：完整流程、e2e 场景
- **仿真/压力测试**：性能、容量、退化、分布式模拟
- **质量门/回归测试**：sd15 质量门、实验质量、边界回归
- **专项/其他测试**：TUI、launcher、网络、数据保留等

此分类聚焦测试意图，而非实现模块，便于识别跨模块的重复覆盖、空洞和脆性点。

## 2. 审计概览

- 测试文件总数：143 个（含 simulation/ 子目录）
- 整体评级：良好（> 一般仓库水平），多数测试为行为断言 + 真实组件执行，未发现系统性无断言或死代码
- 主要发现：部分模块边界/负向路径覆盖不足；质量门测试可进一步抽象以降低脆性；qwen3 pipeline 测试覆盖良好但需补充 edge case
- 与先前审计对比：已完成 P0/P1/Q1-Q8 整改；本次新增关注可维护性与分类空洞

## 4. 质量发现与建议

### 4.1 覆盖空洞
- 边界/错误路径：部分模块（如某些 inference 分支、edge case）不足
- 负向测试：安全拒绝、异常恢复、超时处理覆盖率 60-70%
- 跨平台：Windows 下某些网络/TCP 测试依赖环境门

### 4.2 脆性与杀虫剂风险
- 部分测试断言硬编码文本/路径，易随实现变动
- 质量门测试参数化不足，可增加更多变体
- qwen3 新增测试（src/qwen3_pipeline_transaction.py 修改后）覆盖良好，但建议增加 dry-run 失败场景

### 4.3 冗余与优化
- 部分 simulation harness 可复用更多
- 建议合并部分 quality gate 为通用 regression 测试
- 单元测试中混入集成 fixture 的需清理

### 4.4 与先前整改对比
- P0/P1 问题已解决（scheduler HA、security boundaries 等）
- 剩余 P2/P3 建议按本次新分类优先级处理

## 5. 结论与下一步

本次审计确认测试质量整体优秀，切换分类策略后可提升测试可维护性与覆盖广度。推荐：
1. 按新分类重构部分测试命名/组织（e.g., test_*_contract.py、test_*_unit.py）
2. 补充 20-30 个针对性 edge case 测试
3. 定期按新分类运行全量 pytest 并生成报告
