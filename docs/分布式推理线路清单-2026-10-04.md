# 分布式推理线路清单（2026-10-04）

本文只列**产品设计线路** —— 产品请求会真实走到的多节点协同路径。

**不列**探针脚本（它们只用于验证技术路线，不是产品路径，见附录 A）；**延后**需加载整模或传输权重的形态（RPC、tensor-split、任务图整请求，见附录 B）。

## 判据

一条线路算「实测通过」，必须同时满足：

1. `distributed_used=true`
2. `fallback=false`
3. `claimed_layers` 非空
4. **逐 token 与整模对拍一致**

两个容易误读的信号：

- 日志 `回退到本地推理` = **分布式失败后的本地兜底**，不是线路生效。`docs/已知问题记录.md` #35 记录了这种掩盖持续了很久。
- tail 段的 `[session] … closed_cleanly=True` 只证明会话正常关闭，**与数值正确无关**。

## A 类：hidden 接力型（层切分，跨节点传 hidden）

QLH 的核心产品形态：把模型层区间切给不同节点，节点间只传残差流 hidden。

### A1 生产 relay 链（master 首段 + 远端段）

> **定位（2026-10-04）**：**A1 不算产品路径**。它依赖「段服务在集群外 + SSH 隧道把远端端口映射到本机 loopback」（`relay_transport.py` 强制 loopback），本质是**服务探针与实验的支撑设施**。产品形态只有 A3 一条；A1 按其自身节奏退场。本节保留是为了记录已有证据与差异，不表示它是交付线路。

- **形状**：master 跑 `[0,k)` 交出 hidden；远端段跑 `[k,N)`。段角色 `middle`（hidden→hidden）或 `tail`（hidden→token，段自己做 argmax 回 token，master 因此不需要 lm_head）。
- **配置**：`QLH_RELAY_ENABLED=1`、`QLH_RELAY_SEGMENTS="<node_id>=<role>@<host>:<port>#<n_embd>#<start>-<end>"`；默认关闭。
- **实现**：`src/scheduler_pipeline.py:_handle_layer_forward_via_relay` / `_parse_relay_segment_map`；会话与传输 `src/inference_service/peer.py`、`src/relay_segment_client.py`、`src/relay_transport.py`；段服务 `scripts/relay_mid_service.py`。
- **实测**：
  - PyTorch master 形态：三机产品级验收通过（`local_docs/evidence/relay-product-acceptance-20260930/SUMMARY.md`，含 40/40 同精度逐 token 一致）。
  - llama.cpp（去 torch）master 形态：2026-10-04 首次跑通（`docs/已知问题记录.md` #35）。
  - 同日的 L→L 探针对拍（本机 head `[0,8)` + Surface tail `[8,24)` 对整模）：**32/32 逐 token 一致**（`local_docs/evidence/l2l-probe-2026-10-04-gen32.json`），上行接口即 `KeepHeadUpstream` ⇒ **数值面已验证**。剩余差距在**调度编排面**（产品路径经 `/api/chat` 的逐 token 对拍仍待做）。
- **已知坑**：
  - `#34`：调度侧 `_close_relay_segment_client` 是死代码，relay 会话真源只有 `peer.py`。
  - master 侧必须配 `tail` 段。master 手上的裁层工件含真实 blk 层，走 `middle` 会让 relay 回的 hidden 再过一遍 ⇒ 数值全错。

### A2 v3 task-worker `layer_forward` Stage

- **形状**：协议层 stage，`stage_type=layer_forward`，`middle_channel ∈ {extract_hidden, keep_head_layer_out}`。PC 与 Android 都可当 layer worker。
- **实现**：`src/task_worker_protocol.py`、`src/scheduler_task_worker.py`、`src/scheduler_pipeline.py:_execute_layer_stage_offer`、`src/inference_service/engine_host.py`；Android 侧 `AndroidFullWorkerStageExecutor.kt` + JNI。
- **开关**：`QLH_TASK_WORKER_EXPERIMENTAL_ENABLED`（默认 false）。
- **实测**：Y700 真机三层链（master torch `[0,16)` + Surface `[16,20)` + Y700 `[20,24)`）跑通 prefill + decode，与 L 档整模逐字一致。判据强度低于 A1（步数少）。

### A3 Route A 产品路径

- **形状**：`execution_mode=route_a_stage_offer_v3`，master 前缀 + Stage 链（offer 协商式）。
- **实现**：`src/scheduler_pipeline.py:_run_route_a_stage_pipeline`；能力推导 `src/scheduler_task_worker.py`。
- **开关**：`QLH_TASK_WORKER_EXPERIMENTAL_ENABLED` + `QLH_PIPELINE_PREFER_ALL_WORKERS`，默认双闸关。
- **实测**：部分通过（单/两/三段各若干步）。
- **准入苛刻**：master 必须先真正加载模型（`prepare-pipeline` 不物化权重 ⇒ 身份为 None ⇒ fail-closed）；Android 广告层区间须覆盖请求区间。**这些 503 是正确的拒绝，不是 bug。**

### A4 PyTorch legacy 层流水线

- **形状**：主节点推送层配置（`LAYER_CONFIG` / `LAYER_FORWARD`），从节点本地跑层。
- **实现**：`src/scheduler_pipeline.py:_handle_layer_forward_locked`、`src/inference_service/peer.py:_handle_layer_forward_locked`、`src/model_module.py:prepare_pipeline_model`。
- **实测**：协议/调度/会话治理有大量真实链路证据；**但「从节点用真实 PyTorch 权重跑层段并与整模逐 token 对拍」找不到独立记录** —— 现有真机层段证据都落在 A1/A2。这是当前最值得补的一条。

## B 类：sidecar 型（节点内进程隔离 + 网络控制面与工件传输）

把层段放进隔离进程（同机），控制面与工件传输走 loopback/网络。

### B1 Qwen3 sidecar / network 段链

- **实现**：`src/qwen3_pipeline_sidecar.py`、`qwen3_pipeline_multisidecar.py`、`qwen3_pipeline_loopback.py`、`qwen3_pipeline_network.py`、`qwen3_pipeline_transfer.py`；调度接线 `src/scheduler_sidecars.py`。
- **实测**：同机多进程真实模型链通过（`tests/test_qwen3_network_sidecar_chain.py`，`real_model` 门，需 ≥3 GB 可用 RAM）。**跨物理机明确「继续后置」，未验收。**

### B2 Gemma 4 pipeline sidecar

- **实现**：`src/gemma4_pipeline_sidecar.py`、`gemma4_pipeline_multisidecar.py`；接线 `src/scheduler_sidecars.py`。
- **阻塞**：`docs/已知问题记录.md` #11 —— 真实工件经 `pipeline_runtime_supported=false` 被拒；真实工件 + CUDA + 双机验收未做。官方 smoke 要求 Transformers 5.10.1（当前 5.17.0 ⇒ skip）。

### B3 Qwen3 multimodal sidecar

- **实现**：`src/qwen3_multimodal_multisidecar.py`、`qwen3_multimodal_runtime.py`、`qwen3_multimodal_contract.py`。
- **实测**：未找到**跨节点**端到端实测。工件在 `models/qwen3-vl-4b-instruct*`。

- **实现**：`src/pipeline_reshard.py`；接线 `src/scheduler.py`（lease book 构造）、合同 `src/pipeline_node_contract.py`。

## 附录 A：探针线路（不算产品线路）

只用于验证技术路线，不参与产品路由。

- **L→L 探针链**：`scripts/relay_l2l_net_probe.py`（纯 llama.cpp，两段/三段/多跳）。
- **跨框架 D→L / D→L→L 实验**：`scripts/relay_experiment.py`（多条 `--path`）。
- 两者的实测证据（32/32、27/27、141/141 等）证明的是**技术路线可行**，不能当作 A 类产品线路的验收。

## 附录 B：低优先级（需整模或传权重，实测延后）

- **llama.cpp RPC device**：`src/llama_rpc_device.py`、`src/llama_rpc_planner.py`、`src/llama_rpc_contract.py`。脚本级双机实测通过，**产品路由无调用点**；上游 #27（任一 socket 失效即 `abort()`）本仓不改。
- **llama.cpp tensor-split / 多设备切分**：`src/llama_rpc_planner.py:plan_to_tensor_split`，唯一非测试消费者是 `scripts/llama_pc_rpc.py`。无独立真机实测。
- **Edge RPC worker**：`src/edge_cluster.py:EdgeRpcWorker`、`src/qlh_edge.py` HTTP 入口。Python 侧可用（WSL 证据）；Android 侧只有 Kotlin 包装，未接入 worker 生命周期与能力上报。
- **任务图 / 整请求 stage**：`src/task_graph.py`、`src/task_worker_adapter.py`。真机通过，但**要求整模在某节点装得下**，按架构裁决只作回退。
- **island / 外部 provider**：`src/island_engine.py`、`src/external_provider.py`。不属层切分，无外部端点时不可测。

## 附录 C：支撑件（不是线路，但 A 类依赖它们）

- **keep-head 上游通道**：`src/llama_keep_head.py:KeepHeadUpstream`，带补丁 shim（`build/keephead/build-cpu/bin/qlh_keep_head.dll`）。供 A1 的 master 交出「末层输出、`output_norm` 之前」的 hidden。见 `docs/已知问题记录.md` #35。
- **裁层工件生成器**：`scripts/cut_layers.py`（`--keep-head N` / `--k K1 --end K2`）、`scripts/relay_artifact_manifest.py`、`src/relay_segment_info.py`（零依赖读 GGUF 层范围）。
- **SSH 隧道编排**：`scripts/relay_ssh_tunnel.py`（跨机时 `relay_transport` 要求 loopback 目标）。
