> **适用范围**：统一测试通道入口——`scripts/run_test_channels.py` 的通道划分、`external`/`real_model`/`requires_db`/`requires_gpu` 标记语义、运行方式与跳过条件；与 `pytest.ini` markers 和 `requirements-test.txt` 对齐。

项目测试拆成三条通道，避免协议测试加载真实权重，也避免数据库、SMTP和 GPU 生命周期互相争用。

## 安装测试依赖

测试依赖单独放在 `requirements-test.txt`，不会加入运行时或打包依赖。应在项目专用虚拟环境中安装：

```powershell
python -m pip install -r requirements-test.txt
```

不要使用系统 Python 安装测试依赖。

## 一键运行

```powershell
python scripts/run_test_channels.py
```

运行顺序为：

1. `unit`：排除 `external`、`requires_db`、`slow`、`requires_gpu` 和 `real_model`，安装 `pytest-xdist` 后默认使用 4 个 worker 和 `loadscope` 并行。
2. `external`：运行数据库、SMTP、慢测试和其他外部资源测试，固定 `-n 0` 串行。
3. `smoke`：默认跳过，不会加载模型权重。

可单独运行：

```powershell
python scripts/run_test_channels.py --channel unit --workers 4
python scripts/run_test_channels.py --channel external
python scripts/run_test_channels.py --channel smoke
```

## 真实模型冒烟

冒烟测试必须显式开启，并且始终串行：

```powershell
$env:QLH_RUN_REAL_MODEL_SMOKE = "1"
$env:QLH_SMOKE_MODEL_ID = "qwen-1_8b"
$env:QLH_SMOKE_ENGINE = "pytorch"
$env:QLH_SMOKE_QUANT = "int4"
python scripts/run_test_channels.py --channel smoke
```

可选设置 `QLH_SMOKE_MODEL_PATH` 指向对应内置模型槽位的本地 Safetensors 目录或 GGUF 文件；未设置时使用项目模型注册表中的路径。冒烟流程只做一次最小生成，然后卸载模型，失败应视为当前解释器、模型文件、CUDA/量化依赖或引擎适配问题，而不是单元测试失败。

目前默认使用 Qwen 1.8B。验证 DeepSeek 时修改 `QLH_SMOKE_MODEL_ID`，例如 `deepseek-r1-distill-qwen-1.5b`，并确认本地模型已完整下载。
