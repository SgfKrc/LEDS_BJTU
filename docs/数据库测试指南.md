# 数据库与存储测试指南

> 状态：现行操作参考
>
> 更新日期：2026-08-10
> 适用范围：M1.3（远端 PostgreSQL 退场）后的存储层测试现状、运行方式与结果解读
>
> 变更记录：2026-08-10 随 M1.3 收口重写。生产运行时不再连接或打包 PostgreSQL，本文档不再提供 PG 安装、Docker 或 CI 服务容器指引；原"离线/在线双轨"描述作废。

## 概述

M1.3（2026-08-10）后远端 PostgreSQL 已退场：**主节点 SQLite 是唯一事实源**，Python 与 control-svc 共用同一 SQLite 库；`src/db.py` 降级为"已退场的兼容实现"，任何生产连接请求都会被拒绝（fail-closed）。`psycopg2` 不再出现在 requirements 与安装包中，`pg` 在 control 侧仅保留为 devDependency（供退场迁移工具测试使用）。

存储层测试相应分为三层：

1. **Python 配置与退场行为测试**（`tests/`）——不依赖任何数据库
2. **control-svc 存储契约测试**（`control/test/`）——SQLite 为真实被测对象
3. **跨平台隔离环境门**（`scripts/model_fleet_storage_environment_gate.py`）

## 1. Python 侧

### 1.1 tests/test_db_config.py（31 项）

- **18 个离线测试始终通过**：配置解析、环境变量读取与凭据安全（源码/日志无硬编码密码）、无效值处理与范围校验、`close_db()` 线程安全。
- **13 个标记 `requires_db` / `external` 的测试**（`TestClusterConfig` / `TestUserSettings` / `TestDedicatedKeys`）针对已退场的 db.py 兼容实现编写。因 PG 已退场，`_db_connected()` 恒为 `False`，这 13 项在本地与 CI 均**按预期跳过**，属于全量基线（`1714 passed / 27 skipped`）的组成部分。

运行（无需任何数据库）：

```bash
python -m pytest tests/test_db_config.py -q
# 预期：18 passed, 13 skipped
```

### 1.2 tests/test_database_fallback.py（2 项）

验证退场契约：请求代码绝不从 PostgreSQL 路径重连，远端不可用时 fail-closed 返回本地 SQLite 状态。无需数据库，始终通过。

### 1.3 组合运行

```bash
python -m pytest tests/test_db_config.py tests/test_database_fallback.py -q
# 预期：20 passed, 13 skipped
```

## 2. control-svc 存储契约测试

M1.2/M1.3 新增的存储与退场用例（`control/test/`），SQLite 为真实被测对象，**不需要 PostgreSQL**：

| 文件 | 覆盖内容 |
|------|----------|
| `sqlite-store.e2e-spec.ts` | 核心 store 读写、schema 迁移与 fail-closed |
| `sqlite-core-stores.e2e-spec.ts` | 会话/消息/workflow journal/review 等核心域 store |
| `storage-health.e2e-spec.ts` | 健康状态与损坏库 fail-closed |
| `storage-migration-package.e2e-spec.ts` | `.qlhmigrate` 打包/恢复/篡改回滚 |
| `postgres-retirement.e2e-spec.ts` | 退场 `prepare/retire/verify` 与 manifest 哈希校验 |
| `auth-assets.e2e-spec.ts` 等认证用例 | SQLite v5/v7 认证资产（用户/TOTP 引用/恢复码/绑定） |

运行：

```bash
cd control && npm test   # jest --runInBand，无需任何环境变量
```

## 3. 跨平台隔离环境门

```bash
python scripts/model_fleet_storage_environment_gate.py
```

在 Windows 11（干净目录、损坏活动库、NTFS 写入 deny ACL）与 WSL2 Ubuntu 22.04（干净目录、损坏库、`0555/0444` 权限）下验证 Python/Node 共库的隔离行为，损坏/只读一律 fail-closed。需要对应平台环境，Windows 侧本机可直接运行。

## 环境变量说明

`QLH_DB_*`（HOST/PORT/NAME/USER/PASSWORD/MIN_CONN/MAX_CONN）**已不再被生产代码读取**：db.py 退场后仅解析不连接，control 生产启动图不再包含 pg/outbox/projector。`.env` 中保留的 `QLH_DB_*` 仅作历史备用，**测试无需设置任何数据库环境变量**。

## 常见问题

### Q1: test_db_config.py 有 13 项 skipped，正常吗？

正常，这是预期行为（见 §1.1）。13 项针对已退场的 PG 兼容实现，`_db_connected()` 恒为 `False` 导致跳过，不应尝试安装 PostgreSQL 使其通过。

### Q2: 需要安装 PostgreSQL / Docker 才能跑测试吗？

不需要。`scripts/setup_test_db.py`（创建测试库/用户）与文档中的 Docker/CI 服务容器方案均已无用途，脚本仅保留作历史参考，不参与任何测试路径。

### Q3: 怎么确认"PG 退场"没有回归？

三层证据：
1. `tests/test_database_fallback.py` 2 项通过（请求代码不重连 PG）；
2. `control/test/postgres-retirement.e2e-spec.ts` 通过（退场工具链完好）；
3. 全量基线无未解释失败（`1714 passed / 27 skipped`），且 `requirements.txt` / `packaging/requirements-cpu.txt` 不含 `psycopg2`。

## 总结

- **不再需要任何数据库环境**即可跑通全部存储层测试：Python 侧 `20 passed / 13 skipped`，control-svc 全量契约通过。
- 13 项 skipped 是 PG 退场后的预期残留，不属于失败。
- 远端 PostgreSQL 仅保留一次性迁移审计通道（`storage:retire-postgres`），由 `postgres-retirement.e2e-spec.ts` 维护其行为契约。
