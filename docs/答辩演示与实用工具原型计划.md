> 适用范围：大创收尾阶段（答辩目标 2026-04）的实用小工具/演示原型；与总体计划的真机验收（A4/SD-N4、B3）并行，不引入架构级新工作。所有原型须可落盘、可验证，声称一律附 git 证据。

## 1. 背景与策略

项目（QLH 分布式推理集群）体量已远超一般大创，核心风险**不是功能数量**，而是：

1. **真机闭环**（双机分布式验收 A4/SD-N4）——答辩核心卖点，第一优先，独立于本计划推进；
2. **演示稳定性**——现场演示不翻车；
3. **性能数据**——单机 vs 双机对比，用数字说话；
4. **结题材料**——文档收口 + 答辩 PPT + 正式 release。

本计划只承接"演示 + 数据 + 易用性"侧的实用原型，**明确不做**：QW3.5 运行时接入（QW35-R1）、Gemma 4 真实三轮标定、音频/8K 上下文等架构级新工作（登记为"未来工作"，答辩中体现规划能力）。

## 2. 原型清单

| # | 原型 | 目标 | 验收标准 | 优先级 |
|---|------|------|---------|--------|
| P1 | **一键演示模式** | `demo.sh`/`demo.bat` 启动全栈（后端+前端+worker）并跑通预置脚本（对话/图像各一），演示不翻车 | 干净环境一键启动 ≤2 分钟；预置脚本输出固定成功标记；失败有中文提示 | **P0** |

| P3 | **分布式 benchmark 工具** | 单机 vs 双机延迟/吞吐/显存对比，输出图表 | 同负载下输出 JSON+PNG 图表；数据可复现（seed 固定） | **P0** |

## 3. 顺序与依赖

- **第一批（P0，2026-01~02）**：P1 → P2 → P3。三者构成答辩故事线："分布式推理集群、断网自愈、性能数据说话"。
- **第二批（P1，2026-02~03）**：P4 → P5。
- **第三批（P2，有余力）**：P6/P7/P8 任意。
- 依赖：P3 建议等双机验收（A4）数据源就绪后做实测；P1/P2 不依赖外部设备，本机即可原型。

## 4. 协作约定（GROK 组原型）

1. 每个原型独立提交，声称完成必须附 `git status`/`git diff`/commit hash 证据；
2. 原型放 `scripts/` 或 `build/`（临时验证物）不入主流程，验收通过后由主开发组收编；
3. 涉及网络/密钥/路径的脚本须遵循项目脱敏纪律（不落凭据、不落绝对路径到报告）；
4. 原型验收由本机实测（跑通验收标准）而非文本声称。
