# QLH 定位与模块归属终局决策（2026-09-14）

> 状态：**生效**（用户指示"必须现在敲定"）。本文档为模块归属的唯一裁决依据，冲突表述以本文为准。
> 创建日期：2026-09-14
> 依据：五轮清理与审计（分界清单/边缘化清单/功能存废/边缘基线/科研与优化审计）+ 本轮用户指示（"拆除一个管理模块和一个引擎模块；引擎最核心最轻量、提供简单 TUI 对话"）。

## 1. 主项目定位（最终裁定）

**主项目 QLH = 轻量推理引擎与优化系统。**

- **一句话**：在边缘设备（无/弱 GPU）上跑轻量模型的**推理引擎**——核心资产是优化（量化 / 分页 KV / 单元对齐 / 投机解码 / 层分页外置）与可证质量（实验体系）。
- **交付形态**：`qlh chat`（简单 TUI 对话，纯标准库 + llama.cpp）+ `qlh_edge`（最小 HTTP，120MB venv 实测）。
- **纪律**：主仓**不再承载**管理面（拆出）、产品壳（前端/Android，支线）、知识库（已裁）。新增功能准入问句："它服务边缘推理引擎吗？"

## 2. 三分定案（拆除两个模块）

| 归属 | 名称 | 角色 | 当前代码映射（文件级） | 形态 |
| --- | --- | --- | --- | --- |
| **主项目（本体）** | **QLH Engine** | 轻量推理引擎：跑模型 + 优化 + 对话 | `llama_engine.py` · `qlh_edge.py` · `paged_kv_cache.py` · `cache_unit_layout.py` · `speculative.py` · `inference_service/`（新一代流水线宿主）· `tui_chat.py`/`tui_sse.py`/`tui_shared.py`（简单 TUI 对话）· 量化工具（`scripts/quantize_model.py`/`build_llama_quantize.py`/`scripts/model_tools.py`）· 模型资产面（`model_config.py`/`model_downloader.py`/`model_download_jobs.py`）· 引擎侧契约（`schemas/` 推理部分） | 主仓本体；依赖白名单 ≤300MB（实测 120MB） |
| **拆出①** | **QLH-Control（管理模块）** | 集群/节点/调度/控制面：多节点编排，调用引擎执行 | `scheduler.py`（14k 调度核心）· `tcp_comm.py`（节点通信）· `device_profiler.py`（画像）· `scheduler_svc_http.py` · `api_server.py` 的**管理面端点**（cluster 63 / logs 11 / user / bootstrap / workflows / db / storage / system——约 150 端点中的管理侧）· `review.py`/`email_notifier.py`（审批通知）· `task_worker_protocol.py`/`task_worker_adapter.py`（任务链协议，双方共用——协议归管理、执行归引擎） | 先内部独立包（`packages/qlh-control/`）→ 独立仓 → submodule |
| **拆出②** | **QLH 产品壳（发布支线）** | 前端/端侧/打包：把引擎+管理组装成产品 | `frontend_cybergothic/`（独立仓）· `android/`（独立仓）· `packaging/`（UNI-A3）· 演示/答辩工具（UNI-A2） | 支线独立仓（不占主仓） |

> 注："拆除一个管理模块和一个引擎模块"= 引擎从当前混杂体中**切出为清晰模块并成为主项目本体**（最核心资产留在主仓）；管理拆为独立项目；产品壳与一切非引擎内容支线化。

## 4. 边界与接口（模块怎么合作）

```
[QLH-Control 管理模块]                [QLH Engine 主项目]
  调度/集群/节点/控制面  ──任务(REST/任务链协议)──▶  跑模型（llama.cpp+优化）
  设备画像/审计/审批                                 对话面（TUI + chat 端点）
        │                                                  │
        └────── 契约：schemas/（推理请求/结果/任务协议）──────┘
[产品壳支线] 前端/Android ──▶ 面向用户（经管理面或引擎面）
```

- **引擎对外**：`qlh chat`（本地 TUI）、`qlh_edge`（最小 HTTP：health/status/generate）、models 资产面；
- **管理对外**：cluster/scheduler/节点/审批面（原 api_server 管理侧端点迁入）；
- **双方耦合点**：仅契约（`schemas/`）与任务协议；引擎**不 import 管理**，管理可依赖引擎作执行器。

## 5. 实施路径（四阶段）

| 阶段 | 动作 | 验收 |
| --- | --- | --- |
| **P1 引擎出口**（立即可做） | `qlh chat` TUI 对话（复用 `tui_chat`（715 行、零第三方）+ llama.cpp 后端；或极简新写）；`qlh_edge` 已备 | 一条命令本地对话（含多轮/流式）；venv ≤300MB |
| **P2 管理包化** | 管理文件集建 `packages/qlh-control/`（内部独立包，参照 spawnledger 路径） | 包内测试通过；引擎无反向依赖 |
| **P3 管理独立** | qlh-control 独立仓 + submodule；`api_server` 按域瘦身（管理端点迁出） | 引擎仓不再含管理端点 |
| **P4 产品壳外置** | cybergothic/Android/packaging 按既有清单外置 | 主仓 = 引擎 + 契约 + 实验体系 |

## 6. 不变式（本次决策不改变的事）

1. Koakumix/docagent/bridge/spawnledger 的既有独立状态与纪律不变；
2. 实验体系（fixtures/experiments/MANIFEST/EX-N3 门）**留在引擎仓**（它是引擎的质量基建）；
3. 边缘基线（≤300MB venv / ≤15s 冷启动 / 无 torch）为引擎交付标准；
4. 文档双轨归档（docs/archive、_archive）与"先归档后删"纪律不变。
