# 接力边界数值对齐（Boundary Alignment）：可行性调研与实验设计（2026-09-16）

> 性质：**想法调研 + 实验设计**（未实施）。源于一个提问：
> **"既然两侧量化不同会引入误差，能不能在传递张量前对数值做处理，以匹配量化？"**
>
> 关联：[跨框架接力量化与加速解耦分析](跨框架接力量化与加速解耦分析-2026-09-16.md) · [推理性能现状调研](推理性能现状调研-2026-09-16.md) · [跨框架层接力重启评估](跨框架层接力重启评估-2026-09-15.md)

---

## 0. 问题重述与直觉

跨框架逐层接力下，上游（PyTorch，可能 NF4）与下游（llama.cpp，可能 Q4_K_M）各有自己的量化误差。接力点传的是 hidden state，两侧误差**独立累积到同一个张量**上。

**提问的直觉**：既然误差是可观测的（已知两侧在同一输入下输出的差异），能不能在**交接前对张量做一次变换**，让下游"更适应"它接收到的数值，从而**缩小最终 argmax 分歧**？

**简短回答**：**方向成立，但要注意三件事**：
1. 这不是"消除误差"，而是**在下游输入端做误差重分配**——收益上限受下游自身量化误差限制；
2. **最简单的形态是线性变换/缩放**（低成本、可解析验证），复杂形态（缝合一整个 MLP）收益高但会**改变逻辑模型身份**，与合同冲突；
3. **必须用 argmax 判据验证**，且**必须在多个 prompt 上验证**，否则容易过拟合单个样本。

---

## 1. 候选手段（按侵入性从低到高）

### L0 — 不做处理（基线）

当前状态。对照组。

---

### L1 — 数值域归一到下游期望（**最保守，可能零收益**）

**做法**：把 hidden 按下游侧统计（均值/方差）做仿射归一，再反归一。

**机理假设**：两侧数值分布若因量化而整体偏移（scale shift），可被消除。

**问题**：
- 两侧本就是**同一个逻辑模型**（合同要求 `model_sha256` 一致，`relay_contract.py:192`），理论分布应当相同；
- 若分布确实不同，那是**量化导致的**，而下游接收后**仍要过它自己的量化权重** → 归一化改变不了下游权重的量化误差。

**预期**：**几乎零收益**，但**成本极低、可作为阴性对照**（证明"误差不是简单的 scale shift"）。

---

### L2 — 逐通道缩放（per-channel rescale）★ 推荐先做

**做法**：在交接前对 hidden 的每个通道 `j` 乘一个标量 `s_j`，下游输入处再乘 `1/s_j`（或把 `s_j` 吸收进下游的第一层权重）。

**为什么可能有收益**：
- 下游若是**块量化**（Q4_K_M 是 per-block scale+min），某个通道若**动态范围过大**，会拉低该块其余通道的有效精度；
- 通过 `s_j` **压缩离群通道**，等价于一种 **activation-aware scaling**（AWQ 的核心思想之一）；
- **关键**：`s_j` 只需**离线标定**（用小样本统计下游第一层的输入敏感性），推理时是纯乘法 —— 零额外算子。

**⚠️ 与合同的冲突点**：若把 `s_j` 吸收进下游权重，则下游权重被改 → **产物摘要变化**。但合同**允许裁层产物摘要不同**（`:211-216`），所以**制度上可行**；不过要新增元数据说明"该产物含边界对齐缩放"。

**实验**：给定一小组 prompt（如 8 条），最小化下游输出的 argmax 分歧：

```
s* = argmin_s  Σ_prompt  D_argmax( downstream( hidden_upstream ⊙ s ), baseline )
```

**零成本变体**：只做**全局标量** `s`（1 个自由度），先验证"缩放是否有任何作用"。

---

### L3 — 学习式线性缝合（stitching layer）

**做法**：在边界插一个小线性层 `W`（`n_embd × n_embd`，2048×2048 ≈ 4.2M 参数，f16 约 8 MB），用少量样本训练使下游输出匹配"理想接力"。

**参考**：学术界 **model stitching** 表明不同网络的中间表示可通过线性层对齐；**但**这里两侧本是同一模型的层划分，**理论最优 `W = I`**。

**判断**：
- 若 `W*` 明显偏离单位阵 → 说明两侧存在**系统性的表示漂移**（有价值的科学发现）；
- 若 `W* ≈ I` → 说明误差是**零均值噪声**，线性层无用 → 应转向 L4。

**⚠️ 合同冲突**：引入可学习参数**改变了逻辑模型语义**。需要新合同字段（如 `alignment: {type: linear, sha256: ...}`），并明确"该接力的逻辑模型身份依赖对齐参数"。

---

### L4 — 误差反馈 / 迭代修正（error feedback）

**做法**：把上游量化误差 `e = hidden_f32 - quantize_dequantize(hidden)` 的**残差**传到下游，在下游输入处加回。

**问题**：
- 上游误差发生在**上游的权重**上，不在 hidden 上 —— 所以"残差"没法简单算出来（除非上游同时提供低精度与高精度的 hidden，即**双份传输**，代价翻倍）；
- 若上游是 f32/f16（当前 D→L 实测就是 f32 hidden），这个残差近似为 0 → **无收益**。

**适用场景**：只有当**上游 hidden 本身被量化传输**时才有意义（合同目前只支持 f32/f16，`:43`）。

---

### L5 — 接力点降精度以"对齐两端"（反向思路）

**做法**：不补偿误差，而是**故意降低精度使两侧一致** —— 例如把 f32 hidden **量化到与下游权重同级的精度**再传。

**机理**：让下游"看到的输入"更接近它在训练/量化时见过的分布（**量化感知**）。

**⚠️ 风险**：这是**主动引入误差**，可能更糟。但成本极低（一次量化），**值得作为对照实验**。

---

## 2. 收益上限的理性判断（重要）

**必须先说清楚**：这些手段**不能**提升下游模型本身的**能力**，只能减少**接力引入的额外分歧**。

设：
- `D_down`: 下游自身量化误差导致的分歧（与 hidden 精度无关的**固有**部分）
- `D_align`: 两侧表示不匹配导致的分歧（**本文想减少的**部分）

则：**`收益上限 = D_align`**。若 `D_down` 占主导（低比特时很可能如此），**任何边界处理都救不了**。

**→ 因此，本文所有实验的前置问题是**：**当前 D→L 的分歧，主要来自 `D_down` 还是 `D_align`？**
这正是 E2（下游 Q4_K_M）实验要回答的 —— 见 §4。

---

## 3. 与既有约束的一致性

| 约束 | 影响 |
| --- | --- |
| `model_sha256` 必须一致（`:192`） | **L3 类"可学习参数"会改变逻辑身份** → 需扩展合同 |
| 产物摘要**允许不同**（`:211-216`） | **L2 吸收进下游权重是制度上允许的** |
| 判据 **per-token argmax**（`:30-31`） | 所有对齐方案都用它评估 |
| hidden 仅 f32/f16（`:43`） | L4 在 f32 hidden 下无意义 |
| Relay 生产准入 fail-closed | 边界对齐一旦启用，**必须新增准入项** |
| `embd` 路径位级非确定（#28963） | 对齐目标只能是 argmax，**不能追求 bitwise** |

### E2b —— Q4_K_M 下游的 hidden 敏感性（诊断）

**做法**：给下游喂**不同精度**的同一 hidden（f32 / f16 / 故意加噪），观察 argmax 分歧曲线。

**目的**：区分"**输入精度敏感**"与"**下游权重误差主导**"。

### E4b —— 边界对齐的最小可行实验（**本文核心**）

**做法**（按顺序，每步都便宜）：

1. **只做全局标量 `s`**（1 自由度）：扫 `s ∈ [0.9, 1.1]`，看 argmax 分歧是否变化；
2. **逐通道缩放**：用 8 条 prompt 标定 `s_j`，在另 8 条上验证（**必须留出验证集**）；
3. **线性缝合 `W`**：先看 `W*` 与单位阵的距离（**科学价值 > 工程价值**）。

**判据**：
- 分歧显著下降 → 说明存在**可补偿的系统性漂移**，值得继续；
- 无变化 → **阴性结论同样有价值**：证明误差是零均值、不可在边界修复的 → 应转向"两侧用同精度"或"下游换更高精度"。

## 5. 风险与反模式

| 反模式 | 为什么 |
| --- | --- |
| **在单个 prompt 上调参** | 141 个 token 高度自相关，极易过拟合；**必须多 prompt + 留出验证集** |
| **用 cosine 作为优化目标** | 与准入判据（argmax）不一致；cosine 很高但 argmax 分歧是**已知现象**（D→L 实测 cosine_min 0.9999995 而仍要求 argmax 全对） |
| **把边界对齐当成"提升模型能力"** | 它只能减少**接力引入**的额外分歧（§2 的 `D_align`） |
| **引入可学习参数却不更新合同** | 会让"逻辑模型身份"变得不可复现 |
| **把对齐参数当普适常量** | 它依赖**具体的上下两侧量化组合**，换组合即失效 → 必须与精度组合绑定记录 |

## 6. 前置建议（先做哪个）

1. **先有 E2 的数字**（下游 Q4_K_M 的额外分歧量级）——
   如果 Q4_K_M 下仍能 141/141，那么**边界对齐的紧迫性大幅下降**，本文可降级为"备选方案"；
2. **然后做 E2b**（诊断分歧来源）；
3. **只有当 E2b 表明"输入精度敏感"时**，才投入 E4b 的对齐实验；
4. **全局标量 `s` 是最便宜的第一步** —— 若连它都无效，逐通道与线性缝合大概率也无效。
