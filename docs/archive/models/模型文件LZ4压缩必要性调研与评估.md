# 模型文件 LZ4 压缩必要性调研与评估

> 状态：**调研完成，结论：本地模型 LZ4 转换**不值得做**（收益 <6%，且有加载峰值反噬）；可选低成本替代方案见 §5，若需传输压缩另见 §6 计划骨架**
>
> 创建日期：2026-08-23
> 适用范围：模型文件本地存储占用的压缩归档决策；不覆盖模型量化精度、低比特推理或文件系统级压缩

---

## 1. 问题与目标

模型文件（GGUF / Safetensors）体积大（Qwen-1.8B GGUF 约 1.2GB，DeepSeek-R1-7B GGUF 约 4.5GB，QW3-VL-4B Safetensors 约 10GB），占用磁盘显著。候选方案：**模型离线转为 LZ4 压缩文件；加载时解压、卸载时重新压缩**，以换取空闲态磁盘占用下降。

本调研回答三个问题：
1. 模型权重可压缩性如何（LZ4 实际能省多少）？
2. "加载解压/卸载压缩"的磁盘与延迟代价是否可接受？
3. 若不值得，有哪些低成本替代方案？

## 2. 实测（真实模型权重，2026-08-23）

对仓库 `models/` 下真实 GGUF 权重做压缩率 + 吞吐实测（`.venv-test` + `lz4`/`zstandard`，结果保留于本次会话探针）：

| 样本 | LZ4 默认 | LZ4 level9 | zstd-1 | zstd-3 | zstd-9 |
|---|---|---|---|---|---|
| Qwen-1.8B Q4_K_M 头部 128MB | 97.5% (1.64GB/s) | 96.9% (60MB/s) | 95.1% | 95.1% (550MB/s) | 94.8% |
| Qwen-1.8B Q4_K_M 尾部 128MB | 99.96% (1.79GB/s) | 99.95% | 97.6% | 97.7% | 97.6% |
| DeepSeek-7B Q4_K_M 抽样① 64MB | 94.3% | 93.3% | 92.9% | 91.7% | 91.4% |
| DeepSeek-7B Q4_K_M 抽样②③④ | **~100%**（省 0-0.4%） | ~100% | 97.6-97.9% | 97.7-98.0% | 97.6-97.9% |

**解读**：
- 量化后的模型权重（Q4_K_M）近似高熵：**LZ4 平均收益约 0~6%（多数段 <3%，尾部段接近 0）**；zstd 同级别约 2~8%。
- 反证：文件头/元数据段（GGUF header、tokenizer、量化表）有压缩价值，但仅占总量的很小比例；主体张量不可压。
- 以 LZ4 乐观 4% 计：1.2GB 省约 48MB、4.5GB 省约 180MB——**收益远低于同类优化（低量化 Q4→Q3 可省约 25%）**。

### 2.1 熵编码专项实测（2026-08-23，回答"熵编码能否更优"）

对同一批真实权重的**字节级香农熵**测量（熵编码的理论压缩极限 = H/8，含 probe 清理）：

| 样本 | 香农熵 H (bit/byte) | 熵编码理论极限 | zstd-3 实际 | zstd-9 实际 |
|---|---|---|---|---|
| Qwen-1.8B 头部 128MB | 7.9306 | 99.13%（省 0.87%） | 95.08%（542MB/s） | 94.83% |
| Qwen-1.8B 尾部 128MB | 7.9540 | 99.42%（省 0.58%） | 97.72% | 97.55% |
| DeepSeek-7B 头部 128MB | 7.8966 | 98.71%（省 1.29%） | 96.83%（517MB/s） | 96.71% |
| DeepSeek-7B 尾部 128MB | 7.8945 | 98.68%（省 1.32%） | 98.76% | 98.65% |

**结论**：
- 权重字节分布逼近满熵（8 bit/byte），**纯熵编码（算术/ANS/range coder）上限仅省 0.6~1.3%**——比通用压缩更差。
- zstd 之所以实际省 1.3~5.2% 超过熵极限，靠的是**块重复匹配**（重复零块/量化模式），并非熵编码本身。
- 速度：熵编码 C 实现约 100~500MB/s（python 慢 1~2 个数量级），zstd-3 压缩 ~550MB/s、解压 >1GB/s 已覆盖并超过；**没有必要单独引入熵编码器**——zstd 内已含 FSE（有限状态熵）编码。

## 3. "加载解压 / 卸载压缩" 的代价

| 代价 | 量化 | 说明 |
|---|---|---|
| **磁盘峰值反噬** | 压缩态 + 解压临时文件并存 | 加载时先解出完整权重到临时文件（llama.cpp 默认 **mmap** 加载，压缩文件无法直接 mmap；torch 加载同样需要完整文件）。加载期间磁盘峰值 ≈ 2× 模型大小，与"省空间"目标相反 |
| 加载延迟 | 解压 4.5GB：LZ4 约 2.5s（1.7GB/s），zstd-9 约 6s | 每次加载模型都要付出；模型切换/重启被放大 |
| 卸载压缩延迟 | 压缩 4.5GB：LZ4 约 2.6s；zstd-9 约 8s | 卸载路径变慢；若卸载失败/中断，临时文件或压缩文件残留需清理事务 |
| 完整性与校验 | 需要"压缩文件↔明文文件"双向事务（原子替换、SHA 复核、失败回滚） | 与现有 `verify_files`/`build_manifest`/资源门体系叠加，复杂度显著上升；压缩包损坏只会在加载时暴露 |
| 与现有能力冲突 | `model_registry`/manifest/`import_model` 全部按明文路径登记 | 需要新增归档层概念，改动面覆盖下载、注册、加载、卸载、冒烟管线 |

**结论**：以节省 **<6%** 的磁盘为代价换取加载/卸载变慢、磁盘峰值翻倍与全链路事务复杂度，**净收益为负**。

## 4. 什么场景压缩才有价值（数据特征决定）

只有当数据**不是高熵**时压缩才有意义：
- 模型权重（量化张量）：❌ 高熵，不可压（本次实测）。
- Tokenizer/vocab 文本、配置 JSON、日志、文档/README：✅ 可压。
- 未量化 FP16/BF16 权重：比 Q4 略可压（约 5-10%），但仍是高熵主体。
- **结论性判断：对任何模型权重主体做通用压缩（LZ4/zstd）都拿不到可观收益；收益上限被数据熵锁死。**

## 5. 低成本替代方案（按推荐排序）

1. **按需下载 + 删除（推荐，项目已有基础）**：`P0a` 模型一键下载 job 已交付（`POST /api/models/downloads` + presets + resource gate）。空闲模型直接删除、需要时一键重新下载——磁盘收益 = **100% 模型大小**，远超压缩的 <6%。该路线唯一成本是网络与下载时间，与"省磁盘"目标同向。
2. **低量化档位**：QW3/GGUF 系列 Q4→Q3/Q2 可省约 20-30%（受质量门约束，按 `llm_smoke_matrix`/质量门验收）。压缩 <6% 与量化 25% 相比微不足道。
3. **磁盘预算与提示（已有）**：`model_sync._ensure_assignment_disk_budget`、`model_download_jobs` 的 `min_disk_gb` 资源门已存在；可补充"安装前磁盘占用预估 + 建议清理"提示，属低成本 UX 改进。
4. **文件系统级压缩（零代码）**：Windows NTFS 压缩 / ReFS、Linux btrfs/zstd 压缩卷对高熵权重同样收益有限（<6%），但对元数据/文本段有效且零侵入；作为部署侧可选项登记即可。

## 6. 如果要做"传输压缩"（可选计划骨架，与本地转换不同目标）

若目标不是本地省盘而是**网络分发省带宽**（离线资产包 `build_offline_bundle`、从节点同步、下载源），zstd 压缩传输才有意义：
- 带宽收益：约 5-8%（实测数据）；配合已"上传即缓存"的场景收益集中在重复分发的网络侧。
- 建议实现形态：**只压不落库**——`build_offline_bundle` 出包时用 `zstd -3`（550MB/s 压缩、解压 ~1GB/s）打包模型目录；安装/导入端解压写临时目录后走既有 manifest/SHA/资源门管线；**不改变运行时模型存储格式**，避免 §3 的全部反噬。
- 范围：`build_offline_bundle.py` + `import_model`/`model_download_jobs` 增加 `.zst` 源识别 + 解压临时目录 + 校验后 publish。
- 验收：真实离线包 zstd 出包/安装回环、带宽统计、SHA 一致、失败清理无残留；不做运行时 mmap 压缩加载。
- 决策点：**是否立项取决于"离线包实际分发体积"是否是当前瓶颈**；若分发主要通过公网一键下载（P0a），则优先继续投 P0a 的下载体验而非压缩。

## 7. 结论

| 决策 | 结论 |
|---|---|
| 本地模型 LZ4 转换（加载解压/卸载压缩） | **不做**。实测收益 <6%（多数段≈0），代价含磁盘峰值 2×、加载/卸载延迟、全链路归档事务；与本项目"省磁盘"目标相悖 |
| 熵编码（算术/ANS，仅熵编码器） | **不引入**。字节级香农熵 H≈7.89-7.95 bit/byte，理论极限仅省 0.6~1.3%，比通用压缩更差；zstd 内含 FSE 熵编码且靠块匹配额外省 2-4%，速度（压缩 ~550MB/s / 解压 >1GB/s）也超过纯熵编码器 |
| 传输压缩（zstd 打包离线包） | **可选**，收益真实但有限（5-8%）；仅在"离线包分发体积成为瓶颈"时按 §6 骨架立项 |
| 立即推荐动作 | ① 用 P0a 一键下载 + 删除实现"冷模型回收"（收益 100%）；② 磁盘门加"占用预估 + 清理建议"提示；③ 量化档位按质量门下探 |

## 8. 边界

- 本调研只覆盖通用压缩算法对量化权重的可压缩性；不否定未来结构性稀疏/剪枝/蒸馏（改变数据分布）的压缩收益。
- 实测样本为仓库真实 Q4_K_M GGUF；Safetensors FP16 权重预计略高于 Q4 但仍是高熵主体，不改变结论方向。
- 文件系统级压缩与低量化属于部署/质量门管辖，不在本调研建议的开发范围。
