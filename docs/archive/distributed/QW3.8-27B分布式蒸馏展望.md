# QW3.8-27B 分布式蒸馏展望（大饼）

> 状态：展望（纯大饼，**不计入大创结题验收**；有余力/硬件条件则完成，否则作为答辩展望材料）
>
> 更新日期：2026-08-17
> 适用范围：在 [QW3.8-27B 分布式运行专项计划](QW3.8-27B分布式运行专项计划.md) **跑通之后**的自然延伸——让 27B 充当**老师**，小模型充当**学生**，进行**分布式蒸馏**，最终用 EX-N3 判题体系对比蒸馏前后效果
>
> 定位一句话：**分布式跑起来的 27B 是稀有的"本地老师"**——用它给项目现有小模型（**主选 Qwen3.5-9B 与 Qwen3-4B**）蒸馏，把老师能力沉淀进学生；1.8B/2B 仅作玩票对照组；做成了是亮点，做不成也是答辩的"展望与下一步"章节素材

## 1. 为什么是"大饼"

| 现实约束 | 说明 |
|---|---|
| 前置依赖 | 27B 分布式跑通（S1-S4 全部完成）才谈得上当老师——当前 S1 都未开始 |
| 硬件条件 | 蒸馏训练需要多机长期占用（数据生成 + 训练 + 评估），与日常开发抢资源 |
| 收益不确定 | 小模型学 27B 有容量上限（4B 明显、9B 更接近），蒸馏收益需实测才知 |
| 验收定位 | **不计入大创结题验收**——结题材料以现有功能/质量门为准；本项是"有余力则做"的加分项 |

**但**：EX-N3 判题体系已就绪（LLM/Gemma/SD 自动判题 + 质量总 gate）——蒸馏效果可以**全自动评估**，不需要人工打分，这是本项目做蒸馏的独特优势。

## 2. 蒸馏方案选型（适合分布式场景）

| 方法 | 传输需求 | 分布式适配 | 结论 |
|---|---|---|---|
| **黑盒蒸馏（序列级，只用输出文本）** | 老师只输出文本（无 logits/hidden） | ✅ **最优**：27B 分布式作为"黑盒老师 API"，慢网不影响——离线批量生成 `(输入, 老师输出)` 对，学生本地训练 | **主选** |
| 白盒 logits 蒸馏（KL 散度） | 每 token 全词表 logits（27B 词表 24.8 万 × 每 token） | ❌ 分布式下传输量大（logits 是激活的百倍） | 仅单机/高速互联时考虑 |
| 特征级蒸馏（hidden states） | 每层 hidden（5120 维） | ❌ 同 logits，跨节点传输不划算 | 不适用 |
| RLAIF/自举（老师给偏好标注） | 老师判优（文本） | ✅ 可行（复用 EX-N3 判题器做偏好信号） | 可选进阶 |

**结论：黑盒蒸馏是分布式天然适配**——老师的分布式慢吞吐（1-3 tok/s）正好是"离线批量生成数据"场景，与学生训练完全解耦。

## 3. 技术路线（分阶段，每阶段可停）

```
S0 数据生成：27B 分布式离线批量生成训练对（输入 → 老师输出）
    输入来源：ps-v1 题集 + 对话模板 + 既有语料；目标 1-5 万对（分布式
    吞吐 1-3 tok/s × 长文本 → 数天到数周，量力而行）
S1 学生训练：黑盒蒸馏（**Qwen3.5-9B 与 Qwen3-4B 双主选**，LoRA 或全参；1.8B/2B 玩票对照组，用于讲"容量上限"故事）
    训练数据 = (输入, 老师输出) 的监督微调；可加判题器偏好（进阶）
S2 效果评估：三角对比（EX-N3 全自动判题）
    ① 学生基线（未蒸馏） ② 蒸馏后学生 ③ 老师（27B 分布式）
    指标：ps-v1 客观正确率 / 格式率 / 生成质量人工抽查
S3 收尾：结论（蒸馏收益 / 成本 / 是否值得）；产物归档
```

### 关键决策点
- **学生选型（2026-08-17 修订）**：**主选 Qwen3.5-9B 与 Qwen3-4B 双模型**——9B 容量最接近 27B（蒸馏吸收上限最高，是效果主战场）；4B 是低成本主力（判题正确率 1/4 基线已有，提升空间可测，训练/评估都快）。**1.8B/2B 仅作玩票对照组**（容量太小，学不会是预期内，用于对照展示"容量决定吸收上限"）
- **训练成本差异**：9B LoRA 训练与推理约 4B 的 2-3 倍资源/时间——S1 按 4B 先出结果、9B 随后跟进的双轨节奏
- **数据规模**：1 万对起步（分布式生成约 1-2 天）；效果不达预期再扩
- **评估判据**：9B/4B 蒸馏后正确率 ≥ 各自基线 + 显著提升才算有效；无提升则诚实记录（"容量上限"结论也是产出）；1.8B/2B 对照组预期无提升——正好佐证容量决定吸收上限
