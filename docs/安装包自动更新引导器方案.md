## 1. 背景与目标

### 1.1 现状

- 安装包分发目前有两条通道：**GitHub Releases**（`SgfKrc/LEDS_BJTU`）与**官方源**（`packaging/serve.py` 起在 `http://100.90.76.108:9090/` 的 Tailscale 内网文件服务）。
- 节点要装新版本时，需要人工打开 release 页或官方源目录页，**自己判断**该下哪个包（集显版 exe / 独显版 exe / Android full / Android lite），再手动下载安装。
- 节点类型不同（集显 PC、独显 PC、安卓标准、安卓极简），选错包会装成错误变体（如把 CUDA 版装到集显机器，体积膨胀且无法加速；把 lite 版装成 full 版则功能缺失）。

### 1.2 问题

1. 人工选包容易选错变体；版本判断靠人眼（release 页文件名与 tag 版本号可能不一致，如 tag `v0.1.8` 的资产文件名仍是 `v0.1.7`）。
2. 更新路径分散：GitHub 网络不稳定时只能等官方源；官方源 IP 是 Tailscale 地址，换网络后 IP 变化，节点不知道去哪找。
3. 没有统一的"检查最新版 → 下载匹配包 → 校验 → 引导安装"流程，节点同步成本高。

### 1.3 目标

1. 提供一个**引导器**（`QLH-Updater`）：自行检测设备画像与配置，自动从更新源拉取最新 release 的**匹配安装包**，校验后引导安装。
2. 更新源双通道：**Git release 源**（GitHub Releases API）+ **官方源**（默认 `http://100.90.76.108:9090/`，Tailscale 内网）；任一不可用时自动故障转移。
3. **官方源 IP 可自定义**：本质是 Tailscale IP，通过配置文件 / CLI 参数 / 环境变量三种方式覆盖，默认值 `100.90.76.108:9090`。
4. 失败时给出可读的降级指引（打印手动下载链接），不阻塞节点使用旧版本。

> **非目标**：不做应用运行期热更新（代码/模型在进程内替换）；Android App 内自动更新仅出设计方向；不改动 `launcher.py` 现有启动流程，只提供可选集成点。

## 2. 总体设计

### 2.1 组件与数据流

```
┌──────────────┐   ┌───────────────┐   ┌───────────────┐
│  QLH-Updater │──▶│ Git release 源 │──▶│ GitHub API    │
│  (引导器)     │   │ (priority 2)  │   │ /releases/    │
└──────┬───────┘   └───────────────┘   │ latest        │
       │                                └───────────────┘
       │ 设备画像检测(平台/架构/GPU/变体)
       │
       ▼
┌──────────────┐   ┌───────────────┐   ┌───────────────┐
│ 资产匹配      │◀──│ 官方源         │──▶│ serve.py      │
│ (变体→文件名) │   │ (priority 1)  │   │ GET /latest.json
└──────┬───────┘   └───────────────┘   │ + 静态文件    │
       │                                └───────────────┘
       ▼
┌──────────────┐   ┌───────────────┐   ┌───────────────┐
│ 下载 + 校验    │──▶│ 本地下载目录    │──▶│ 引导安装       │
│ (SHA256/大小) │   │ (缓存复用)     │   │ (exe/apk/deb) │
└──────────────┘   └───────────────┘   └───────────────┘
```

### 2.2 主流程

1. **读配置**：合并默认值 ← 配置文件 ← 环境变量 ← CLI 参数（优先级递增）。
2. **检测设备画像**：平台、架构、GPU 能力、推导出安装包变体（见 §3）。
3. **查询最新版本**：按源优先级逐个请求清单；官方源读 `/latest.json`，Git 源读 `/releases/latest`；首个成功的源为准，其余源结果仅作一致性参考。
4. **版本比较**：语义化版本比较（`v0.1.7 < v0.1.8`）；与本地已装版本比较（读本地版本标记文件，见 §6.4），无新版本则提示"已是最新"。
5. **资产匹配**：用变体规则在清单资产中选下载 URL（见 §3.4）；匹配不到时给出降级建议（如独显版缺失 → 建议集显版）。
6. **下载**：到临时文件 → SHA256/大小校验 → 原子改名放入下载目录；同版本同校验值已存在则复用。
7. **引导安装**：默认**询问用户**；Windows 启动安装器 exe，Linux 提示 `sudo dpkg -i` / `apt install`，Android（后续阶段）FileProvider 拉起安装。
8. **结束**：打印本机下一步指引与手动下载链接（两源均失败时）。

### 2.3 与现有组件的关系

| 组件 | 关系 |
|---|---|
| `packaging/launcher.py` | 不修改现有启动流程；新增可选 `--check-update` / `--skip-update` 参数，在启动早期调用引导器（见 §10） |
| `packaging/serve.py` | 新增 `GET /latest.json` 清单端点（见 §5.3），其余行为不变 |
| `packaging/dist/` | 官方源资产根目录，与 GitHub release 资产保持同一命名约定 |
| `src/__init__.py` 等版本号文件 | 发布时按既有清单同步（见打包 README "版本号更新清单"） |

## 3. 设备画像检测

### 3.1 画像数据结构

```json
{
  "platform": "windows",        // windows | linux | android | darwin | other
  "arch": "x86_64",             // platform.machine() 归一化: x86_64/aarch64/...
  "gpu": "cuda",                // cuda | igpu | none | unknown
  "gpu_name": "NVIDIA GeForce RTX 4060",
  "variant": "cuda",            // 推导出的安装包变体: cpu | cuda | full | lite
  "os_version": "Windows 11 23H2"
}
```

### 3.2 检测方法

| 画像项 | Windows | Linux |
|---|---|---|
| platform | `sys.platform == "win32"` | `sys.platform == "linux"` |
| arch | `platform.machine()` | 同左 |
| GPU | ① `shutil.which("nvidia-smi")` 存在；② 执行 `nvidia-smi --query-gpu=name --format=csv,no-header`（超时 5s）返回非空 → `cuda`；③ 退化：WMI `Win32_VideoController` 名称含 NVIDIA/AMD（仅探测，不装 torch） | ① `shutil.which("nvidia-smi")`；② 读取 `/proc/driver/nvidia/version` 存在 → `cuda`；③ 其余 → `igpu` |
| 兜底 | 无 nvidia-smi 且探测失败 → `igpu`（集显默认，匹配 cpu 变体） | 同左 |

> 设计约束：引导器**不依赖 torch**（引导器要足够小、足够快），CUDA 探测用 `nvidia-smi` 存在性即可——驱动可用的机器必然有该可执行文件。`unknown` 仅在平台不支持时出现。

### 3.3 资产命名约定（本方案强制固化）

发布者在生成安装包与上传 release 时必须遵守（引导器按此匹配）：

| 变体 | 资产名模式（glob） | 说明 |
|---|---|---|
| PC 集显版 | `QLH-Edge-Inference-Setup-*.exe`（且不含 `-CUDA`） | Windows 集显/CPU 安装包 |
| PC 独显版 | `QLH-Edge-Inference-Setup-*-CUDA.exe` | Windows 独显安装包（未来资产） |
| Android 标准版 | `QLH-Inference-*-full-release.apk` | 安卓标准包 |
| Android 极简版 | `QLH-Inference-*-lite-release.apk` | 安卓极简包 |

> ⚠️ **版本号不参与资产匹配**：资产文件名中的版本号可能滞后于 tag（如 tag `v0.1.8` 的资产名为 `...-v0.1.7.exe`）。**最新版本一律以清单的 `tag` 字段为准**，资产匹配只按变体模式筛选，不解析文件名中的版本号。

### 3.4 变体 → 资产匹配规则

| platform | gpu | variant | 首选资产 | 降级策略 |
|---|---|---|---|---|
| windows | cuda | cuda | `*-CUDA.exe` | 缺失 → 提示用户可装集显版 `Setup-*.exe`（不自动降级，询问） |
| windows | igpu/none | cpu | `Setup-*.exe` | — |
| linux | 任意 | cpu/cuda | `*.deb`（未来资产） | 缺失 → 提示源码部署路径 |
| android | — | full | `*-full-release.apk` | 由 App 内更新器使用（后续阶段） |
| android | — | lite | `*-lite-release.apk` | 同上 |

## 4. 更新源设计

### 4.1 源类型

**A. Git release 源（默认 priority 2）**

- 端点：`GET {api_base}/repos/{repo}/releases/latest`，默认 `https://api.github.com/repos/SgfKrc/LEDS_BJTU/releases/latest`。
- 提取：`tag_name`（版本）、`assets[].name`、`assets[].browser_download_url`、`assets[].size`。
- 可配 `api_base` 以支持镜像/代理（如 `https://ghproxy.com/...` 类前缀），默认走官方 API。
- 无 `sha256` 字段 → 下载后仅做大小校验，并打印"无法校验完整性"警告。

**B. 官方源（默认 priority 1）**

- 根地址：`http://100.90.76.108:9090/`（Tailscale 内网，`serve.py` 服务）。
- 清单端点：`GET {root}/latest.json`（serve.py 扩展，见 §5.3），字段与 Git 源对齐并**额外提供 sha256**。
- 文件下载：`GET {root}/{asset_name}`，即现有 serve.py 静态文件能力。

### 4.2 优先级与故障转移

1. 按配置的 `source_order` 依次尝试；默认 `["official", "git"]`（内网快、有 sha256，优先）。
2. 单源判定失败：连接超时（默认 15s）/HTTP 5xx/清单 JSON 解析失败/清单为空。
3. 首个成功源决定"最新版本与资产列表"；若官方源与 Git 源版本不一致，**取版本号更大者**并在日志中提示差异。
4. 两源全部失败：打印两源的手动访问链接（GitHub release 页 + 官方源首页），退出码 2。

### 4.3 自定义官方源地址（Tailscale IP）

优先级从低到高（后覆盖前）：

| 方式 | 示例 |
|---|---|
| 内置默认 | `http://100.90.76.108:9090` |
| 配置文件 | `{"sources": [{"type": "official", "url": "http://100.88.99.1:9090"}]}` |
| 环境变量 | `QLH_UPDATE_SOURCE=http://100.88.99.1:9090` |
| CLI 参数 | `qlh-updater --source http://100.88.99.1:9090` |

自定义值校验：必须是 `http(s)://host[:port]`，host 允许域名/IP（含 Tailscale `100.x.y.z`）；拒绝包含路径深度、`..`、非 http(s) 协议（防伪造源注入）。

## 5. 配置与清单协议

### 5.1 配置文件

- 路径：Windows `%LOCALAPPDATA%\QLH-Edge-Inference\updater.json`；Linux `$XDG_CONFIG_HOME/qlh/updater.json`（无 XDG 时 `~/.config/qlh/updater.json`），与 launcher 配置目录约定一致。
- 字段：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 整体开关 |
| `sources` | array | 官方 + Git | 源列表（type: `official`/`git`，url，api_base，repo） |
| `source_order` | array | `["official","git"]` | 尝试顺序（按 `sources` 中 type 引用） |
| `timeout_seconds` | int | `15` | 单请求超时 |
| `download_dir` | string | 见 §6.2 | 下载目录 |
| `auto_install` | bool | `false` | 校验通过后是否免询问直接启动安装 |
| `device_override` | object\|null | `null` | 手工覆盖画像（调试/特殊机器用），如 `{"gpu":"cuda"}` |
| `git_api_base` | string | `https://api.github.com` | Git 源 API 前缀（镜像/代理） |

示例：

```json
{
  "enabled": true,
  "sources": [
    {"type": "official", "url": "http://100.90.76.108:9090"},
    {"type": "git", "repo": "SgfKrc/LEDS_BJTU"}
  ],
  "source_order": ["official", "git"],
  "timeout_seconds": 15,
  "download_dir": "",
  "auto_install": false,
  "device_override": null
}
```

### 5.2 本地已装版本标记

- 文件：与配置文件同目录 `installed.json`，内容 `{"tag": "v0.1.7", "variant": "cpu", "installed_at": "..."}`。
- 由安装包卸载钩子/引导器首次成功安装后写入；`--force` 可忽略该标记强制重下。

### 5.3 官方源清单协议（serve.py 扩展）

`GET /latest.json` 返回：

```json
{
  "tag": "v0.1.8",
  "published_at": "2026-08-07T18:00:00+08:00",
  "assets": [
    {"name": "QLH-Edge-Inference-Setup-v0.1.7.exe", "size": 157949378, "sha256": "…"},
    {"name": "QLH-Inference-v0.1.7-full-release.apk", "size": 7004505, "sha256": "…"},
    {"name": "QLH-Inference-v0.1.7-lite-release.apk", "size": 1636757, "sha256": "…"}
  ]
}
```

- 扫描范围与现有 serve.py 一致（`packaging/dist/*.exe` + `*.apk` + Android Gradle 输出），按 §3.3 模式归类。
- `tag` 来源：`packaging/dist/` 下资产名的最大版本号，或根目录 `version.txt`（serve.py 维护者手动写）——**保证与 release 同步是发布流程责任**。
- sha256 计算对大文件（1.7 GB）耗时：按 `mtime+size` 做内存缓存，文件未变不重算。
- 兼容性：serve.py 未升级的旧节点直接访问 `/latest.json` 返回 404 → 引导器将官方源标记失败，走 Git 源。

## 6. CLI 与交互

### 6.1 命令形态

```
qlh-updater [命令] [选项]

命令（默认 check）:
  check       检测设备画像 + 查询最新版，打印结果，不下载（退出码 0=最新 / 3=有更新）
  download    下载匹配安装包到下载目录（含校验）
  install     download + 引导安装（默认询问；--yes 免询问）
  list        列出各源清单与匹配结果（诊断用）

选项:
  --source URL        覆盖官方源地址（Tailscale IP 自定义）
  --force             忽略本地已装版本标记
  --yes               免询问（配合 auto_install）
  --config PATH       指定配置文件
  --json              机器可读输出（stdout 单行 JSON）
  --headless          无交互，自动选择安全默认（不自动安装）
```

退出码：`0` 已最新/成功；`1` 有更新但用户取消；`2` 错误（网络/清单/校验失败）；`3` 有更新（check 模式）。

### 6.2 下载目录

默认 Windows `%LOCALAPPDATA%\QLH-Edge-Inference\downloads`、Linux `~/.cache/qlh/downloads`；可配置。下载先落 `.part` 临时文件，校验通过后原子改名；已存在同名同大小文件时跳过（打印"已下载"）。

### 6.3 交互 UI

- Windows：复用 launcher 的 Win32 对话框风格（`MessageBox` 确认安装、进度条窗口可选）；无 pywebview 依赖。
- Linux：优先 `zenity`，缺失回退纯 CLI 提示（与 launcher 现有策略一致）。
- `--headless`/`--json`：全程无交互。

### 6.4 版本比较

- 解析 `tag` 为 `(major, minor, patch, prerelease)`；忽略 `v` 前缀；预发布版本（`-rc1` 等）默认不选，除非 `--include-prerelease`。
- 本地标记缺失（首次运行）→ 视为"需要下载"。

## 7. 安全与健壮性

| 项 | 措施 |
|---|---|
| 清单来源 | 官方源为 Tailscale 内网 HTTP，信任模型 = Tailscale 网络身份（成员可互相访问）；Git 源强制 HTTPS + 证书校验 |
| 下载校验 | 官方源：SHA256 必须匹配，否则丢弃并报错；Git 源：大小校验 + 警告 |
| 路径安全 | 资产名白名单匹配 §3.3 模式；下载 URL 只允许拼接已匹配的资产名，禁止用户输入直接进 URL |
| 临时文件 | `.part` 后缀，崩溃残留可清理；完成前不覆盖已有文件 |
| 安装行为 | 默认询问；`auto_install` 默认关闭；Windows 以普通权限 `ShellExecute` 启动安装器 |
| 自定义源校验 | §4.3 的协议/host 白名单，拒绝非 http(s) |
| 杀软友好 | 沿用 launcher 约定：不 spawn 可疑进程（仅 nvidia-smi 探测），用标准库 urllib |

## 8. Android 端设计方向（后续阶段，不在首期）

- App 内置"检查更新"：请求官方源 `/latest.json`（或 Git API），解析 `tag` 与 `BuildConfig.VERSION_NAME` 比较。
- 变体由 `BuildConfig.FLAVOR`（`full`/`lite`）决定，直接匹配同变体 apk。
- 下载 → 校验 SHA256 → `FileProvider` 拉起系统安装器（需 `REQUEST_INSTALL_PACKAGES` 权限）。
- 本方案首期不实施，原因：APK 分发可走现有 release/官方源直接装，且 Android 安装权限与签名校验需要单独设计。

## 10. 测试方案

`tests/test_updater.py`（pytest，纯逻辑不联网）：

1. 画像检测：mock `platform`/`shutil.which`/subprocess → windows+cuda / windows+igpu / linux+cuda / linux+igpu 四组合法推导。
2. 资产匹配：给定清单 → 各 variant 命中正确资产；`-CUDA` 缺失时降级提示；文件名版本滞后于 tag 不影响匹配。
3. 版本比较：`v0.1.7 < v0.1.8`、`v0.1.8-rc1 < v0.1.8`、相等、预发布默认排除。
4. 清单解析：合法 JSON / 缺字段 / 坏 JSON / 空 assets → 对应失败归类。
5. 源优先级：官方失败（404/超时）→ 自动切 Git；两源版本不同取大者。
6. 配置合并：默认值 < 文件 < 环境变量 < CLI；非法 `--source` 拒绝。
7. 校验：sha256 匹配/不匹配；`.part` 原子改名；已有文件复用。
8. serve.py `/latest.json`：构造临时 dist 目录 → 清单字段与 sha256 正确、缓存命中不重算。

## 11. 风险与待确认

| 风险/事项 | 影响 | 对策 |
|---|---|---|
| GitHub 网络不稳定 | Git 源失败 | 官方源优先 + 双源故障转移 + 手动链接兜底 |
| 官方源 `tag` 与 release 不同步 | 节点拿到旧清单 | 发布流程强制：发布前跑 serve.py 清单生成，README 固化检查项 |
| 资产命名不遵守约定 | 匹配不到 | 匹配失败打印"可用的全部资产名"辅助排查；P1 在 serve.py 侧做命名 lint |
| 大文件 sha256 计算耗时 | 清单生成慢 | mtime+size 缓存；必要时 P1 后改为发布时预生成 `sha256s.txt` |
| 旧版 serve.py 节点无 `/latest.json` | 官方源 404 | 引导器把 404 视为该源不可用，自动切 Git 源 |
