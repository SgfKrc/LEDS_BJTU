### 4.2 GitHub 远端网页版准备清单（docagent 示例，逐项可在 UI 完成）

| # | 操作 | 说明 |
|---|---|---|
| G1 | **New repository**：名称（如 `qlh-docagent`）、描述、可见性 | 建议**先 Private**（内部验证期），准备给他项目引用时再 Public；**不勾选** README/.gitignore/LICENSE 初始化文件（本地已有内容，勾选会带来合并冲突与"空壳初始化"问题） |
| G2 | 归属：个人账号 或 新建 Organization | 强调学校/队伍语义可建 org（如 `QLH-*`）；个人账号更简单 |
| G3 | **推送认证**：确认本机可用凭据 | 主项目 push 用 HTTPS（Git Credential Manager 已记住），同账号新仓库直接可推；若走 SSH：Settings → SSH and GPG keys 加本机公钥；若用 PAT：Settings → Developer settings → Personal access tokens（`repo` 权限） |
| G4 | **Actions（可选）**：Private 仓库每月约 2000 免费分钟，Public 免费 | docagent CI（pytest + 规则预演 demo）默认开启；首次运行在 Settings → Actions → General 确认 workflow 权限（需"允许 Actions"） |
| G5 | **分支保护（可选）**：Settings → Branches → Add rule（`main`：要求 PR + CI 通过） | 单人可后置；公开后建议开启 |
| G6 | **LICENSE/README**：子项目根放 LICENSE | 建议与主项目一致（主项目当前无 LICENSE 文件——需先定，建议 **Apache-2.0** 或 MIT；"通用工具"给人用更推荐 MIT） |
| G7 | **submodule 引用方体验**：主项目 `git clone --recursive` 或 `git submodule update --init` | 仓库需对引用者可见（Public 或同账号 Private）；submodule URL 用 HTTPS 全路径 |
| G8 | 发布（远期，P3/P4 后）：Git tag + GitHub Releases / PyPI | 不阻塞独立化 |

> 提醒：主项目转 submodule 前，先锚定主项目当前 `tools/docagent/` 的 commit；独立仓库初始 commit 从同一内容起，主项目 gitlink 更新与目录替换**一次提交完成**。
