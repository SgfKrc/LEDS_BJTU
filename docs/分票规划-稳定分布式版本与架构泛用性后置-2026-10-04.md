# 分票规划：稳定分布式版本优先（2026-10-04）

本规划落实《关键架构泛化与分布式调度可用性审查报告》的裁定。近期目标是做出一条可重启、可重连、可验收的分布式生产链；模型架构泛用性和 KTransformers 优化均后置到同一优先级，不与稳定性收敛抢占主线。

## 产品裁定

1. **A1 relay 从产品调度入口剔除。** A1 依赖 probe/SSH 隧道和 loopback 段服务，保留为技术探针与历史证据，不再作为 `/api/chat` 的生产候选、容量来源或可用性证明。探针脚本、工件和证据暂不删除，避免丢失复现材料；后续单独做归档票。
2. **A3 Route A 是本阶段唯一生产主线。** 生产请求只允许统一的 `stage_offer_v3`/task-worker 链；legacy layer relay 不再与 A3 并列参与同一调度域。暂不支持的节点应明确处于不可用状态，而不是进入另一套 relay 协议。
3. **“分布式可用”必须 fail-closed。** 只有 `distributed_used=true`、`fallback=false`、`claimed_layers` 非空并通过逐 token 对拍，才能计为成功；本地整模回退、探针成功和 HTTP 200 均不能替代该门槛。

## P0：近期必须完成

### DIST-0：生产线路收敛与 A1 退场

**状态：已完成（2026-10-04）。** 生产入口默认 probe-only，A1 不再作为生产候选；实现与回归见 `PIPELINE_RELAY_PROBE_ONLY` 及 relay 线路测试。探针代码和证据仍保留。

**目标**：删除 A1 对生产调度的影响，保留探针能力但与产品路径隔离。

- 在 scheduler 的候选、readiness、assignment、forward 和 fallback 判据中禁止读取 `QLH_RELAY_ENABLED`/`QLH_RELAY_SEGMENTS` 作为生产能力。
- 将 relay 入口标成 probe-only；生产请求若检测到该配置，只记录具名诊断并继续走 A3，不能悄悄切换到 A1。
- 清理或隔离 scheduler 侧无效 relay session/cache；探针脚本继续使用独立入口。
- 更新线路清单和运行手册，明确 A1 证据不计入产品验收。

**验收**：开启 A1 环境变量不会改变生产 assignment；混合 legacy/A3 不再进入半可用状态；生产日志不出现 A1 relay 委派；A3 的候选、层声明和错误原因可独立追踪。

### DIST-1：配置生命周期单一事务源

**状态：恢复路径已实测通过（2026-10-05，两段链）；完整的单一事务状态机仍未合并。**

实测结论（2026-10-05，master pytorch `[0,16)` + Surface GGUF `[16,24)`，两段）：重启后闸门按设计挂起、worker 重连 hello 触发权威重发、闸门解除、请求成功（`distributed_used=True` / `fallback=False` / `claimed_layers=[16,24]`）。**这条路径此前从未实测过**（`:34` 自述「三机重启实测仍待执行」），首次实测即暴露出**两个此前未知的缺陷**，均已修复：

1. **恢复闸门死锁**：闸门解除要求「新代际的权威重发」，而重发**只在请求路径**触发、请求又被闸门自身拒绝 ⇒ 没有任何路径产生新代际（实测：三机全在线、TCP 已重连、`hello accepted=True`，请求仍返回 `pipeline_recovery_pending` 直到超时）。修法：worker 重新 hello 是「节点回来了」的权威信号，在 `_handle_task_worker_message` 的 hello 分支里、恢复期补一次 `request_authoritative_layer_sync(require_distributed=True)`（`3ddb3695`）。
2. **双栈下进程内两套 `TCPServer`**：`run_api_servers()` 在通配地址下为 `0.0.0.0` 与 `::` 各起一个 `uvicorn.Server`（共享同一 `app`）⇒ lifespan 跑两次 ⇒ `scheduler.start()` 跑两次（无幂等保护）⇒ 两个实例同时监听 8888，`_tcp_server_default` 被覆盖，而 worker 的连接只被其中一个 accept。请求线程读到空 `clients`，连锁导致 `worker_tcp_disconnected`、assignment 拿不到 `execution="stage_offer_v3"`、capacity 求解器从未被调用而退化成 `simple_weight` 分配（`Layer 13-20` / `15-24` 即由此而来）。修法两层：`Scheduler.start()` 加**并发**幂等守卫（锁内「检查 + 占位」，`9dcd1e04`）+ 根因面让 `_lifespan` 的启动/关闭**进程级只执行一次**（`5fb024cb`）。

顺带修掉一个误导诊断的展示缺陷：stage-only 提交漏回写 active plan 的 `transaction_phase`（legacy 路径有、Route A 没有），使 `/api/cluster/pipeline-capacity` 恒定返回求解器初值 `planned` 且投影里没有 `config_id`/`generation` ⇒ 看上去像「事务不存在」（`2bd885ac`）。

**仍未完成**：`_layer_config_*` 那 ~20 个状态集合没有合并成单一显式状态机；`assignment_id` 维度仍未引入（`:38` 的版本三元组只落实了前两维）。

本轮实现：REGISTER ACK 后被标记为 pending 的新连接，即使 hello 能力内容与上一代完全相同，也会被视为一次连接代际变化并触发层配置重新发布；同一连接内的重复 hello 仍保持幂等，不会形成自激重推。

本轮继续实现：容量事务以 `pipeline_config_lifecycle_v1` 写入本地 SQLite，记录 `config_id/generation/phase/worker_ids` 等受限元数据；master 启动时若发现上次事务处于 `preparing/committing/ready`，先挂起分布式就绪与普通整模回退，等待基于当前在线节点重新发布并完成 ACK。旧记录只作为恢复闸门，不会被直接当作新连接的活动配置；恢复失败保持 fail-closed。

本轮新增回归契约：重启后旧 `config_id` 不得直接使 readiness 变为 ready；新代际在所有期望 worker 完成确认前不能解除闸门；Route A stage-offer worker 需重新满足当前健康/能力判据；持久化记录不携带 set、模型路径或执行器对象；生命周期写入失败时，即使内存事务到达 ready 也不得解除闸门，只有 ready 状态成功落库后才能继续；相同或更旧的持久化 `(config_id, generation)` 不能被当作新活动配置。验证已完成：`tests/test_scheduler.py` 318 passed，`tests/test_local_store.py tests/test_task_worker_adapter.py` 90 passed，另有编译检查和 `git diff --check`；三机重启实测仍待执行。

**目标**：消除 master 重启后 release 与 re-ACK 互相打断、节点没有已确认活动配置的问题。

- 以 `(config_id, generation, assignment_id)` 作为唯一活动配置版本，任务只引用已 commit 版本。
- 将 push、ACK、release、re-ACK、restart rehydrate 合并到一个显式状态机；旧 generation 的 ACK/release 必须幂等忽略。
- master 重启后先恢复配置事务，再开放新请求；恢复失败必须具名 fail-closed。

**验收**：重启/重连窗口内无 stale active config、无旧 ACK 污染；同一配置重复 ACK 和重复 release 均幂等；连续请求不会因配置生命周期竞态回退。

### DIST-2：节点可用性与故障收敛

**目标**：将 heartbeat、task-worker lease、presence、layer readiness 收敛为可解释的可用状态。

- 定义 `registered -> admitted -> ready -> leased -> draining/offline` 状态转移及唯一超时来源。
- 节点掉线、任务取消、配置失效必须释放 lease 并阻止旧任务结果回写。
- readiness 不满足时快速返回具名错误，禁止等待多个互相独立的超时后才 fallback。

**验收**：Surface/Y700 断线、重连、后台任务残留和 master 重启均能在固定时间内收敛；无重复分配、无旧任务结果串台。

### DIST-3：三机发布验收与长时 soak

**目标**：把真实设备链闭环为可重复的发行门。

- master + Surface + Y700 运行 A3，覆盖 prefill、至少两步 decode、取消、重试。
- 注入 master 重启、Surface 断线、Y700 USB/网络抖动、worker 重连和配置重发。
- 保存请求级证据：`distributed_used`、`fallback`、`claimed_layers`、generation/config_id、逐 token 对拍结果。

**验收**：连续 soak 至少 2 小时；所有成功请求满足四项分布式判据；失败请求快速、可解释且不返回伪成功文本。

### DIST-4：可观测性与发布闸门

**目标**：让“真的走了分布式”和“本地回退成功”不可混淆。

- 统一请求级 route、assignment、generation、worker、layer range 和 fallback reason 日志。
- 对 A1 配置、legacy bridge、整模回退和能力广告缺失增加显式指标。
- 发布脚本默认关闭实验线路，只允许显式开启 A3。

**验收**：从单条请求日志可重建完整链路；任何 fallback 或能力缺失都不会伪装成分布式成功。

## P1：稳定版之后并行开发

### GEN-1：架构适配器与模型描述符契约

把模型适配从 Qwen 分支提升为 descriptor/adapter 注册契约，覆盖 tensor layout、layer loader、forward/cache、norm/head、prompt 和 KV 语义。第一阶段先选择一个非 Qwen decoder 做完整对拍，不以“能加载”作为支持标准。

**分类依据：按「计算图契约」分，不按模型系列名分。**

对齐 llama.cpp 的做法（依据：`llama-arch.h` 的 `LLM_ARCH_*`，桌面侧 b10431 实测 ~150 项）——它新增一个 arch 的判据是**图能否复用**，不是名字像不像。同类证据：

- `LLM_ARCH_MISTRAL3` / `MISTRAL4` 存在，但**没有** `LLM_ARCH_MISTRAL` / `MISTRAL2` ⇒ **Mistral 1/2 直接复用 `LLM_ARCH_LLAMA`**（与 Llama 同构）。
- MoE 在**图不同时**才是独立 arch（`QWEN2MOE` / `GLM4_MOE` / `GRANITE_MOE` / `PHIMOE`），图相同时靠 `n_expert` 参数表达（Mixtral 即如此复用 `LLAMA`）。
- 多模态里**改了位置语义的**才独立（`QWEN2VL` / `QWEN3VL`，M-RoPE）；视觉编码器是独立 `LLM_ARCH_CLIP` + 独立 mmproj 文件，不进主模型图。
- 混合 SSM 独立（`MAMBA` / `JAMBA` / `FALCON_H1` / `GRANITE_HYBRID`）——state 语义不同。
- **`LLM_ARCH_RWKV6QWEN2`**：一个 arch 名里带**两个系列** ⇒ 命名服务于图而非系列。
- **RoPE 变体本身不是 arch**，是 `rope.scaling.type` 参数。

因此 descriptor 契约的维度应按「每一维都是『图会不会变』」来定：

1. **attention**：MHA / GQA / MQA / sliding-window / linear-attn / 混合 SSM
2. **norm**：类型（RMSNorm / LayerNorm）+ 位置（pre / post）
3. **FFN**：dense / MoE（含路由方式）
4. **RoPE**：变体，特别是 `n_pos_per_embd`（M-RoPE = 4）
5. **head**：tied / untied
6. **KV 语义**：纯 attention / recurrent state / 混合

**QLH 比 llama.cpp 多一个维度：层接力可行性。** llama.cpp 的 arch 只回答「能不能加载」，不回答「能不能跨节点接力」。典型反例是 `qwen3*` 的 keep-head 挂点在 `output_norm` **之后**（`docs/已知问题记录.md` `#35`），所以它在 GGUF 上能加载、却**不能**做层接力上游。⇒ QLH 需要的状态表是 **arch × 层接力可行性** 的二维，而不是 arch 一维。

### GEN-2：非 Qwen 适配矩阵

建立**非 Qwen decoder** 的明确状态：已支持并对拍、协议可用但未验收、或安全拒绝。每个架构必须通过 descriptor → assignment → prefill → decode → full-model 对拍门。

**矩阵的行按 GEN-1 的图契约维度取，不按 `Llama/Mistral/Phi/Gemma` 这类系列名取**——那个列法会误导适配边界：Mistral 1/2 与 Llama 同构，不是独立基座；反过来同一个系列可以有多个 arch（Qwen2 / Qwen2MoE / Qwen2VL）。

矩阵每个格子要同时给两列状态：

- **加载/前向可行性**（对齐 llama.cpp 的 arch 判据）；
- **层接力可行性**（QLH 独有：能否作为 `stage_offer_v3` 的上游/下游段，含 keep-head 挂点是否在 `output_norm` 之前）。

第一阶段的候选应优先选**图最简单、且挂点在 norm 之前**的非 Qwen decoder（如与 Llama 同构的 dense 模型），把「图契约 + 接力」两条链一并走通，再扩到 MoE / VL / 混合 SSM。


### KT-1：KTransformers 优化迁移

保持当前暂停状态，和 GEN-1/GEN-2 同优先级。只迁移可验证的算法/数据层优化，不把 KT 引擎直接并入近期 A3 生产路径。

## P2：归档与清理

- `RELAY-ARCHIVE`：将 A1 的 probe/SSH 隧道、relay 工件和证据移入明确的实验归档入口；删除生产文档中的“产品线路”措辞。
- `LEGACY-RETIRE`：在 A3 稳定后再移除 legacy layer relay 的生产兼容分支和死代码，保留迁移期诊断。
- `MATRIX-DOC`：维护模型架构、设备形态、线路和验收状态矩阵。

## 执行顺序

`DIST-0 → DIST-1 → DIST-2 → DIST-4 → DIST-3` 为稳定版主线；`DIST-3` 之前不得宣称“稳定可用”。`GEN-*` 与 `KT-1` 后置并行，不阻塞当前稳定版；`RELAY-ARCHIVE` 和 `LEGACY-RETIRE` 在主线验收后处理。
