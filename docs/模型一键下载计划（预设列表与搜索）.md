## 1. 现状复核（2026-08-21）

**已具备（可复用，不重复造）**：
- CLI 一键导入：`python scripts/model_tools/import_model.py <source> [--modelscope] [--proxy …] [--expected-sha256 …] [--register]`
  —— source 支持 HF repo id、ModelScope path、本地目录；HF 走 `huggingface_hub.snapshot_download`，
  ModelScope 走 `modelscope.snapshot_download`；代理读 `--proxy` / `QLH_HTTP_PROXY` / `QLH_HTTPS_PROXY`；
  SHA 校验 fail-closed；`--register` 写入主节点 SQLite `model_registry`。
- 后端运行面：`POST/GET /api/models/registry`、`POST /api/models/load|prepare-pipeline`、
  `POST /api/models/unload`、`POST /api/models/switch`、`GET /api/models/available`、
  `GET/POST /api/models/local-assets/…preflight`、`GET /api/models`、`GET /api/models/downloadable`（Android/从节点 manifest）。
- 资产工具与质量门：`scripts/model_tools/` 的 inspect/verify/sweep/sync_status/llm_smoke_matrix/SD 批测；
  RAM/VRAM 资源门与 `llm_smoke_matrix` 配套（DeepSeek-7B Safetensors 因内存被正确 resource_rejected）。

**缺口（本文档要补）**：
1. 无「用户点一下」触发端到端下载+部署的界面/端点——所有前端（含 `frontend_cybergothic` ModelsPage）
   只有 加载/卸载/切换/本地资产 preflight，没有安装按钮；
2. 无**预设模型列表**（官方 curated 一键可装）；
3. 无 **HF / ModelScope 仓库搜索**。
（旧 `src/model_downloader.py` 仅为交互式复制命令的辅助器，不是 UI 点击闭环，维持原状不扩展。）

## 2. 目标与原则

- **用户点击 → 后台 job**（下载 → SHA 校验 → 注册 → 冒烟/就绪）→ 前端状态展示；失败可查、可取消、幂等。
- **双源**：Hugging Face 与 ModelScope 均可用（同一 preset 尽量双镜像）。
- **CPU/GGUF 优先**：与硬件阻塞表（`docs/验收清单与资源限制登记.md` A5/A2/A3/A6）一致，
  预设按当前机 RAM/VRAM 标注「可装 / 硬件不足不可装」，避免 Safetensors 大模型触发资源拒绝。
- **显式 opt-in**：安装不隐式改变默认模型/路由；不自动多模型驻留。
- **脱敏/合规**：不保存 HF/ModelScope token；只登记 repo 元数据与受控摘要；下载量有界、进度脱敏。

## 3. 短期（P0）：预设模型列表一键装

**预设数据模型**（`model_presets`，SQLite 或代码内置均可，先代码内置便于审查）：

```toml
id = "qwen1_8b-gguf"            # 稳定的预设 id
display = "Qwen 1.8B Chat (GGUF)"
kind = "gguf"                   # gguf | safetensors | sd-asset
source = "hf+ms"                # 双镜像：hf => Qwen/Qwen1.5-1.8B-Chat-GGUF
default_engine = "cpu"          # cpu|cuda
default_quant = "q4"            # 有量化层级时
default_model_id = "qwen1.8b"   # 注册簿 model_id
resource_gate = { ram_gb = 4, vram_gb = 0, disk_gb = 2 }
expected_sha256 = "…"           # 可选，严格时提供
```

**后端**（复用 import_model 流程包成 job）：
- `POST /api/models/downloads { preset_id | source:{…}, target, model_id, engine }` → 创建异步 job
  （状态机：queued → downloading → verifying → registering → ready / failed），幂等（同 source+target 去重）；
- `GET /api/models/downloads`、`GET /api/models/downloads/{id}`（进度/状态/脱敏错误）、`DELETE …`（取消/清理）；
- `GET /api/models/presets` → 预设列表 + 当前节点资源评估（装得下/装不下）。

**前端 / TUI**：
- Model 页新增「可安装模型」区：预设卡（名称、来源、大小、资源门）→「安装」→ 进度条/阶段/完成状态；
- TUI：`/model install <preset_id>`、`/model jobs`、`/model presets`。

**初始预设（首批，全部 CPU/GGUF 优先，规避硬件阻塞）**：
| 预设 | 形态 | 双源 | 备注 |
|---|---|---|---|
| Qwen 1.8B Chat | GGUF + Safetensors | hf+ms | 与 `llm_smoke_matrix` 既有资产打通 |
| Qwen3 3.8B | GGUF | hf+ms | 需先核实公开 GGUF 存在；否则仅 safetensors 并可装为测试 |
| QW3-VL-4B | safetensors | hf+ms | 判题已实跑；标记中资源门 |
| DeepSeek-7B | GGUF | hf+ms | Safetensors 7B 全部 resource_rejected，GGUF 规避 |
| SD 1.5 资产 | sd-asset | 本地已核准 | `diffusion/assets` 已有 download 端点，接线到同页 |

**边界**：预设 = 推荐可装清单，不自动下载；全部显式点击触发；不做跨模型 hidden-state。

## 4. 中期（P1）：搜索 Hugging Face / ModelScope

- 后端 `GET /api/models/search?q=&source=hf|ms|all&page=`：
  - HF：`huggingface_hub.HfApi().list_models(search=q, limit=n, sort="downloads")`
  - ModelScope：`modelscope.hub.list_models` 或公开 HTTP API；结果投影为统一的脱敏元数据
    （id、描述、task/tags、大小估算、截断 sha 摘要；不返回 token/凭据/完整 sha）。
- 前端：搜索框 → 结果卡（显示来源徽标、大小估算、资源门评估）→「安装」→ 走 P0 同一条 job 管线。
- 资源门在安装前用 API 元数据估算；估算不准确时只做提示，不做硬拦截。

### P1a 源与代理策略（已落地）

- `GET /api/models/search?q=&source=hf|ms|all&page=&limit=&proxy=` 返回统一脱敏投影：只含仓库 ID、来源、描述、任务/标签、下载量、大小、许可证、公开状态和网页 URL；不返回文件清单、凭据、完整 SHA 或原始 provider payload。
- `source=all` 的固定顺序为 **HF 直连 → HF 代理 → ModelScope 直连**。代理只用于本次搜索请求，默认回退 `http://127.0.0.1:7897`，也可通过用户显式 `proxy` 或 `QLH_MODEL_SEARCH_PROXY` / `QLH_HTTP_PROXY` 配置；直连阶段不继承系统代理。
- `source=hf` 只在 HF 直连/代理之间重试；`source=ms` 只访问 ModelScope，尊重用户明确的源选择。
- 每个阶段记录 provider/transport/失败码，不记录 URL 中的凭据或原始异常。全部失败返回带 `X-QLH-Error-Code` 的 `502 SEARCH_UNAVAILABLE`，不伪装成空成功；非法 query/source/proxy 返回 `400`。
- 单次最多 50 条、搜索词最多 128 字符、网络请求超时 8 秒；P1b UI 展示 `provider`、`fallback_used` 和可读的失败状态。

### P1b 搜索 UI 与安装接线（已落地）

- `frontend_cybergothic` 的 Downloads 工作区新增搜索词、`all|hf|ms` 源切换和可选回退代理输入；搜索结果以语义表格展示来源、任务、大小、热度、许可和外部仓库链接。
- 搜索结果安装复用 `POST /api/models/downloads`：HF 结果保持 `use_modelscope=false`，ModelScope 结果使用 `use_modelscope=true`；私有或 gated 结果只显示授权提示，不盲目排队。
- UI 展示后端 `provider`/`fallback_used` 和失败状态；下载任务继续统一显示进度、状态、错误和取消操作。
- 预设、搜索和下载任务均提供 fixture 流程，后端离线时可验证搜索→安装→job 的完整交互；真实模式不写入 token 或前端缓存。

## 5. 明确不做（边界）

- 不实现 MODEL-FLEET 内容寻址工件库 / 远端 PostgreSQL 投影（远期计划，另立；
  本计划只做「离线 snapshot + 本地注册」这一种分发形态）。
- 不自动填充/保存 HF 或 ModelScope 凭据；搜索不是全量镜像。
- 不隐式改变默认模型、默认路由或 worker 选择策略。
- 预设/搜索结果一律「可安装」，真实可用性仍以 `llm_smoke_matrix` 为准。

## 6. 验收口径

- **P0 预设**：自动化（fake/small preset 回环）后端 job 端到端通过；真实 Qwen 1.8B GGUF
  「点一下」可装 + `llm_smoke_matrix` 冒烟通过；界面展示进度与就绪/失败；TUI 三命令可用；
  硬件不足预设在前端正确标灰不可装。
- **P1 搜索**：HF 与 ModelScope 至少各一轮真实搜索返回脱敏结果；真实小模型经搜索安装走通端到端；
  搜索接口在源站不可达时 fail-closed（返回明确错误而非空成功）。
- 本计划实施期间不宣称「生产级一键安装」；真实网络/代理/配额场景按验收记录逐项登记。
