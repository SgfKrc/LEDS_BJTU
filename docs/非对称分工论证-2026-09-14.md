# CACHE-05 非对称分工论证（2026-09-14）

> 结论：DeepSeek-V4.1-Flash 的输入/输出参数非对称是架构参考；QLH 当前能验证的是**系统角色非对称**，即小模型负责低成本提议或专项探测，较强模型负责校验/最终输出。本文不宣称复现 V4.1 架构，也不开放生产 draft-verify 路径。

## 1. 一页对照

| 参照/岗位 | 输入侧或草稿侧 | 输出侧或校验侧 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- | --- |
| DeepSeek-V4.1-Flash | 官方资料记载输入侧 8B active | 官方资料记载输出侧 16B active | 一个模型架构可以按输入/输出工作负载分配容量 | 不能证明 QLH 的小模型组合等价于 552B MoE Causal Encoder-Decoder |
| QLH `draft-verify` | 本地 Qwen2.5-0.5B / Qwen3-0.6B 候选提出 token；通过 token id 和概率与 verify 对接 | DS3-0324-7B 或明确允许的外部 endpoint 校验并决定修正 | 在共享 tokenizer、可见概率和相同随机种子下，测量接受率、每轮 token 和端到端成本 | 不改变 verify 的能力；HTTP top-k 重建不等于精确分布；当前没有生产解码接线 |
| 亚 1B 岗位化 | Qwen2.5-0.5B 做链路/上下文基线；Qwen3-0.6B 做 thinking 开关与画像探测；MiniCPM4-0.5B 做架构/低配探针 | 主节点 host gate、较强回答模型或人工复核作为边界 | 测量每个专项契约的资源和失败回退成本 | 不能把任一专项通过写成通用正确率或自主工具能力 |
| DS3-0324-7B 候选 | 不承担小模型草稿质量结论 | 作为判题/verify 的质量权威候选 | 复用已有 DS3 v2 标定和判题口径证据 | 不等于已经完成生产引用点切换或人工复核 |

三者的共同抽象是“不同成本的角色承担不同责任”，而不是“参数规模可以直接互换”。`src/speculative.py` 已经保证接受/拒绝和修正逻辑以 verify 分布为准；它的 draft 函数、共享 tokenizer、外部状态和收益门仍是实验前提。

## 2. 可验证假设

| ID | 假设 | 对照与控制变量 | 主指标 | 证伪条件 |
| --- | --- | --- | --- | --- |
| `ASYM-01` | 在 verify 相同的前提下，draft 只改变协调成本，不改变 verify 主导的输出分布 | 同一 prompt、tokenizer、verify、seed、采样策略和输出上限；single 对 draft-verify | `quality_rate`、`format_rate`、`distribution_agreement`、`acceptance_rate` | 完整 verify 概率下分布或 holdout 质量发生偏离，或 draft 没有暴露可独立观测的 verifier 错误 |
| `ASYM-02` | 角色拆分只有在接受 token 的收益抵消 draft 和往返成本时才值得 | 同一 verify；固定 `gamma`；记录每轮 draft/verify 时间、RTT 和回退原因 | `tokens_per_round`、`acceptance_rate`、`latency_p95_ms`、`fallback_rate`、`quality_rate` | `tokens_per_round <= 1.5`，或 `RTT >= tokens_per_round / local_tok_per_second`，或 holdout 质量回退 |
| `ASYM-03` | 亚 1B 专项化只有在契约通过且资源下降时成立 | 每个模型与 QW1.8B 在同一链路、模板或探针 fixture 上对照 | `contract_pass_rate`、`latency_p95_ms`、`rss_peak_bytes`、`format_rate`、`unsupported_architecture_rate` | 没有资源收益，或契约失败率超过 host fallback 预算 |

这些假设是可执行的停止规则，不是收益承诺。真实验证必须补齐模型画像/工件 digest、holdout、资源采样和逐轮计时；报告本身是 `fixture-only`，不加载权重、不联网。

## 3. 证据和边界

- DeepSeek 公开资料仅用于架构和缓存机制参考：[Context Caching](https://api-docs.deepseek.com/guides/kv_cache)、[V4.1-Flash 发布说明](https://api-docs.deepseek.com/news/news260910)。
- QLH 已有的 `speculative.py` 单测证明采样核心的分布等价性质和 `tokens_per_round` 等统计口径；实验端点默认关闭，未接入生产解码循环。
- `Qwen2.5-0.5B`、`Qwen3-0.6B`、`MiniCPM4-0.5B` 的岗位来自亚 1B 专项计划；MiniCPM4 还必须服从架构/模板/资源兼容门。
- DS3 的已有 v2 结果是判题候选证据，不能替代新的 draft-verify 配对实验，也不能直接恢复客观正确率门。

机器可读契约由 `harness_workbench.research.role_asymmetry` 生成。离线检查：


## 4. 票据结论

`CACHE-05` 完成“统一论证 + 可验证假设 + 机器可读证据契约”，不改变生产路由、不启用 speculative decoding。下一票为 `CACHE-06`：模型名与预设口径更新。
