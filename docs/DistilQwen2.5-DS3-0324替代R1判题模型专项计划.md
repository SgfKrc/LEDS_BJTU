# DistilQwen2.5-DS3-0324 替代 R1 判题模型专项计划（快思考替代不可关闭 thinking）

> 状态：**D1 本机开发门完成；D2/D3 待后续票**；意图 = 用 `alibaba-pai/DistilQwen2.5-DS3-0324-7B`（DeepSeek-V3-0324 蒸馏的"快思考"模型）**替代 DeepSeek-R1-Distill-Qwen-7B**，解决其"无法可靠关闭 thinking、输出预算耗尽在 `<think>`"导致无法判题的问题。**不是**替换已采纳的 Qwen3-4B 路线，而是填补"要有推理能力又要能判题"的 R1 遗留场景
>
> 创建日期：2026-09-08
> 适用范围：判题/答案生成场景的候选模型替换实验；不覆盖量化算法研究、多模态、文档工具子项目。与 [Qwen3.5与Qwen3-VL小模型支持计划](Qwen3.5与Qwen3-VL小模型支持计划.md)、[模型通用小工具调研与方案](模型通用小工具调研与方案.md)、[2bit与4bit量化调研与实施计划](2bit与4bit量化调研与实施计划.md) 的关系见 §7。

## 1. 背景与问题（R1 失败证据，项目内实测）

`DeepSeek-R1-Distill-Qwen-7B` 是本项目早期回答案判定基线（Q4_K_M GGUF 4.68GB，带 `.sha256`；safetensors 全模型亦登记）。实测结论（[Qwen3.5与Qwen3-VL小模型支持计划](Qwen3.5与Qwen3-VL小模型支持计划.md) §记录）：

- **三轮客观子集标定**：正确率 `0/4`、格式率 `2/11`（与 Qwen-1.8B 标定同档）；
- **根因**：R1 蒸馏模型**无法被当前路径可靠地关闭 thinking**，输出预算耗尽在 `<think>`，没有最终答案可按 rubric 检验；
- **已被证伪的补救**：再调 R1 参数不是出路（该计划已明确"首选替代不是再调 R1，而是官方 Qwen3-4B"）；
- **既有质量门不变**：LLM 侧仍用"非 R1 格式率 + 人工复核"临时规则；**不得因下载成功就恢复客观正确率门**。

现状：QW3-4B 路线已完成（`QW3-S0/D1a/D1b/QW3-G3` 等票关闭，判题口径 `normalized_contains` 存在地板效应，客观正确率门仍维持临时规则）。R1 场景（希望模型"有推理能力且输出可判"）目前**无合格替代**——本计划尝试新候选。

## 2. 目标与不做什么

### 目标
用 `DistilQwen2.5-DS3-0324-7B` 验证："快思考"（短 CoT）风格是否能在**固定输出预算内收敛到最终答案**，从而在三轮标定中显著改善格式率/可判性，**成为替代 R1 的判题/回答模型**（候选进质量门，不直接进生产）。

### 不做什么（边界）
- 不更换判题口径（`normalized_contains` 地板效应问题依然存在；换模型 ≠ 换口径，口径变更需独立重标）；
- 不在模型卡/报告分数基础上提前宣布替代——按项目惯例"**真实下载 + 三轮标定 + 人工复核**"才能进质量门；
- 不做量化研究（2bit/4bit 是另一条线）、不做多模态、不改 tool gateway / WEB-TOOL 支线；
- 不卸载或废弃现有 R1 工件（保留历史失败证据），替换仅发生在"判题/回答模型"引用点。

## 3. 调研结论（候选模型）

来源：HuggingFace `alibaba-pai/DistilQwen2.5-DS3-0324-7B` 模型卡 + EasyDistill 公开发布材料（2025，阿里云 PAI）。

| 项 | 结论 |
|---|---|
| 身份 | 系列 `3B/7B/14B/32B` 中的 **7B**，base 为 **Qwen2.5-7B**（`qwen2` 架构，项目已有加载路径） |
| 教师 | **DeepSeek-V3-0324**（不是 R1）；训练 = 长转短 CoT 收集 + CoT 认知对齐（QwQ-32B Judge 统一轨迹难度），合成"快思考"数据 SFT |
| 效率卖点 | 输出 token 比慢思考系列**少 60-80%**（32B 上 MMLU_PRO 平均 4198→690）；这是"解决 R1 预算爆炸"的机制性理由 |
| 报告分数 | AIME2024 43.33 / MATH-500 88.4 / GPQA-D 42.93 / LiveCodeBench V2 46.38（7B 卡值；R1-Distill-Qwen-7B 官方为 AIME2024 ~55.5 / MATH-500 ~92.8——**报告分数更低**，赢在 token 效率与可判性，不是绝对能力） |
| 许可证 | Apache-2.0（比 R1 的 MIT 更宽松，无"蒸馏需同意"类限制） |
| 工件 | 官方仓库为 **safetensors（约 8B 参数，F32）**；无官方 GGUF（llama.cpp 转换链路可用，含近期 Qwen `layer_norm_epsilon` 兼容补丁） |
| 运行要求 | transformers ≥ 4.37（项目主运行时 4.47.x、Qwen3 sidecar 4.57.6 均满足） |
| 关键未知 | **chat template 是否支持 `enable_thinking=False`？思考是否带 `<think>` 标签？** 模型卡未承诺硬开关；"快思考"可能以普通文本 CoT 形式输出——**必须实测，禁止推断** |

## 4. 与 R1 的对比（替代可行性预判）

| 维度 | R1-Distill-Qwen-7B | DS3-0324-7B | 本项目判读 |
|---|---|---|---|
| 底座/模板 | Qwen2.5-7B | Qwen2.5-7B | 无新架构成本 |
| 思考模式 | 慢思考，**无可靠关闭开关**（已证） | 快思考（短 CoT），开关状态**未知** | 核心待验证点（D1） |
| token 效率 | 差（预算耗尽） | 好（-60~80%） | 与"预算内收敛"目标直接相关 |
| 推理分数 | 更高 | 略低 | 判题场景先看格式率/可判性，再看正确率 |
| 许可证 | MIT | Apache-2.0 | DS3 更友好 |
| 集成成本 | 已有 GGUF/模板路径 | 需下载 + 转换/量化 | 与既有 ModelScope/HF 下载 + model_tools 链路一致 |

**结论（预判，待实测推翻）**：DS3-0324-7B 最可能的价值是"**短思考可判**"——若三轮标定格式率显著高于 R1 的 2/11（对齐 QW3-4B 的 4/11 甚至更好），且在预算内产出可判答案，则替代成立；若模板仍产生超长不可控 CoT，则与 R1 同病，计划按 §6 判定门终止。

## 6. 判定门与风险

1. **判断标准（预定义，防"为替代而替代"）**：替代成立需要同时满足——① D1 确认存在可接受渲染方式（硬关闭或短 CoT 自然收敛）；② D2 三轮格式率 ≥ 4/11 且正答可被 rubric 检出；③ 人工复核无复现性疑点。任一不满足 → 维持现状（R1 保留为历史证据，回答模型继续用现有已准入门模型的组合）。
2. **最大风险（模板未知）**：DS3 系列训练目标是"快思考"而非"无思考"，模板可能**不可关闭**——这正是本计划第一验证点（D1 提前否决，成本最低）。
3. **正确率不升反降**：报告分数低于 R1（AIME 43.33 vs 55.5）。判题场景若"可判性"提升但"正确性"下降，按项目临时质量规则（人工复核 + 格式率）裁定；不以模型卡数字代替实测。
4. **体积/资源**：官方 F32 safetensors 约 8B 参数，CPU 资源门参考 QW3 实证（fp16 全模型双路径 fail-closed：GPU 9.95GB > 7.45GB、CPU 19.4GB > 10.4GB）；**D1 必须落地可加载档位**（Q4_K_M GGUF 或 bnb 4bit），不能只下载 F32 就宣称可部署。
5. **判题口径地板效应依然存在**：`normalized_contains` 对推理风格输出不匹配的问题不会因换模型消失；本计划只评估"换模型能否在预算内给出可判答案"，口径变更另行重标（不得搭车）。
6. **范围边界**：不做 3B/14B/32B 扫描（先 7B 验证机制）；不做 DS3 与 R1 的混合路由；不做 docagent/harness 子项目相关改动。

### 6.1 首轮标定登记（2026-09-09，工件就绪后）

**执行**：DS3-0324-7B Q4_K_M（SHA `8f6ffc43…`，架构 `qwen2`、ctx 32768、模板探测：**无 `<think>` 标记、无 enable_thinking 开关**，stop `<|im_end|>` 151645）；固定采样 0.7/0.8/20/0、`max_new_tokens=192`、`n_ctx=4096`、`ps-v1` 客观子集 15 题（correctness 4 + format 11），三轮串行（~245s/轮，CPU 6 tok/s）。证据 `build/experiments/ds3-e4-round{1,2,3}.json`。

| 指标 | DS3-0324-7B | R1（历史） | Qwen3-4B（QW3-E4） | Qwen-1.8B |
|---|---|---|---|---|
| correctness（4 题） | **0/4 ×3** | 0/4 | 0/4（v1）/ **1/4（v2）** | 0/4 |
| format（11 题） | **5/11 ×3** | 2/11 | 4/11 | 4/11 |

**口径混搭说明（重要，勿直接归因模型）**：本轮 rubric 判据取自 `llm-objective-ps-v1-v2.json`（**已含 P5 的 `loose_contains`**），但**生成预算仍用 192 token**（复刻 QW3-E4 的 v1 预算）。P5 已证明 v2 口径需 **512 token 预算**才可区分（Qwen3-4B 1/4 vs 1.8B 0/4）。因此：

- **本轮 0/4 不能作为"DS3 能力不足"的证据**——符合"判题口径问题"假设：极可能是 192 预算截断（v2 判据 + v1 预算混搭）；
- **format 5/11 ×3 有效且可比**（format 判据在 v1/v2 均保持 192 口径）：显著优于 R1（2/11）与 Qwen3-4B（4/11），**"可判性"改进成立**；
- **结论状态**：判定门条件①（可接受渲染方式：无 think 脚手架）与②前半（格式率 ≥4/11 且三轮稳定）满足；correctness 项**待 v2 全口径（loose + 512 token）重标后**再判；维持 **candidate，不进 production，不恢复客观正确率门**。

### 6.1.1 v2 全口径重标结果（2026-09-09，结论性）

**执行**：与 §6.1 完全相同的命令/rubric/set，**仅 `max_new_tokens` 192 → 512**（P5 口径）；三轮串行（~350s/轮）。证据 `build/experiments/ds3-e4-v2-round{1,2,3}.json`。

| 指标 | DS3 v2（512） | DS3 混搭（192） | Qwen3-4B v2（P5 基线） | R1 |
|---|---|---|---|---|
| correctness（4 题） | **2/4 ×3** | 0/4 | 1/4 | 0/4 |
| format（11 题） | **8/11 ×3** | 5/11 | 4/11（v1/192） | 2/11 |

**结论（判定门触发，替代成立）**：
1. **口径问题被实证**：同一模型同一 rubric，仅预算 192→512 即 0/4→**2/4**、5/11→**8/11**——与 §6.2"多模型 0/4 是判题口径问题而非模型问题"的判断完全一致；
2. **2/4 > 1/4**（Qwen3-4B v2 可区分基线，P5）→ 判定门②（正答可被 rubric 检出）**满足**；①（无 think 脚手架，模板探测已证）满足；格式率 8/11 为当前全部候选最高 → **DS3-0324-7B 替代 R1 判题模型成立**；
3. 状态升级：**candidate → 替代 R1 判题模型的已批准候选**（生产引用点切换需单独票 + 按 EX-N3 增加人工复核样本）；客观正确率门**仍不恢复**（口径规则修订需独立重标流程）；
4. 未决：人工复核（quality_unit 设计不落输出，需单独采样复核 math 题）登记为后置小票，不阻塞替代结论。

### 6.2 判题口径问题专项分析（多模型一致性 0/4 的归因）

**现象**：换过 Qwen-1.8B、R1-7B、Qwen3-4B、DS3-0324-7B 四个模型，correctness 三轮几乎都是 0/4（唯一例外：P5 重标后 Qwen3-4B v2 口径的 1/4）。

| 模型 | 判据 | 预算 | correctness |
|---|---|---|---|
| Qwen-1.8B | normalized_contains（v1） | 192 | 0/4 |
| R1-Distill-7B | normalized_contains（v1） | 192 | 0/4（且 `<think>` 占预算） |
| Qwen3-4B | normalized_contains（v1） | 192 | 0/4（人工复核：完整推理但 192 内未收敛到精确串 `13:54`） |
| Qwen3-4B | loose_contains（v2，P5） | **512** | **1/4** |
| DS3-0324-7B | loose_contains（v2 判据）+ 192 预算（**混搭**） | 192 | 0/4（本轮） |

**结论（观点正式化）**：多模型一致 0/4 是**判题口径问题**而非模型问题——v1 时代由 ① `normalized_contains` 精确串对推理风格输出不匹配 ② 192 token 预算截断 双重叠加造成；P5（`loose_contains` + 512 token）已在 Qwen3-4B 上证明可区分（1/4 vs 0/4），**口径可修，模型并非全不行**；本轮 DS3 混搭结果进一步支持该判断。

**下一步**：① 按 P5 完整 v2 口径（`loose_contains` + 512 token）对 DS3 重跑三轮（需建 DS3 专属 Qwen2.5 渲染集——v2 rubric 绑定的 `ps-qwen3-nothink` 含 `<think>` 脚手架不可复用）；② v2 下 DS3 ≥ 1/4 则"可判性 + 能力"两项齐备，替代 R1 成立；③ 口径规则修订按 EX-N3 流程独立登记，不搭车本计划。
