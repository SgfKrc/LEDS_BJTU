**结论：否认决结论（"不推荐开工"）上调为"可研究，前置成本显著下降"；但未升级为主线，且 §3.1 的根本障碍未被解除。**

## 7. PoC 实测结果（2026-09-16，本机）

> 实验落点 `build/cross-framework-layer-poc/`（**已被 `.gitignore` 覆盖**）。以下为**实测**，命令见 §7.5 可复跑。

### 7.1 环境与对象

| 项 | 值 |
| --- | --- |
| 上游代码 | PR #27073 分支，commit **`6f04274cc`**；MinGW CPU 构建（`-DGGML_CUDA=OFF`），仅需 `cmake` + `mingw32-make` + `gcc`（**MSVC 缺失亦可**） |
| 工具 | `llama-hs-extract-batch.exe --raw --mean --ctx-size 512 --batch-size 1 -ngl 0` |
| 模型 | **`qwen35-2b`**（架构 `qwen3_5`，24 层，hidden 2048）—— **PR 原生支持列表内** |
| HF 侧 | **独立 venv**（`python -m venv --system-site-packages`，仅升级 `transformers` → 5.17.0；torch 沿用系统 2.13.0+cu126），fp32，`attn_implementation="eager"` |
| prompts | 3 条短句（3–5 token） |
| 抽样层 | 0, 12, 20, 21, 22, 23 |

### 7.2 关键结果：未量化路径**逐层精确一致**

| 精度 | 抽样层 | cosine（token-mean） | 两侧范数比 |
| --- | --- | --- | --- |
| **fp16（未量化）** | **0, 12, 20, 21, 22** | **1.000000**（全部） | **1.000** |
| Q4_K_M | 0, 12 | 0.9920 / 0.9927 / 0.9916 / 0.9908 / 0.9857 | ≈1.00 |

**结论一（本方向的核心答案）**：`layer 0–22` 在 fp16 下 `cosine = 1.000000` 且**范数一致到小数点后三位** —— 两侧对"层输出"的定义、token 聚合方式、数值尺度**完全一致**。**§3.2 步骤 2 判据（未量化 ≥ 0.999）PASS。**

**结论二**：Q4_K_M 引入 **0.7–1.4% 偏差**（0.986–0.993），即量化代价 —— 对应 §3.2 步骤 3。**跨框架接力的量化预算由此有了第一个实测量。**

### 7.3 末层（layer 23）异常：**已定位，未完全解释**

| 观测 | 值 |
| --- | --- |
| llama 侧 l23 范数 | 28.748（延续 l22=23.367 的平滑增长 → 正常） |
| torch 侧 `hs[24]` 范数 | **125.145**（自 `hs[23]=23.367` 跳变 5.4×） |
| `hs[23]` vs `hs[24]` | cosine **0.321** / ratio **5.356** |
| **`norm(hs[23])` vs `hs[24]`** | cosine **0.476** / ratio **1.457** → **不匹配** |

**已定位并解释**（读源码 + 实测双向确认）：

- **实测**：`hs[24]` 与 `base.last_hidden_state`、`base.hidden_states[-1]` 的 cosine = **1.000000**、范数比 **1.0000** → **`hs[24]` 就是文本模型输出的 `last_hidden_state`**。
- **源码**（`transformers/models/qwen3_5/modeling_qwen3_5.py:1288-1307`）：

```python
        hidden_states = inputs_embeds
        for i, decoder_layer in enumerate(self.layers[: self.config.num_hidden_layers]):
            hidden_states = decoder_layer(hidden_states, ...)
        hidden_states = self.norm(hidden_states)      # final RMSNorm
        return Qwen3_5ModelOutputWithPast(last_hidden_state=hidden_states, ...)
```

**结论：两侧差的不是"语义"，而是 final RMSNorm 做在哪一侧。**

- **llama.cpp**：`t_hidden_layers.push_back(cur)` 位于**层循环内部** → 得到**未 norm 的层输出**（28.748）；
- **HF**：`last_hidden_state` 只在 `self.norm(...)` **之后**暴露 → 给出 **norm 后**的值（125.145）。

量级吻合：`125.145 / 28.748 = 4.35`，即该 final norm 权重对输出的放大倍数。

**一处已纠正的误判（诚实记录）**：本文早期版本据 `norm(hs[23])` 与 `hs[24]` 的 cosine 0.476，判断"不是 final RMSNorm"。**该对照选错了输入** —— `hs[23]` 是**第 23 层**输出，而 `hs[24]` 是**第 24 层**输出再 norm，本非同一层。结论现已由源码确证。

**可操作规避**：跨界传 **`0 .. n_layers-2`**；若必须用最后一层，需在 llama 侧补 final norm，或让 HF 侧暴露 norm 前的值（当前未暴露）。

### 7.3.1 这**不**意味着什么（重要）

本 PoC 验证的是**跨框架 hidden 的数值一致性** —— "两侧对同一层输出是否算同一个量"。**这是层间拆分的必要条件，不是充分条件。**

**已确立**：hidden 语义一致（fp16 逐层 cosine = 1.000000）；量化代价已有实测（Q4_K_M 0.7–1.4%）。

**仍未验证（因此不能据本 PoC 宣布"llama 层间拆分推理流水线可行"）**：

1. ~~**反向能力（注入）**~~ → **已验证可行（2026-09-16，见 §7.8）**：`llama_batch.embd` **接受任意 `n_embd` 向量**（头文件仅要求"float vector of size n_embd"，**不校验来源**）。实测把 5×2048 的**随机噪声**注入 `qwen35-2b`，`llama_decode` 返回 **0**、logits 非零 → **前向正常完成**。**故"把外部 hidden 写回并续算"在接口层面成立。** 新增的剩余缺口见 §7.8 第 ③ 项。
2. **跨节点传输开销** —— decode 每跳 hidden 约 4KB/token（估算），**每步同步的实际延迟未测**；
3. **调度与图重建** —— `llama-context.cpp:1241` 注释已提示"t_hidden_layers output tensors → the scheduler must re-reserve compute"，**多节点下的实际代价未测**；
4. **误差累积** —— Q4_K_M 的 0.7–1.4% 偏差在**多层多跳**下是否放大，未测；
5. **异构算力** —— 两端性能不对称（§7.1 与硬件评估）对流水线吞吐的影响未测。

**已可排除的**：该方向**不存在"两侧算的不是同一个量"这一根本性障碍** —— 这曾是本方向最硬的技术疑问。

- **层间拆分流水线的 4 项未验证**（传输开销 / 调度重建 / 误差累积 / 异构算力）—— 见 §7.3.1；**反向注入已由 §7.8 验证**。

### 7.8 注入实验：`llama_batch.embd` 接受任意向量（2026-09-16）

**动机**：§7.3.1 判定"能否把外部 hidden 写回续算"是层间接力的关键未知 —— PR #27073 只提供**读取**。

**查证**（`include/llama.h`）：`embd` 的注释只要求 "float vector of size n_embd"（`:245`），**不校验来源**；且 `llama_model_n_embd_inp`（`:582`）与 `n_embd_out`（`:583`）**分离**，说明框架允许**输入维 ≠ 输出维**。另：llama.cpp **无**跳层选项（`--start-layer` / `n_layer_skip` 均 grep 无命中）。

**实验**：自建 `llama-embd-inject-test`（`build/cross-framework-layer-poc/llama.cpp/tools/hs-extract-batch/embd-inject-test.cpp`，**gitignored 不入库**），把 **5×2048 随机噪声**（`np.random.default_rng(0).standard_normal * 0.02`，**非 token embedding**）放入 `llama_batch.embd`（不设 token），对 `qwen35-2b` 跑 `llama_decode`：

```
[4/6] n_embd_inp=2048  n_embd_out=2048
[6c] inject 向量已写入 batch.embd，准备 decode
[decode] rc=0
[logits] 末 token 前 10 项 |和| = 57.936595
PASS: embd 通道接受了注入向量，前向正常完成
```

**结论**：**注入接口存在且有效** —— 任意向量都能作为层输入进入前向，**"把外部 hidden 写回续算"在接口层面成立**。

**踩坑记录**：`llama_batch_init(n_tokens, embd≠0, ...)` 时 **`batch.token` 为 NULL**（token 与 embd **互斥**）。照抄 token 路径写 `batch.token[i]` 会**解引用空指针**（本次先遭段错误，再由 `[6b] batch.embd ptr=... batch.token ptr=0x0` 定位）。

**对"层间拆分流水线"的更新判断**：

| 环节 | 状态 |
| --- | --- |
| ① 跨框架 hidden 语义一致 | ✅ 已证（§7.2） |
| ② 注入任意向量 | ✅ **已证**（本节） |
| ③ **模型从第 k 层开始** | ✅ **已证（裁 GGUF 路径，见 §7.9）** |
| ④ 传输 / 同步 / 误差累积 / 异构算力 | ❌ 未测 |

**即：① ② ③ 三项已在接口与模型形态层面成立；剩余为工程集成（跨节点传输 / 调度）与性能类未测项。**

### 7.9 裁层实验：剪掉前 4 层后仍能加载并注入（2026-09-16）

**动机**：§7.8 表格第 ③ 项 —— "让模型从第 k 层开始"。llama.cpp 无跳层选项，故 B 侧只能靠裁 GGUF。

**做法**（`build/cross-framework-layer-poc/cut_layers.py`，gitignored 不入库）：读入 `qwen35-2b-f16.gguf`（`block_count=25`、335 张量），保留 `blk.4..blk.24` 并重命名为 `blk.0..blk.20`，非 blk 张量（`token_embd` / `output_norm` / `output`）原样保留，KV 全量复制、仅改 `qwen35.block_count: 25 → 21`；产出 282 张量、41 个 KV。

**判据与结果**（`llama-embd-inject-test`，5×2048 随机噪声注入）：

```
llama_model_loader: loaded meta data with 42 key-value pairs and 282 tensors ...
print_info: n_embd_inp            = 2048
print_info: n_layer               = 20      n_layer_all           = 21
[6c] inject 向量已写入 batch.embd，准备 decode
[decode] rc=0
[logits] 末 token 前 10 项 |和| = 60.003920
PASS: embd 通道接受了注入向量，前向正常完成
```

**结论**：**③ 项成立** —— 裁层 GGUF 被 llama.cpp 当作"层数更少的模型"正常加载与前向，注入通道依旧可用。**① ② ③ 三项已在接口与模型形态层面闭环。**

**三条限制（先讲清）**：

1. **层号映射**：裁层后 llama.cpp 报 `n_layer=20 / n_layer_all=21` —— 它把最后一个 block 视作 MTP 层（`nextn_predict_layers=1` 被原样保留）。故裁层模型 `layer i` ↔ 原模型 `layer i+4`，跨节点传 hidden 时**必须带偏移**。
2. **状态起点**：裁层模型的 KV cache / recurrent state（qwen35 为混合 SSM+attention）**从裁剪边界起算**，A 侧历史状态不在 B 侧。单请求逐层接力不受影响（每步位置一致），但"两端各自缓存"的形态需另行设计。
3. **tokenizer 全量保留**：与"换模型"不同，裁层仍带 24.8 万 token 词表 —— 这不是优化，只是满足加载。

**踩坑（gguf-py 写入）**：

- `GGUFWriter.add_array()` **只有 2 个参数**（无子类型）；数组 KV 须走 `add_key_value(name, val, ARRAY, sub_type)`；
- 必须**跳过 `GGUF.version` / `GGUF.tensor_count` / `GGUF.kv_count`**（reader 会把这三个头部字段也列进 `fields`），否则写出重复字段 → `KeyError: Duplicate GGUF.version already in list`；
- 运行实验二进制时要把 **ucrt64 置于 PATH 最前** —— `/mingw64/bin` 在前的 DLL 会让进程直接 `exit 127` 且**无任何输出**，极易误判成"命令不存在"。

**④ 类四项仍未测**（传输/同步开销、调度与图重建、误差累积、异构算力），见 §7.3.1 与 §7.7。
