# StudyPact 风格分析与 `frontend_cybergothic` 前端计划

## 1. 文档目的

本文记录对 [StudyPact](https://studypact.cn/) 首页的视觉与交互观察，并结合本地参考项目 `G:\C\VUE\cmys-fight\website\src\world`，形成 `frontend_cybergothic` 的落地方案。

目标不是复刻 StudyPact，而是提取它的高识别度视觉语法，再压低“极客终端感”、霓虹噪声和文案门槛，做成适合长期使用的简洁赛博哥特前端。

### 1.1 观察范围

- StudyPact 首页 `/`。
- StudyPact 的 `/download`、`/terms`、`/privacy` 路由结构与下载弹窗入口。
- 首页 CSS 与打包脚本中可见的配色、字体、布局、Framer Motion 动画和交互逻辑。
- `cmys-fight` 的 `WorldApp.tsx`、`world.css`、`PaperCanvas.tsx`、`AnomalyCanvas.tsx`、`assets.ts`。

页面观察以 2026-08-20 抓取结果为准；线上内容、下载地址和文案后续可能变化，实施时应再次确认。

## 2. StudyPact 页面风格总结

### 2.1 总体气质

StudyPact 是“运动品牌式的赛博朋克产品页”：黑色背景承载大字号口号，荧光色承担状态和行动提示，倾斜、硬阴影与粗边框制造速度感。它不是纯粹的终端 UI，也不是传统企业 SaaS，而是把自律、契约和奖励包装成一场带有竞技感的行动。

主要关键词：

- 高对比、强节奏、低圆角。
- 粗体斜体标题 + 小号等宽标签。
- 黑底上使用绿色、蓝色、橙色、红色作为功能色。
- 画面有颗粒、斜线和局部光晕，但主体仍由文字和结构块组成。
- 每个区块像海报或运动装备广告，而不是信息密度很高的控制台。

### 2.2 页面结构

1. **固定顶栏**：左侧品牌标记，右侧锚点导航和 `LOGIN` 行动按钮；桌面显示更多导航，窄屏隐藏次要链接。
2. **Hero 首屏**：全视口高度，左侧大标题和主 CTA，右侧为带 3D 倾斜和浮动状态标签的产品视觉。
3. **Features**：三列功能块，分别表达契约、观察、排名；卡片使用 4px 白色边框和同色硬阴影。
4. **Community**：整块绿色背景，以大数字、统计指标和评论日志表达群体参与感。
5. **Rewards**：黑底奖励区，左侧奖励说明，右侧旋转的物品卡片和虚线环。
6. **Footer**：品牌、条款、隐私和联系入口。
7. **辅助路由**：下载页以平台、系统要求、文件大小和二维码为主；条款和隐私页为黑底白字的长文档布局。

页面使用 `100dvh` 分屏与 `snap-y snap-mandatory`，滚动时有整屏章节感；同时保留普通文档页的自然滚动能力。

### 2.3 用色

| 角色 | StudyPact 观察值 | 设计含义 |
| --- | --- | --- |
| 主背景 | `#000`，局部 `#050505` / `#080808` | 舞台、压低视觉噪声 |
| 主文字 | `#fff` | 标题、关键数据、主要按钮 |
| 次级文字 | `rgba(255,255,255,.4-.7)`、`#afafaf` | 说明、标签、辅助信息 |
| 绿色 | `#58cc02` | 主行动、正向状态、社区区块 |
| 蓝色 | `#1cb0f6` | 功能、下载、信息状态 |
| 橙色 | `#ff9600` | 奖励、强调、悬浮光晕 |
| 红色 | `#ff4b4b` | 风险、稀有奖励、重点警示 |

常见表现形式是纯色块、半透明叠层、`8px 8px 0` 或 `15px 15px 0` 的偏移硬阴影。渐变只用于背景光带或多色 CTA，不作为所有组件的默认表面。

### 2.4 字体与排版

- 正文：`Space Grotesk`，中文需要用项目内可用的无衬线回退字体。
- 标签和数据：`JetBrains Mono`，常见 `uppercase`、小字号、较大字距。
- 展示标题：`Syne`，粗、斜、紧缩字距，字号最高可到 `clamp(2.5rem, 10vw, 7rem)`。
- 标题使用全大写英文或短中文句，避免长段落占据首屏。
- 说明文案以左侧 4px 彩色竖线、斜体和较短行宽增强节奏。
- 数字采用超大字号、斜体和等宽/数字字体，作为视觉锚点。

### 2.5 线条、形状和材质

- 4px 白色外框是重要卡片的结构线；次级分隔线多为 `1px` 半透明白线。
- 按钮、标签和装饰块大量使用 `skewX`，形成轻微平行四边形。
- 背景有 `diagonal-bg` 重复斜线和 `grain` 噪点纹理；纹理透明度较低，只用于增加材质。
- 部分标题使用文字描边（`-webkit-text-stroke`）或黑色偏移阴影。
- 少量模糊光晕跟随鼠标移动，强化空间感；不应遮盖文本和可操作控件。
- 圆角主要用于头像、奖励徽章等语义明确的元素，主卡片不依赖大圆角。

### 2.6 动画与过渡

- 首屏标题从左侧带 `skewX` 弹簧进入，副标题延迟淡入并横向移动。
- 绿色高亮条在标题下方从 0 宽度展开。
- Hero 右侧视觉根据鼠标坐标做 `rotateX/rotateY` 视差。
- `SYNCED`、积分等状态标签以不同周期上下轻微浮动。
- 功能卡片进入时上移并淡入，悬停时上移约 10px、轻微旋转。
- 社区统计使用进入视口后数字递增；评论日志从侧面淡入。
- 奖励卡片使用旋转、缩放和弹簧过渡，内部虚线环持续慢速旋转。
- 背景斜向光带长周期移动；粒子和噪点为低强度环境动效。
- 交互反馈统一使用 `150-300ms` 的颜色、位移和阴影过渡，避免所有元素同时抖动。

### 2.7 交互方式

- 顶栏锚点跳转到 `#features`、`#community`、`#rewards`。
- `LOGIN`、主 CTA 和下载按钮进入下载/登录流程；下载页提供 App Store、Android APK、二维码和系统要求。
- 卡片悬停显示结构变化，而不是弹出大量说明。
- 鼠标只影响装饰性视差，不能改变按钮点击区域和阅读顺序。
- 移动端隐藏次要导航，主 CTA 保留，功能卡片从三列变为单列。
- `prefers-reduced-motion: reduce` 时关闭视差、循环动画、弹簧和复杂背景动效。

## 3. `cmys-fight` 参考项目提炼

### 3.1 可复用的架构思路

- `WorldApp.tsx` 将页面拆成导航、Hero、数据条、世界选择、角色、章节、系统、操作表、资产位、CTA、页脚，信息层级清晰。
- `useReveal` 使用 `IntersectionObserver` 为 `.w-reveal` 统一处理滚动显现，避免每个区块重复写监听逻辑。
- `assets.ts` 用 `SLOTS` 和 `SLOT_HINT` 约定静态资源路径，缺图时由组件回退到程序化占位。
- Canvas 组件使用 `ResizeObserver`、DPR 缩放和 `IntersectionObserver`，离开视口时暂停 `requestAnimationFrame`。
- CSS 使用变量切换主题；同一结构可以在不同世界中替换背景、文字、强调色和边框色。

### 3.2 可复用的视觉交互

- Hero 通过两层 `clip-path: polygon(...)` 形成斜向分屏，中心 seam 随鼠标和状态变化。
- `PaperCanvas` 用光丝、漂浮碎片和闪光点表现“纸化”世界；`AnomalyCanvas` 用建筑、霓虹、雨线、粒子和故障带表现异常世界。
- 角色卡悬停时由实体视觉翻转为二维纸片，结合折痕闪光，反馈明确且有记忆点。
- 章节卡采用左右交替媒体/文字布局，悬停时整体横向位移，保持阅读方向稳定。
- 移动端关闭两侧信息栏、将章节改为单列，并降低分屏斜角，响应式策略明确。

### 3.3 不直接照搬的部分

- 双世界分屏、故障文字和大量霓虹色适合世界观展示，不适合作为所有业务页面的默认状态。
- Canvas 粒子和循环动画应只放在 Hero 或特殊空状态，不能让列表页持续消耗 GPU。
- 角色卡翻面属于展示型交互；业务卡片优先保证点击、键盘和触屏可用。

## 4. 综合设计方向：克制赛博哥特

### 4.1 设计原则

1. **先可读，再有风格**：主流程使用清晰中文，英文仅作为短标签或状态编号。
2. **单一主强调色**：每个页面只选一个主色，其他荧光色只表达状态，避免“彩色控制台”感。
3. **硬朗但不嘈杂**：保留细线、切角和偏移阴影；降低故障、颗粒、发光和重复斜线的透明度。
4. **真实层级而非装饰堆叠**：不把每个区块包装成浮动卡片，页面区域使用整宽色带，卡片只承载可比较的重复内容。
5. **动效解释状态**：进入、切换、完成和异常有动效；静态内容不做无意义循环。
6. **非极客文案**：不使用 `MECH_SYS`、`PROTO_X` 等连续内部代号作为主要导航；保留少量小号英文作为品牌气质。

### 4.2 建议主题令牌

```css
:root {
  --bg: #0b0b0d;
  --surface: #141419;
  --surface-raised: #1b1b22;
  --line: rgba(255, 255, 255, 0.16);
  --text: #f4f2ed;
  --muted: #9c9aa2;
  --accent: #c7ff3d;       /* 主行动色，后续可按品牌替换 */
  --accent-soft: rgba(199, 255, 61, 0.14);
  --info: #76c7ff;
  --danger: #ff6b76;
  --shadow-hard: 8px 8px 0 #050505;
  --radius-sm: 2px;
  --content-max: 1180px;
}
```

推荐默认使用暖白文字配黑灰表面，避免整页纯黑导致层级消失。`--accent` 为唯一主色；`--info` 和 `--danger` 仅用于信息/错误状态。

### 4.3 页面信息架构

首期建议实现一个可工作的单页应用，保留后续路由扩展能力：

- `Overview`：首屏价值说明、关键指标、最近活动和主行动。
- `Tasks`：任务/模型/工作流列表，支持筛选、状态、分页或虚拟滚动。
- `Activity`：时间线、事件详情、运行进度和错误提示。
- `Settings`：连接、主题、通知和动效偏好。
- `Help`：简短的使用说明、资源链接和版本信息。

如果后端接口尚未稳定，先用本地 fixture 驱动相同的数据形状，禁止把演示数据散落在组件内部。

### 4.4 首屏布局建议

- 顶栏高度控制在 `56-64px`，左侧品牌/页面名，右侧主操作、主题和用户入口。
- Hero 不使用全屏营销口号，改为“当前状态 + 一项主行动 + 关键数字”三段式。
- 右侧可采用 `cmys-fight` 的轻量 Canvas 或静态程序化图形，但默认关闭高成本粒子。
- 首屏底部露出下一段的标题或列表边缘，提示仍可继续滚动。
- 桌面为 5:7 或 6:6 的双列；移动端改为单列，操作区置于说明之后。

## 5. `frontend_cybergothic` 实施计划

### 5.1 技术边界

- 建议沿用仓库已有前端的 React + TypeScript + Vite 体系，避免再引入第二套构建方式。
- 动效优先使用 CSS Transition/Keyframes；只有复杂时间线、弹簧或数字动画才引入现有动效库。
- 图标使用项目已有图标库；按钮内使用图标 + 短文本，不手写装饰性 SVG。
- 数据访问、状态管理、页面壳和视觉组件分层，后端 API 变化不应迫使 CSS 组件重写。

### 5.3 组件与状态规范

- `AppShell` 统一背景、顶栏、内容最大宽度和移动端安全区。
- `Topbar` 管理页面导航、全局主操作和动效开关；当前路由必须有清晰选中态。
- `MetricStrip` 只显示 3-4 个关键指标，数字进入视口后递增一次。
- `TaskTable` 支持加载、空数据、错误、成功和批量操作状态；表头固定，移动端转为纵向条目。
- `StatusBadge` 使用颜色 + 文本，不依赖颜色单独传达状态。
- `EmptyState` 可使用低成本线条插画或静态 Canvas，占位文案保持直接。
- `AccentCanvas` 仅在首屏或空状态挂载，进入后台/离开视口即暂停。

### 5.4 动效规格

| 场景 | 动效 | 时长/规则 |
| --- | --- | --- |
| 页面进入 | 标题从左侧淡入，切角高亮条展开 | `450-600ms`，只播放一次 |
| 区块显现 | `translateY(18px)` + opacity | `500ms`，IntersectionObserver 触发 |
| 卡片悬停 | 上移 `2-4px`，边框变主色，硬阴影增加 | `180ms` |
| 主按钮 | 背景/阴影切换，轻微右移 | `160ms` |
| 数据刷新 | 数字递增或进度条增长 | 一次性，避免无限循环 |
| 状态变化 | 状态点短促闪烁或边框脉冲 | `800ms` 内完成 |
| 背景装饰 | 低速噪点/斜线/一条光带 | 仅 Hero，页面不可见时暂停 |

必须实现 `prefers-reduced-motion`：关闭视差、循环光带、颗粒、弹簧和卡片翻转，保留颜色和布局变化。

### 5.5 交互与可访问性

- 所有可点击卡片使用真实 `button` 或 `a`，不能只依赖 `div:hover`。
- 键盘焦点使用 2px 主色 outline；焦点样式不能被 `clip-path` 或阴影吞掉。
- 顶栏在移动端提供菜单按钮，菜单打开时锁定背景滚动并支持 `Escape` 关闭。
- 表格、时间线和状态标签提供语义化标题、`aria-live` 更新区和错误描述。
- 对比度以 WCAG AA 为基线；荧光色用于背景时必须检查白/黑文字的对比度。
- Canvas 必须是装饰层（`aria-hidden`），核心信息不能只画在 Canvas 中。
- 触屏不依赖 hover；卡片详情通过点击或明确的展开按钮触发。

## 6. 性能与工程约束

- 首屏优先加载结构和文字，装饰图片、Canvas 和非关键图标延后加载。
- Canvas 使用 `ResizeObserver` 处理尺寸，DPR 最大限制为 2；不可见时取消 `requestAnimationFrame`。
- 动画只改变 `transform`、`opacity`、必要时 `filter`，避免对大面积元素持续修改布局属性。
- 列表超过 100 条时评估虚拟滚动；筛选和排序放在数据层，避免每行重复计算。
- 纹理、渐变和阴影要控制层数，移动端减少模糊半径和粒子数量。
- 静态资源使用明确的尺寸和 `aspect-ratio`，避免首屏布局跳动。
- 运行 `build`、TypeScript 检查和基础 E2E；至少验证 1440px、1024px、768px、390px 四种宽度。

## 7. 分阶段排期

### Phase 0：基线确认

- 确认 `frontend_cybergothic` 的启动命令、API 基址、品牌名和主色。
- 盘点仓库已有图标、字体、组件和接口类型，避免重复造轮子。
- 输出页面状态矩阵：加载、空、错误、成功、无权限、离线。

### Phase 1：壳与设计令牌

- 初始化 Vite/React/TypeScript 入口。
- 完成 `tokens.css`、全局 reset、AppShell、Topbar、移动端导航。
- 建立浅层切角、细线、硬阴影、状态色和按钮组件。

### Phase 2：Overview 首屏

- 完成首屏主行动、指标条、最近活动和响应式布局。
- 加入一次性 reveal、数字递增和低成本 AccentCanvas。
- 接入真实或 fixture 数据，验证所有状态。

### Phase 3：任务与活动

- 完成任务列表、筛选、详情抽屉/页面、进度和错误反馈。
- 完成 Activity 时间线与事件详情。
- 统一键盘操作、焦点、Toast/Inline error 规则。

### Phase 4：设置、帮助与视觉收尾

- 完成设置、帮助、版本和资源链接页面。
- 根据真实内容调整中文字体、行高和小屏断点。
- 只保留能说明状态的动效，删除装饰性过载。

### Phase 5：验证与交付

- `npm run build`、类型检查、关键流程 E2E。
- 桌面/移动截图检查：无文字溢出、无按钮遮挡、无空白 Canvas。
- 检查 `prefers-reduced-motion`、键盘导航、对比度和离线/弱网表现。
- 在文档中记录启动命令、环境变量、API 契约和资产替换方式。

## 8. 验收标准

- 首屏在 1440px 与 390px 下均能看到品牌、当前状态、主行动和下一段入口。
- 页面视觉能识别出赛博哥特特征，但正文阅读不依赖英文术语或故障效果。
- 主色、状态色、边框、切角和阴影全部来自设计令牌，禁止组件内随意写色值。
- 所有加载、空、错误和成功状态有明确反馈，不能只显示空白区域。
- 动效在普通设备上保持流畅；不可见 Canvas 不持续运行。
- 键盘可完成导航、筛选、打开详情和提交主操作；减少动效设置生效。
- 不引入大面积渐变卡片、嵌套卡片或纯装饰性圆球背景。
