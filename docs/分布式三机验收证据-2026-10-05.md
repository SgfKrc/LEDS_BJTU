## 4. 逐 token 对拍：**未通过，且结论受方法论限制**

同一组 prompt、`temperature=0`，分布式与 `local_only`（HF transformers 全模型）比较：

| prompt | n=8 | n=16 |
|---|---|---|
| `Count from 1 to 5, ...` | local `1,2,3,4,` / dist `1, 2, 3,` | local `1,2,3,4,5` / dist `1, 2, 3, 4, 5`（`tokens_generated=13`） |
| `Name three primary colors.` | local `...red, blue,` / dist **完全相同** | local `...fundamental in` / dist `...and yellow.`（`tokens_generated=11`，提前停） |

**但该对照跨引擎**：`local_only` 是 **HF transformers 全模型**，分层链是
**HF `[0,16)` + llama.cpp GGUF `[16,24)`**。即使 GGUF 为 f16 无量化、权重逐 bit 相同，
**llama.cpp 与 HF 的 kernel 浮点求和顺序不同** ⇒ logits 低位有差异 ⇒ 在 top-2 接近处
翻转 argmax。这与实测形态吻合（`primary` 前 8 步逐字符一致、第 9 步附近翻转）。

**因此不能据此判定「层段接力有误」。** 判定接力正确性需要**同引擎基准**。

已确认、且**不受该限制影响**的三点：

- **接力的切分与节点数无关**：二段链（master `[0,16)` + Surface `cut-16` 承担
  `[16,24)`）与三段链输出**逐条完全相同**；
- **链路确定性**：同一 prompt 连发 6 次，输出完全相同；
- **prefill 正确**：`max_new_tokens=1` 时首 token 与全模型一致（`1` / `Three` / `The`）。

### 同引擎基准的尝试（受阻）

master 以 `engine=llama_cpp` 加载整模 `qwen25-05b-f16`（模型目录中标注为「对照基准」）
后，`local_only` **输出乱码**且与 prompt 无关。同一份 GGUF 在 Y700（App）上正常输出
⇒ **工件本身无问题**，问题在 master 的 llama.cpp 集成路径（最可能是该 GGUF 未内嵌
chat template，master 退化成裸补全）。**该路径暂时无法用作同引擎基准。**
