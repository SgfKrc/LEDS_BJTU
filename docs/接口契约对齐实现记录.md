# 接口契约对齐实现记录

本票基于《接口契约对齐审计计划.md》复核后端路由与 `frontend_cybergothic` 请求层，补齐了真实外部缺口，并将旧扫描器无法识别的泛型/二进制调用单独处理。

## 已实现

| 领域 | 前端实现 | 接入位置 |
| --- | --- | --- |
| RAG | `GET /rag/sources`、`DELETE /rag/sources/{source_id}`，含来源列表、文档/chunk 计数和删除 | Settings -> Local RAG |
| 模型 | `POST /models/prepare-pipeline`，为分层推理准备模型 | Models -> Runtime control |
| GGUF | `GET /models/gguf`、`GET /models/download/{filename}`，含清单、校验摘要和浏览器下载 | Models -> GGUF files |
| 日志 | `GET /logs/export` ZIP、`GET /logs/download` 单文件下载 | Audit -> Log archive |
| 前端诊断 | `POST /logs/client-error`，接收 `window.onerror` 与 `unhandledrejection` | `src/main.tsx` 全局监听 |
| 工作流 | `POST /workflows/journal/cleanup` | Tasks -> Workflows（主节点） |
| 集群档案 | profiles verify/create/list/current/activate/delete，discovery candidates，endpoints verify/list | Cluster Admin -> Cluster profiles |
| 审核邮件 | `POST /cluster/review/mail-poll` | Audit -> Transfer review（主节点） |
| 生命周期 | `POST /system/shutdown`，二次确认且仅 master 显示 | Settings -> Connection |
| 分布式生图 | distributed generate/grid/mixed/blob 的 API client 与二进制下载能力 | `src/data/api.ts`，供 Image Studio 后续编排 |

## 已覆盖但不直接暴露为普通按钮的协议

以下接口属于受信节点、实验或编排协议，已进入共享 API client，调用方可以在具备上下文后使用，但当前页面不提供误触风险较高的自由表单：

- Qwen3 local-chain begin/prefill/decode/parity/release/cancel
- `GET /models/downloadable`、`GET /models/files/{model_id}/{relative_path}`、`GET /models/pipeline-assignment/{model_id}`（受信模型 peer）
- deployment simulation create/get/prepare/activate/rollback
- experimental speculative

这些调用统一复用 bearer/log token、超时和错误语义；二进制接口通过 `requestBlob` 处理，不再误走 JSON 解析。

## 扫描器误报处理

审计扫描器将动态日志路径、二进制响应和泛型请求识别为缺口，因此原始报告中的 150 条不能直接等同于 150 个产品功能缺失。复核后，已将真实用户/管理员能力接入页面；仅节点内部协议保留为 API 能力，不复制一套不适合普通用户的控制台 UI。

## 验证

- `npm run typecheck` 通过。
- 需要真实后端/日志令牌的导出、GGUF 下载、profile 保存等操作在非 fixture 模式下执行；fixture 模式提供等价的本地演示数据和确认路径。
