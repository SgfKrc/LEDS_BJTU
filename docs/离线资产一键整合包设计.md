# 离线资产一键整合包设计

> 状态：**M1 已完成（2026-08-23，本机开发门）；M2 发布/目标设备复验后置**
>
> 更新日期：2026-08-23
> 适用范围：把「克隆后离线资产获取清单」里的**全部资产一键打包**成两个整合包（**PC 版** / **安卓版**），让克隆者/部署者只下载一个文件即可获得全部离线资产；复用既有资产冻结（lock/manifest/SHA）机制，不重新下载、不新增事实源
>
> 关联：[克隆后离线资产获取清单](克隆后离线资产获取清单.md)、[SD 1.5 离线资产包与签名源站发布计划](SD%201.5离线资产包与签名源站发布计划.md)（已完成）、MODEL-TOOLS 资产注册表

## 1. 背景与目标

现状：克隆者需要**逐个**下载 6+ 类资产（合计 ~30 GB）：Qwen 1.8B 双格式、Qwen3-4B GGUF、Gemma 4 原生、SD 五资产（15 GB）、Ollama（可选）——下载命令分散在多个文档，容易漏、容易版本不一致。

目标：
1. **一个脚本** `scripts/build_offline_bundle.py`，扫描本机已下载资产（复用 lock/manifest 校验），一键打包。
2. **两个整合包**：
   - **PC 版** `qlh-models-pc-<ver>.7z`：资产注册表中 scope=PC 的已下载模型与 SD 资产。
   - **安卓版** `qlh-models-android-<ver>.7z`：资产注册表中 scope=both 的**纯 GGUF**；SAF 选中解压后的 `models/` 即可扫描。
3. 整合包结构即"解压即用"：目录就位 + 校验通过（逐文件 SHA 侧车 + 总清单）。

## 2. 整合包结构（解压到项目根即就位）

### PC 版（`qlh-models-pc-<ver>.zip`，预计 ~28-30 GB）
```text
.
├── MANIFEST.json            # asset_id / 版本 / 大小 / sha256 / 去重目录映射
├── CHECKSUMS.sha256         # 逐文件 SHA 侧车（打包器生成）
├── README-导入说明.md        # 解压位置 + 校验命令 + serve 分发说明
└── models/
│   ├── qwen-1_8b-chat/                  # Qwen-1.8B Safetensors（3.5 GB）
│   ├── Qwen-1_8B-Chat.Q4_K_M.gguf       # GGUF Q4（1.16 GB）
│   ├── qwen3-*/                          # Qwen3/Qwen3.5（按注册表）
│   ├── gemma4-native/                    # GGUF + mmproj + lock.json
│   └── sd15-*/                           # 五资产展开后跨包去重，按 manifest 恢复
```
同名 archive 旁另生成 `qlh-models-pc-<ver>.7z.sha256`；分卷时该侧车逐卷列出 `.001/.002/...` 摘要，下载后可在解压前校验。

### 安卓版（`qlh-models-android-<ver>.zip`，预计 ~3.7 GB）
```text
.
├── MANIFEST.json
├── CHECKSUMS.sha256
├── README-导入说明.md      # SAF 选择 models/ + 扫描说明
└── models/
    ├── Qwen-1_8B-Chat.Q4_K_M.gguf
    ├── qwen3-4b-gguf/Qwen3-4B-Q4_K_M.gguf
    └── qwen3-5-*-gguf/    # 受注册表管理的 Android GGUF
```
> 安卓版只收 GGUF（Full 模式 SAF 直接扫目录即可用），不含 Safetensors/SD/Gemma（安卓无对应运行路径）。

## 3. 打包器设计（`scripts/build_offline_bundle.py`）

### 3.1 资产源与校验（不新增事实源）
| 资产 | 来源 | 校验依据 |
|---|---|---|
| Qwen-1.8B Safetensors | `models/qwen-1_8b-chat/` | 与下载时记录 SHA 比对（缺失时给出下载命令） |
| Qwen-1.8B GGUF | `models/Qwen-1_8B-Chat.Q4_K_M.gguf` | 同上 |
| Qwen3-4B GGUF | `models/qwen3-4b-gguf/` | 注册表/已知 SHA（7485fe6f…） |
| Gemma4 原生 | `models/gemma4-native/` | `gemma4-native.lock.json`（逐文件 size+SHA） |
| SD 五资产 | `build/sd15-assets/` | 既有包级 SHA 侧车（阶段 2 产物，复用）。**注：验收后清理过，本机当前无 zip 包**——重新打包用 `python scripts/package_sd15_assets.py --asset-id <id> --output-dir build/sd15-assets`（五个 id 见 `--list`，约 15 GB IO） |

- **缺失处理**：正常构建对所选 scope 的任何缺失均 fail-closed 并给出获取命令；`--missing` 只读列出 PC/Android 两侧缺失项。
- **不重下**：打包器只读已有资产；每次构建都会重新计算收录文件 SHA，不下载、不修改 `models/`。

### 3.2 打包格式与去重（已落地 2026-08-16/17）

- **`--format 7z`（默认）**：7-Zip（winget 安装）`-t7z -mx=1 -mmt=N`（`--threads N` 默认 4，**限制压缩并发**——本机 20 核默认吃满）**单卷三段增量追加**（models 部分 cwd=REPO_ROOT、sd15 staging、清单临时目录——免复制 30GB）；**分卷后置**：`--volume 4g` 时打包完成后再 Python 物理切分（7z 分卷=纯字节切割，`.001` 含完整 header 可独立解压；**7z 不支持对分卷 archive 增量追加**，实测 "System ERROR: 未实现"）。
- **跨资产去重（SD 五包）**：解包重组到 `models/sd15-*/`（不再收 zip），同 SHA 文件只存一份，MANIFEST 记 `dedup_of`，导入时 verify/restore 用 hardlink/symlink 还原——实测省 **2.66GB**（CLIP text_encoder 0.61GB×4、VAE 0.25/0.17GB×3、tokenizer）。
- **磁盘峰值控制**：`--prune-sd-zips` 边解包边删源 zip（可重建）；staging 打包后立即删（切分峰值 49GB）。
- **临时文件**：全部走 `D:/qlh_tmp`（`QLH_BUNDLE_TMP` 可覆盖）——**系统盘保护**（曾因 verify/tamper 临时文件把 C 盘挤到 11GB，已清理恢复）。
- **容量门（M1）**：构建开始前按未压缩 payload 保守估算 `OUT_DIR` 的包体+SD staging 峰值；启用 `--verify` 时同时核算 `QLH_BUNDLE_TMP` 的解包峰值。同卷时把成包保留与解包并存纳入峰值，空间不足拒绝写入；`--preflight` 可只读预览。
- **`--format zip`**：ZIP_STORED 快速模式（不压缩，无去重 staging 时也可用）。
- **体积真相（实测）**：权重已压缩，7z 对安卓版与 zip 几乎无差；PC 版主要收益来自**去重（-2.66GB）**，7z 压缩本身收益在文本/元数据。
- **实测产物（2026-08-17）**：PC 版 `qlh-models-pc-v1.7z.001-.007`（**26.0GB**，4g 分卷，verify 71 文件一致 + 21 去重链接恢复）；安卓版 `qlh-models-android-v1.7z`（3.66GB，verify 通过）。

### 3.2 打包流程
1. 收集资产 → 逐文件 SHA-256 校验（复用 `_sha256` 模式）
2. 生成 `MANIFEST.json`（canonical JSON + 总 SHA）+ `CHECKSUMS.sha256`
3. 写 `build/offline-bundles/`（zip 用 `ZIP_STORED` 不压缩——权重已压缩，压缩浪费 CPU；archive 级 `.sha256` 侧车齐全）
4. `--verify` 模式：受限解包、按 manifest 恢复 dedup 后逐文件比对大小/SHA；ZIP 路径越界、重复路径、manifest/checksum 不一致均拒绝。

### 3.3 CLI
```bash
python scripts/build_offline_bundle.py --pc          # 仅 PC 版
python scripts/build_offline_bundle.py --android     # 仅安卓版
python scripts/build_offline_bundle.py --all         # 双版
python scripts/build_offline_bundle.py --pc --verify # 打包后自动解包校验
python scripts/build_offline_bundle.py --pc --preflight --verify # 只读容量预检
python scripts/build_offline_bundle.py --missing     # 只列出缺失资产+获取命令
```

### 3.4 分发接线（serve.py）
- `packaging/serve.py` 对 `qlh-models-*-<ver>.7z` 与 `.7z.001` 分卷分类为 `kind=model-bundle`，主页列出两个整合包；安卓手机浏览器可直下安卓版。

## 5. 依赖与风险

| 项 | 说明 |
|---|---|
| 磁盘 | 打包需 ~30 GB 额外空间（`build/offline-bundles/`，ZIP_STORED 不压缩）；SD 五资产复用 `build/sd15-assets/` 不复制 |
| 时间 | 全量 SHA 校验 ~10-20 分钟（30 GB）；打包 IO 为主 |
| 冲突边界 | 不修改 `models/` 内容；不重新下载；与 gemma-4/并行组工作零交集（新增限脚本+测试+serve kind 分类）；SD 五资产只读展开到临时 staging 后按 SHA 去重，不修改源 zip |
| 风险 | ① 资产 SHA 漂移（重新下载后）→ manifest 以打包时刻为准并记录版本；② 整合包旧版被误用 → 文件名带 `<ver>`（对齐资产冻结版本） |
| 与 EX-N3 关系 | 27B 北极星（QW3.8-27B 专项）落地后，PC 版可扩展收录 27B Q4（预留结构：`models/qwen38-27b/` 目录约定） |
