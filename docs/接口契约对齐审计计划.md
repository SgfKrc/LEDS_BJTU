# 接口契约对齐审计计划（前端 × 后端机械扫描）

> 状态：**首轮审查完成（2026-08-22）；工具治理待收口**
>
> 创建日期：2026-08-21
> 适用范围：QLH 主系统 —— 「一键导出前后端接口清单，机械比对，
> 找出接口缺口（后端有前端未消费 / 前端调用后端未定义）」。
> 不替代双网关响应契约对比（`scripts/contract_diff.py`，那是后端×后端、需起服务），
> 本工具是**静态、离线、免起服务**的前后端契约面比对。

## 1. 调研结论（2026-08-21）

**后端接口面（两个并存）**：
- 单体 FastAPI：`src/api_server.py` 156 个 `@app.<method>` 路由（`/api/...`），
  另有 `src/inference_service/routes.py` 等 `@router.<method>` 子面；
- TS 网关：`gateway/src/modules/**/*.controller.ts`（Nest `@Controller('api')` 前缀 + `@Get/@Post/...`），
  对外端口 8000（`QLH_API_PORT` 可覆盖）、挂 `/api`，CatchAllController 返回 404。

**前端调用面（两个并存）**：
- 旧 `frontend/src/api/client.js`：`request('/path', { method, ... })`，method 缺省 GET；
- 新 `frontend_cybergothic/src/data/api.ts`：`BASE='/api'` + `request<T>(path, { method, ... })`，
  path 多为字符串字面量，部分为模板（`/auth/sessions/${encodeURIComponent(sessionId)}`）。
- 两前端目前都经 `/api` 前缀直连（dev 各走 vite proxy → 8000）。

**可复用资产**：`scripts/contract_diff.py` 已有「从 `src/api_server.py` 提取 @app.<method>
端点清单」的逻辑（正则/AST 均可参考）；无任何**前端×后端**审计工具。

**需求缺口（本工具补）**：
- 一个命令：导出后端接口清单 + 两端前端引用清单；
- 机械比对：接口是否对齐；报告 ①前端调而后端未定义（404 风险）
  ②后端已定义而前端未消费（功能缺 UI/未接线）。

## 2. 工具规格（`scripts/api_gap_scan.py`）

### 2.1 后端导出（静态 AST，不依赖服务在线）
- FastAPI 面：扫 `src/**/*.py` 中 `@app.<method>("<path>")` / `@router.<method>("<path>")`
  装饰器（`app`/`router` 为 FastAPI/APIRouter 实例），method ∈ get/post/put/delete/patch/head/options；
- 网关面：扫 `gateway/src/**/*.controller.ts`，`@Controller("<prefix>")` + 方法装饰器，
  路径 = `/api` + prefix + 方法 path；
- 产出条目：`{method, path_raw, source, file, line}`。

### 2.2 前端导出（静态扫描 JS/TS）
- 扫 `frontend/src/**/*.{js,ts,jsx,tsx}` 与 `frontend_cybergothic/src/**/*`：
  - `request(...)` / `fetch(...)` 第一参数为字符串或模板字面量，且形如 `/...`（或 `\`${BASE}…\`` / `BASE + path`）；
  - method 从同调用 `method: 'X'` 推断，缺省 GET；
  - 模板字面量中 `${...}` 归一化为 `{param}`；
- 产出条目：`{method, path_raw, source, file, line, kind: literal|template}`。

### 2.3 归一化与比对
- `normalize(path)`：补/剥 `/api` 前缀一致性，去 query，`{x}`/`:x`/`${...}` → `{param}`，去尾斜杠；
- 集合：F（前端引用）、B（后端定义，按 FastAPI 面/网关面分别）：
  - **缺口 A** = F − B：前端调了但后端没定义 → 404/未实现风险（最高优先）；
  - **缺口 B** = B − F：后端已定义但前端未消费 → 功能缺口（用户点名关注）；
  - **对齐** = F ∩ B；method 不同（如前端 GET 后端仅 POST）单独列「软缺口」。

### 2.4 报告与退出码
- 人类可读分节 + `--json` 全量导出（供 CI/证据）；
- 参数：`--include-gateway`（gateway/src controllers）、`--include-control`（control/src
  controllers）、`--only <子串>` 过滤、`-o <file>` 落盘；
- 缺口 B 内置内部面标注（`is_internal`：非 `/api` 前缀或 bootstrap/android/
  register/heartbeat 等关键词，标 `[i]` 与 JSON `internal` 字段），降噪音但**不隐藏**；
- 退出码（`exit_code()`）：0=对齐；1=有缺口 A；2=有缺口 B；3=A+B。提取失败=10。

### 2.5 边界与误报控制
- 只扫**字面量/模板字面量**，动态拼路径（`BASE + fullPath` 变量）不计入（README/文档声明）；
- 前端 `method` 推断：显式 `method: '…'` 优先；`const path = '…'` 形态标 `?`（比对时匹配
  任意后端方法）；不确定不猜；
- **router prefix 已静态展开**（`APIRouter(prefix=…)`/`@Controller('…')` 拼入最终路径，
  如 inference_service 的 `/v1` 面），不产生伪缺口；
- 报告头部输出扫描基线（条目数与来源分布），保证机械可复现。

## 3. 验收口径
- 单元测试：用 mini fixture（含 3 条后端路由 + 4 个前端调用，含模板参数/query/method 缺省）
  断言提取、归一化、A/B 缺口判定与退出码；**已落地 `tests/test_api_gap_scan.py`（8 passed）**；
- 真仓首跑：导出两份清单（后端单体+网关；两端前端），人工抽验 ≥5 条跨面条目
  与源码一致（行号可回溯）；**已抽验 7 条全部一致**；
- 缺口报告可被 CI 消费（`--json` 稳定 schema v1：`inventory + gaps + summary`）。

## 5. 不做（边界）
- 不做运行时请求级审计（需要起服务 + 污染调用面）；
- 不宣称「网关面=生产路由」，网关面差异以 `--include-gateway` 显式开启为准；
- 不动两前端的请求层代码与后端路由本体——本工具只读。

## 6. 2026-08-22 审查修订

本项目已冻结旧 `frontend/`：它只保留作历史对照，后续产品前端只认 `frontend_cybergothic/`。因此当前首跑的 411/255/138 数字只能作为历史混合基线，不能直接作为新前端缺口数。

下一票 `FE-AUD-01` 应将 canonical 前端改为 `frontend_cybergothic`，旧前端改为显式 `--include-legacy-frontend` 对照；报告同时输出“页面实际消费”和“仅共享 API client 声明”。跨行泛型调用（如 `POST /api/logs/client-error`、`POST /api/system/shutdown`）须从软缺口中消除。详细产品缺口见《前端安卓后端接口与功能缺口审查-2026-08-22》。
