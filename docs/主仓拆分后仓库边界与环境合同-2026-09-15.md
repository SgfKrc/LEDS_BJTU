# QLH 主仓拆分后仓库边界与环境合同

> 状态：现行（迁移基线）
>
> 更新日期：2026-09-15
>
> 适用范围：QLH 主仓、Android、Shell、Release、Toolbox 五个本地协同仓库

## 1. 结论

QLH 主仓只负责分布式推理优化、控制面、跨平台终端 TUI、模型资产合同和核心质量门。主仓不再把 Web/桌面壳、Android 客户端、安装发布、答辩演示、补丁同步和生图运行时当作核心目录。

| 仓库 | 本地默认路径 | GitHub 远端 | 责任 |
| --- | --- | --- | --- |
| `qlh` | `G:\C\PYT\qlh` | 当前主仓 | Engine L（llama.cpp）、PC Reference P、Control、TUI、模型合同、核心测试与边缘基线 |
| `qlh-android` | `G:\C\PYT\qlh-android` | `https://github.com/SgfKrc/qlh-android` | Android Full/Lite、JNI、Gradle、Android 测试与资源；内部固定 llama.cpp submodule |
| `qlh-shell` | `G:\C\PYT\qlh-shell` | `https://github.com/SgfKrc/qlh-shell` | CyberGothic Web/Desktop shell、Node 测试、API gap scanner、可选 Textual 环境 |
| `qlh-release` | `G:\C\PYT\qlh-release` | `https://github.com/SgfKrc/qlh-release` | Launcher、PyInstaller/Inno/Linux 发布、发布测试、发布虚拟环境 |
| `qlh-toolbox` | `G:\C\PYT\qlh-toolbox` | `https://github.com/SgfKrc/qlh-toolbox` | SSH/patch 同步、答辩/防御演示、性能报告及其测试 |

Koakumix `harness_workbench` 继续作为独立子模块；生图只在 Koakumix 维护。多模态能力由模型舰队按设备能力按需选择，主仓只维护模型/Provider/能力合同。

## 2. 跨仓库环境变量

开发者可以把四个外置仓库放在默认兄弟目录；换位置时显式设置：

| 变量 | 用途 | 默认值 |
| --- | --- | --- |
| `QLH_CORE_ROOT` | 主仓根目录 | 工作区兄弟目录 `qlh` |
| `QLH_ANDROID_ROOT` | Android 仓根目录 | 工作区兄弟目录 `qlh-android` |
| `QLH_SHELL_ROOT` | Shell 仓根目录 | 工作区兄弟目录 `qlh-shell` |
| `QLH_RELEASE_ROOT` | Release 仓根目录 | 工作区兄弟目录 `qlh-release` |
| `QLH_SPAWNLEDGER_ROOT` | Spawnledger 子模块目录 | `QLH_CORE_ROOT/packages/spawnledger` |

主仓核心脚本不会扫描或要求 Node、Android、发布虚拟环境。发布和工具脚本通过上述变量访问主仓源码；路径不存在时应 fail-closed，而不是重新寻找旧的主仓目录。

## 3. 环境与测试边界

- 主仓：`.venv-edge`、`.venv-test` 和 PC Reference P 实验环境留在主仓；标准入口是 `start_tui.bat` / `start_tui.sh` 与 `python -m src.tui_admin --plain`。
- Shell：`.venv-tui` 和 Node 依赖留在 `qlh-shell`；`frontend_cybergothic` 的构建、浏览器回归和 API gap 扫描在此仓执行。
- Release：`.venv-packaging`、`.venv-packaging-cuda` 以及发布锁文件留在 `qlh-release`；构建时由 `QLH_CORE_ROOT` 读取主仓 `src/`、`models/` 和核心文档，由 `QLH_SHELL_ROOT` 读取前端 dist。
- Android：构建输出、签名材料、Gradle 缓存和模型不入 Git；Android Full/Lite 的 JVM、instrumentation 和真机门在此仓执行。
- Toolbox：演示、补丁同步和答辩工具不应被主仓导入；其测试通过 `conftest.py` 注入跨仓根目录。

## 4. 迁移安全规则

1. 高危移动先做源/目标、文件数、磁盘空间和 Git 状态 dry-run，再执行 MOVE。
2. 删除语义统一改为移动到主仓 `_to_delete/`；本次迁移产生的中断 clone、旧 llama.cpp 工作树和根 `node_modules` 均保留在 `_to_delete/migration/`。
3. 不把签名私钥、keystore、`.env`、模型权重、Node/Gradle/Python 缓存提交到任何远端。
4. 主仓脏工作树属于用户现状，不因拆分而回滚或提交；四个外置仓库的迁移提交独立管理。
5. 外置仓库若需要回滚，优先使用 Git commit 或 `_to_delete/migration/` 保留材料，不直接删除目录。

## 5. 基线验收

迁移后的最低验收顺序：

```text
主仓：核心 Python 测试、文档链接、模型工具路径、无 torch Edge 入口
Shell：typecheck、build、shell tests
Release：发布测试收集/定向测试、spec 路径检查
Toolbox：演示/同步工具定向测试
Android：Full/Lite JVM 测试与 assemble/compile 门
```

四个远端目前已确定为 GitHub `SgfKrc` 下的同名仓库；推送前必须确认工作树中没有凭据、构建产物和模型文件。主仓外置目录不通过主仓 `.gitmodules` 隐式嵌套，协同关系由本合同和环境变量显式表达。
