### 1.2 节点角色：硬件硬门槛

- **实现**：`src/scheduler.py:7670 can_node_vote()` ——
  > 仅 `node_type="pc"` 且具备 **NVIDIA CUDA 独显**的节点可投票（P3 主节点转让审查）
- **调用侧**：`src/api_server.py:7971`（`POST /api/cluster/review/vote`）—— 不合格直接 `403`；
- **票据侧**：`src/review.py`（Gerrit 风格）：阈值 `APPROVE_THRESHOLD=+2` / `REJECT_THRESHOLD=-2`（`139-140`）、超时 `48h`（`141`）、创建者不可投票（`231`）、目标节点不可自批（`234`）、同节点改票（`242`）。

**为什么不合理**（三点）：

1. **审核资格 ≠ 推理能力**：转让主节点是**治理动作**，与"有没有独显"无关；Surface（从节点）与 Android 在组网里是**当事人**，却对主节点归属**无发言权**；
2. **与密码学身份脱节**：仓内每个节点都有 Ed25519 密钥与一次性入群授权（身份是**强的**），但投票资格却看硬件字符串（身份是**弱的**）；
3. **小集群被卡死风险**：家庭网规模下，若只有一台 CUDA 机器，"PC 独显门 + `≥+2` 绝对阈值" = 单点否决/无法达成 → 治理死锁。

### 1.3 可用性：单主节点 + 慢转让

- **单点事实**：`src/api_server.py:6843` `if scheduler._effective_role() != "master": raise 403("仅主节点可签发入群授权")` —— 主节点是唯一签发者；
- **转让链路慢**：`review.py` 的 48h 投票窗口 → **最坏 RTO > 48h**；
- **缺三件**：无备用主节点（standby）、无心跳接管、无 epoch/term 防脑裂；
- **可复用**：`scheduler` 已有 `_effective_role()` / `get_effective_node_id()`（角色抽象已在）；节点表已含 `node_type`、`capabilities`（`cluster_join._normalize_capabilities`）。

## §2 业内成熟方案调研（对照）

### 2.1 高危动作的二次确认（审核）

| 方案 | 机制 | 业内实例 | 适配度 |
| --- | --- | --- | --- |
| **TOTP（RFC 6238）** | 共享密钥 + 时间步（30s）+ HMAC → 6 位码；校验 ±1 步容差；已用码去重防重放；失败限速 | GitHub sudo mode（敏感动作重认证）、AWS S3 MFA Delete（高危操作强制 MFA）、Tailscale 设备审批、Cloudflare Zero Trust 注册审批 | **首选**：用户已持 authapp；纯 stdlib 可实现（`hmac`+`hashlib`+`base64`），零新依赖 |
| HOTP（RFC 4226） | 计数器式 | 硬件令牌 | 次选：需计数器同步，不如 TOTP |
| WebAuthn/FIDO2 | 公钥挑战-响应，防钓鱼 | 通行密钥 | 远期：需平台支持与额外交互成本 |
| 邮件/短信 OTP | 带外通道 | —— | **不采用**：本次被切的正是邮件通道 |

**TOTP 工程要点**（实现时逐条落实）：密钥≥160 bit 随机；`otpauth://` URI 供首次扫码；**重放防护**（记录已消费的 `time_step`，同一步长内同码只接受一次）；**限速**（连续 5 次失败锁定 15 分钟）；**恢复码**（一次性用户码，防手机丢失锁死）。

### 2.2 集群成员变更与角色资格

| 模式 | 要点 | 业内实例 |
| --- | --- | --- |
| **投票权与能力分离** | `votes`（是否有票）与 `priority`/`weight`（当选/权重）是**两个独立字段**；硬件只影响优先级，不剥夺投票权 | **MongoDB 副本集**（`votes` + `priority`），正解 |
| 能力标签 | 节点用 label 描述能力，策略用 selector 表达需求 | Kubernetes node label + taint/toleration |
| 单步成员变更 | 一次只加/删一个成员，避免多数派重叠失效 | Raft §6 joint consensus（Ongaro & Ousterhout）；etcd/Consul 成员管理 |
| 非投票成员 | 可接收数据但无投票权（过渡态） | etcd **learner** |

**对照结论**：本仓 `can_node_vote()` 的"硬件门"是**反模式**；应改为 `votes=1`（所有已入群节点，身份可信即有权）+ `weight`（PC+独显 2、其余 1），阈值从"绝对 ±2"改为**权重比例**（如 ≥50% 且 ≥2 节点参与；小集群退化为"全体一致除当事节点"）。

### 2.3 高可用与主节点转让

| 方案 | 要点 | 业内实例 | 适配度 |
| --- | --- | --- | --- |
| **冷备 + 计划内快转让** | 备节点定期同步状态；转让由**人确认**（TOTP）后立即生效，epoch/term 递增使旧主失效 | Patroni `switchover`（计划内）、Consul `operator raft transfer-leader` | **首选**：秒级生效，取代 48h 投票；无 quorum 成本 |
| 自动 failover | 心跳丢失 N 次 → 备节点自动接管（需 fencing 防脑裂） | Patroni（+etcd/Consul 做 DCS）、MongoDB 副本集自动选主 | P2：自动接管风险高于收益，先做"半自动"（心跳告警 + TOTP 一键接管） |
| quorum / 见证节点 | 多数派确认，天然防脑裂 | Raft、etcd、Consul | **不采用（本项目）**：家庭网规模下 3 节点起才成立，成本 > 收益 |

**关键设计点**：① **epoch/term 单调递增**（每次转让 +1，旧主的所有凭据/令牌**立即作废**）；② **fencing**（旧主被降级后拒绝其写入控制面）；③ **RTO/RPO 明示**（目标 RTO ≤ 60s，RPO = 上次快照点）；④ 转让审计（谁在何时用哪次 TOTP 确认的）。

### 2.4 节点身份与转让

- **已有且成熟**：Ed25519 密钥对（`cluster_join.JoinKeyPair`）、一次性 nonce ledger、短 TTL grant、请求摘要 —— 相当于简化版"入网证书签发"；
- **业内对照**：PKI/mTLS 短期证书、SPIFFE/SPIRE 工作负载身份（短 SVID + 轮换）、Tailscale 设备所有权转移与密钥管理；
- **本仓缺口**：① **密钥轮换**（节点私钥无过期/轮换流程）；② **吊销**（无 `revoked_nodes`；离开组网的节点凭据未失效）；③ **身份转让协议**（换机/重装后如何继承身份，当前只能重新入群）。

## §3 结合本项目的设计建议

### 3.1 A. TOTP 一步确认审核（用户指定方案）

**目标**：把"输入一次 authapp 算出的数字"变成**唯一**的审核凭据，彻底移除布尔接缝。

```
[目标节点] --join request(Ed25519 签名)--> [主节点]
[主节点] 展示请求摘要(节点名/指纹/能力) + 提示"请输入 Auth App 6 位码"
[用户]    authapp 输入 → 6 位码
[主节点]  auth_app.verify(code) 通过 → issue_join_grant(auth_verified=True) → 一次性 grant
[目标节点] consume grant（现有 nonce 一次性消费）
```

**实现要点**：

1. **新增 `src/auth_app.py`**（纯 stdlib，零依赖）：
   - `generate_secret()`（≥160 bit，base32）、`provisioning_uri(secret, label, issuer)`（`otpauth://totp/...`，首次扫码）、`verify(secret, code, *, at=None, window=1) -> bool`；
   - **重放防护**：`verify` 返回消费的 `time_step`，调用方持久化"最后消费步长"，`<= last` 一律拒绝；
   - **限速**：`AuthAppGuard`（连续 5 次失败 → 锁定 15 分钟，按节点/来源计数）。
2. **接线**（替换接缝，不新增端点）：
   - `POST /api/cluster/join/grant` 请求体新增 `otp_code: str | None`；**删除** `QLH_CLUSTER_JOIN_BOOLEAN_APPROVAL` 逃生舱与 `auth_verified` 客户端字段（服务端**自算**，客户端不再有发言权）；
   - `tui_admin.act_join`：`ui.prompt("Auth App 验证码: ")` → 传给端点；**不再** `confirm(...)` 后硬编码 `True`；
   - 保留 `501 auth_control_plane_unavailable`（未初始化密钥时 fail-closed）。
3. **密钥与初始化**：首次在主节点生成 `~/.qlh/auth_app_secret`（`0600`）+ 打印 `otpauth://` URI/QR；提供**恢复码**（10 个一次性码）；密钥可选入 sqlite 加密列（与现有 `JoinGrantLedger` 同库）。
4. **覆盖面**（一张票不够，见 §4）：不止 join —— **所有高危动作统一走 TOTP**：入群签发、**主节点转让**、节点移除、密钥轮换。实现为一个可复用装饰器 `require_totp(action)`，审计日志记录 `(action, node, time_step, result)`。
5. **与 `review.py` 的关系**：TOTP = **即时生效的确认**（单点，秒级）；`review.py` 投票 = **异步风控/知情**（可保留但**不阻塞**，改为"通知 + 异议窗口"语义；异议走 TOTP 否决）。

### 3.2 B. 角色能力化（替换硬件门）

- 删除 `scheduler.can_node_vote()` 的硬件判定；改为读**能力标签**（`cluster_join` 已在入群合同里携带 `capabilities`）：
  - `votes`：入群即 1（身份可信 = 有票），**与硬件无关**；
  - `weight`：`cuda=true` → 2；`cuda=false` → 1；Android → 1；
- `review.py` 阈值改**权重比例**：通过 = 赞成权重 ≥ 参与权重的 50% **且** 参与节点数 ≥ 2（小集群：除当事/创建者外全体赞成即通过）；
- 保留"创建者不可投票、目标节点不可自批"（`review.py:231/234`，这两条是**正确的**）；
- 硬件能力的**正当用途**保留在别处：**任务派发**（是否派 D 档流水线）、**GPU 拓扑** —— 而不是治理权。

### 3.3 C. 可用性（冷备主节点 + TOTP 快转让）

- **状态快照**：主节点定期导出控制面状态（sqlite dump + 关键表：节点表/审批表/join ledger）到**共享位置**（另一节点目录或用户级同步目录），带 `epoch` 与摘要；
- **心跳与告警**：节点每 30s 心跳；主节点失联 3 次（90s）→ 备节点提示"可接管"；
- **转让（计划内）**：`/cluster/failover` → TOTP 确认 → `epoch += 1` → 备节点加载最新快照并成为 master（秒级）；**旧主**的任何后续写入因 epoch 落后被拒（fencing）；
- **接管（计划外）**：同一路径，但需**人工判断**（TOTP 由用户确认"旧主确实宕机"），避免自动脑裂；
- **明确不做**：完整 Raft/quorum（3 节点起才成立，本项目 2–3 设备且手机端不适合做共识参与者）；
- **RTO 目标**：计划内转让 ≤ 60s；计划外 = 用户确认时长。

### 3.4 D. 节点身份转让与吊销

- **转让**：目标（新设备）生成新 Ed25519 密钥对 → 原身份设备签"离职授权"（或主节点凭 TOTP 直接签发新 grant）→ 新设备携带新公钥入群；旧 `node_id` 标记 `superseded_by`；
- **轮换**：节点密钥设有效期（如 180 天），临期前用旧密钥签新公钥（或 TOTP 确认）；
- **吊销**：`revoked_nodes` 表（node_id、公钥指纹、吊销时间、原因）；心跳/请求校验时比对；被吊销节点所有在途 grant 立即失效。
