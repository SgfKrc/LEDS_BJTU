# QLH 答辩演示：环境重置说明

> 票号：`DEF-A4`  
> 适用范围：`scripts/demo` 启动的 P1/P2/P3/P4 无模型答辩进程  
> 安全原则：票据只是线索，不是终止权限；默认只预演，身份不确定时保留现场

## 使用方法

在仓库根目录先执行默认 dry-run：

```powershell
scripts\demo\reset.bat
```

输出为 `DRY_RUN` 时，只表示发现经过当前身份校验、可由本票处理的残留；此命令不会终止进程，也不会删除票据。确认后显式执行：

```powershell
scripts\demo\reset.bat --apply
```

Unix 使用 `scripts/demo/reset.sh` 和 `scripts/demo/reset.sh --apply`。每次运行都会刷新脱敏报告 `build/defense-reset/latest.json`。退出码 `0` 表示无需处理或已完成；退出码 `2` 与 `REVIEW_REQUIRED` 表示票据损坏、PID 身份错配、进程无法停止，或登记端口仍被占用，需要人工查明归属。

## 所有权与终止门

P1/P2 启动器和 P3 benchmark 启动子进程后，会在 `build/defense-runtime/ownership/` 写入随机命名的所有权票据，并持续登记进程树。票据只含 PID、进程创建时间、固定进程类型、根 PID 和本票声明的 loopback 端口；不保存凭据、模型输入输出或命令行正文。

`--apply` 对每个候选进程重新读取操作系统状态，同时满足以下条件才允许终止：

1. PID 与创建时间同时匹配，排除 PID 复用；
2. 工作目录必须精确位于仓库根或现行 `frontend_cybergothic`；
3. 命令必须匹配内置的 frontend、backend、failure-worker 或 benchmark-worker 白名单；
4. 整张票据没有未知字段、重复身份、缺失根进程或身份错配；
5. 强制终止前再次执行同一身份检查。

任一条件不满足时，不按 Python/Node 名称批量终止，也不根据端口反查后盲杀；票据保留供人工审阅。票据内容不能添加新的进程类型或命令权限。

## 清理与保留边界

允许清理的对象只有：

- 身份重新验证通过的本票子进程；
- 对应进程已死亡且登记端口已释放后的 `.json` 所有权票据；
- 所有权目录内、名称严格符合随机票据格式的原子写入 `.tmp` 残片。

明确保留：

- `build/defense-demo`、`build/defense-benchmark`、`build/defense-preflight`、`build/defense-story` 中的脱敏证据；
- 模型目录、模型缓存和任何模型进程；
- 数据库、会话、审计记录和用户配置；
- IDE、浏览器、用户自行启动的 Python/Node 服务；
- 未登记端口及其占用者；
- 损坏或身份错配的票据。

因此，`REVIEW_REQUIRED` 不是“清理失败后可以扩大范围”的授权。应查看报告中的计数，人工确认来源；无法确认时改用空闲端口或停止动态演示。

## 重复彩排顺序

每轮开始前：

```powershell
scripts\demo\reset.bat --apply
scripts\demo\checklist.bat
```

之后按故事线运行 failure、benchmark、performance report 和 topology。演示结束先在启动器窗口按 `Ctrl+C`，再执行一次 `reset.bat --apply`。正常收尾会自动删除自身票据；第二次重置应输出 `RESET_COMPLETE` 且 `receipt_files=0`，证明重置幂等。
