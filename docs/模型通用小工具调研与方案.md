## 2. 候选小工具清单（按类别）

### 2.1 GGUF 文件工具（当前缺口最大，P0）

GGUF 是二进制格式，元数据（架构、量化类型、上下文长度、词表大小、张量清单）内嵌在文件头，llama.cpp 加载失败时很难人工排查。三个最值得做的工具：

| 工具 | 功能 | 依赖 | 工作量 |
|---|---|---|---|
| **`gguf_inspect` 元数据查看器** | 读取 GGUF 头：`general.architecture`、`general.name`、量化类型（从文件名之外直接读 `block_count`/`quantization_version` 推导）、上下文长度、词表类型与大小、张量名/形状/类型列表 | `gguf`（llama.cpp 官方 Python 包，轻量）或手工解析 header | 小（0.5-1 天） |
| **`gguf_verify` 完整性校验** | ① 比对 `.sha256` 侧车文件；② 无侧车时用 `gguf` 包完整解析张量元数据（能解析 = 结构未损坏）；③ 可选做张量字节级哈希抽样 | 无额外依赖 | 小（0.5 天） |
| **`gguf_convert` 量化转换器** | 在 Q4_K_M / Q8_0 / F16 等之间转换；附带"磁盘→临时→原子替换"流程与 junction 兼容 | llama.cpp `convert_hf_to_gguf.py` + `llama-quantize`（需带 llama.cpp 工具链） | 中（2-3 天） |

> 价值场景：下载的模型报"加载失败"时先 `gguf_inspect` 看量化/架构是否与引擎预期一致；`gguf_verify` 快速区分"文件损坏"与"引擎问题"；`gguf_convert` 支持把新模型按设备显存降量化，无需重新下载。

### 2.2 模型库运维工具（P1）

| 工具 | 功能 | 依赖 | 工作量 |
|---|---|---|---|
| **`models_sweep` 全库体检** | 遍历 `models/`：GGUF 查侧车哈希、diffusers 目录对照 manifest SHA256（复用 `src/diffusion/assets.py` 的 `verify_asset_directory`）、报告孤儿文件（`.part`、`.tmp`、无主 `.cache`）、输出人类可读 + JSON 报告 | 复用现有 `compute_file_sha256`、`verify_asset_directory` | 中（1-2 天） |
| **`models_clean` 磁盘清理助手** | `--dry-run` 列出可安全删除项（孤儿 `.part`、`.cache`、旧模型备份 `models_old_backup`、重复 sha256 文件），确认后才删；**必须感知 junction**（当前 `models/` 是 H 盘 junction，不能误删联接本身） | 无 | 小-中（1 天） |
| **`models_sync_status` 多节点模型同步检查** | 对比主/从节点模型清单与哈希，输出"缺、多、不一致"三类差异；只读不改，为分布式部署前体检 | 复用 `model_sync.py` | 中（1-2 天） |
| **`model_disk_usage` 占用统计** | 按模型/子目录统计实际占用，区分 junction 目标盘占用（`du` 对 junction 显示 0 的坑，需 `os.stat` + `Path.resolve()` 处理） | 无 | 小（0.5 天） |

### 2.3 SD 1.5 图像工具（P1-P2）

| 工具 | 功能 | 依赖 | 工作量 |
|---|---|---|---|
| **`sd15_merge` 模型融合器** | checkpoint/LoRA 融合：基座 + LoRA → 合并 safetensors，产出新 asset 目录并按现有 SHA256 约定登记 | `diffusers`、`safetensors`（CUDA 侧车环境） | 中（2-3 天） |
| **`sd15_prompt_batch` 提示词批量测试** | 固定 seed/step/sampler，批量跑 prompt 矩阵并生成对比网格图 + 报告（对齐 `quality_gate_sd15.py` 的报告格式） | 复用 `smoke_sd15.py` / quality_gate 基建 | 中（2 天） |
| **`sd15_sampler_matrix` 采样器对比** | 同一 prompt 下 Euler/DDIM/DPMSolver 等采样器 + step 数矩阵，输出直观对比图，用于 preset 调参 | 同上 | 中（2 天） |
| **`sd15_lora_inspect` LoRA 元数据查看** | 读 safetensors 头：`ss_*` 元数据（训练集、触发词、学习率）| `safetensors` 头解析即可，无需 GPU | 小（0.5-1 天） |

> 注：SD 侧尽量复用现有 CUDA 侧车虚拟环境（`.venv-packaging-cuda`）与质量门报告登记机制，不污染主解释器。

### 2.4 LLM 运行时体检工具（P2）

| 工具 | 功能 | 依赖 | 工作量 |
|---|---|---|---|
| **`llm_smoke_matrix` 全模型冒烟矩阵** | 对注册表里每个模型（GGUF + PyTorch）跑固定 3-5 条冒烟 prompt（中文/英文/长上下文/JSON 输出），汇总"哪些模型可加载、可生成、输出格式合规" | 复用 `benchmark_all.py` 的加载路径 | 中（2 天） |
| **`tokenizer_stats` 分词器统计** | 输出词表大小、BOS/EOS/PAD 是否齐全、中文字符编码效率（每字 token 数） | `transformers` / llama.cpp tokenizer | 小（0.5 天） |

## 3. 优先级与实施建议

### 3.1 推荐路线

| 优先级 | 工具 | 理由 |
|---|---|---|
| **P0（先做）** | `gguf_inspect` + `gguf_verify` | 缺口最大、工作量最小、立即提升排查效率；纯标准库/官方 `gguf` 包，无环境风险 |
| **P0** | `models_sweep`（含 junction 感知） | 模型已迁 H 盘，全库体检能发现迁移残留与损坏，复用现有 SHA256 基建 |
| **P1** | `models_clean`、`model_disk_usage` | 磁盘治理刚需，注意 junction 安全 |
| **P1** | `sd15_prompt_batch` / `sd15_sampler_matrix` | 直接服务 preset 调参与质量门，复用 quality_gate 报告格式 |
| **P2** | `gguf_convert`、`sd15_merge`、`models_sync_status`、`llm_smoke_matrix` | 需要 llama.cpp 工具链或 CUDA 侧车，投入产出比次之 |

### 3.2 通用原则

1. **只读工具优先**：inspect/verify/sweep/status 全部只读，无副作用，先落地建立信心。
2. **复用而非重造**：SHA256 用 `src/model_sync.py`；SD 校验用 `src/diffusion/assets.py:verify_asset_directory`；报告格式对齐 quality_gate 系列；模型注册用 `src/model_config.py` BUILTIN_MODELS。
3. **CLI 优先，输出双格式**：人类可读表格 + `--json`（对齐 `export_model_catalog.py` 与 `quality_gate` 的报告约定，未来可被自动化实验框架消费）。
4. **junction 安全**：`models/` 现为 H 盘 junction，任何删除/统计工具必须 `os.path.islink()` 或 `Path.is_junction()` 判断，只操作 junction 内部文件，绝不删联接本身。
5. **环境隔离**：GGUF 纯解析工具只用标准库 + `gguf` 包（轻量）；SD 工具走 CUDA 侧车；不往主解释器塞重依赖。

### 3.3 落地形态建议

统一入口：`scripts/model_tools/` 目录 + 一个 `model_tools.py` 子命令分发（`python scripts/model_tools.py inspect models/xxx.gguf`），或直接复用 TUI 指令集模式注册进 `bjtu` 命令体系（对齐 `docs/TUI指令集.md`）。P0 两个工具建议一次性提交。
