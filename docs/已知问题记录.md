### #2 任务链落地被 workflow 的单模型身份锁死为同模型

- 现象：异构 Worker（不同模型/引擎）在任务链上被全局过滤，链上只能全集群同模型。
- 根因：`StageSpec` 缺 per-stage 身份表达，自动候选按"与主节点一致"过滤；协议与调度层本就按异构设计。
- 已做：`StageSpec.model_identity`（缺省继承 workflow）+ `_prepare_stage` per-stage 覆盖 + 固定模板 `llm_sd15_v1`。
- 待做：任意 DAG 归 `TC-N3.1`；真实异构 Worker 验收。
- 证据：`src/task_graph.py`、`src/task_worker_protocol.py:625-713`、`tests/test_task_graph_review.py`、`tests/test_task_graph_api.py`。

### #19 分布式注册 / ACK / 重连缺少统一竞态门

- 现象：真实双机曾出现 active 连接重复拒绝、旧 socket `WinError 10038`、ACK 错序、reservation 重复释放。

- 已做：`T-RACE-0`–`T-RACE-5`（三轮 × 48，固定 seed）与 `T-RACE-6-A/B` 通过。
- 待做：`T-RACE-6-C`（长时 / 升级 / 断电）需真实设备。
- 证据：`tests/test_t_race5_soak.py`（`T-RACE-6-C` 无自动化）。

### #28 worker 实时 `models` 为空导致远端 Stage 被误拒（`model_identity_mismatch`）

- 现象：两端 sha256 一致，远端 Stage 仍 `state=failed / model_identity_mismatch`。
- 根因：`src/scheduler_task_worker.py:100-102` 只要残留非 None 的 `layer_range`，实时 `models` 即空；层段加载/释放路径不调 `refresh_task_worker_capabilities()`（`:169-189`）；主节点 `src/scheduler.py:2964-3001` 用 hello 旧快照 ⇒ 同节点双源真相。
- 处置：A（补 refresh）造成正反馈死循环、B（release 卸载）掉出 `opt_out` 触发重分层，两者实测失败已整体回退（`db443dc`）。剩余方向是主节点侧 C：幂等 hello / 同源带时效快照 / opt-out 同步，未实施。
- 与 #22.6 同根因（完整模型身份与层段角色的状态不同步），处置时一并收口。
- 证据：`local_docs/evidence/rr3-taskgraph/distributed_used_proof.json`。

### #29 `execution_mode=auto` 静默忽略 `task_graph_template`

- 现象：带 `task_graph_template` 但未给 `execution_mode` 时返回 503 `pipeline workers not ready`，模板未生效且无提示。
- 根因：`execution_mode` 默认 `auto`，`task_graph_template` 只在任务图分支被消费（`src/api_server.py:2913-2920`、`:3044+`），两者不联动。
- 处置方向（未实施）：带模板或 `task_graph_auto_remote` 时明确走任务图，或返回 `reason_code` 说明未走任务图并写进响应与日志。

### Android layer-worker alignment

- 现象：Android 分布式模式接入认证 TCP task-worker，`layer_forward` 成为真实执行路径。
- 已做：worker 走 REGISTER/HMAC + v3 协商 + 心跳；从裁层 manifest 公布层范围并校验层数与 embedding；scheduler 仅在显式 `forward_layers` 时接受 Android；legacy PyTorch `LAYER_CONFIG` 通道保持 PC-only。Kotlin 侧独立裁层加载路径已修复。
- 待做：真机 coordinator → task-worker → JNI 端到端实测；模型 id + SHA256 资源门需精确匹配。
- 证据：`android/app/src/main/java/com/qlh/inference/service/{LayerArtifactCatalog,ModelManager,InferenceService,LocalInferenceEngine}.kt`。

## 3. 上游缺陷

### #27 llama.cpp RPC 无错误恢复：任一 socket 失效即 `abort()` 整个进程

- 现象：跨机 RPC 请求全部成功后的收尾阶段，host 退出码 `3221226505`（`0xC0000409`）、worker 退出码 1，请求判据仍 `passed`。
- 根因：`0xC0000409` 是 `abort()` 经 `__fastfail(FAST_FAIL_FATAL_APP_EXIT=7)` 的用户态异常码；`ggml-rpc.cpp:30` 的 `RPC_STATUS_ASSERT` 失败即 `GGML_ABORT`，`transport.cpp` 对 `recv() == 0` 静默返回 false。上游 #26384 记录该宏并结论"RPC has no error recovery"。
- 处置：本仓不改（上游设计缺陷）；作为生产 supervisor 使用前需上游修复或自建 supervisor。
- 证据：`local_docs/evidence/llama-pc-rpc/rr6-*.json`；另见[验收清单](验收清单与资源限制登记.md) D20。
