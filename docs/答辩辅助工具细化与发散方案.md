## 1. 概述

原计划《答辩演示与实用工具原型计划》已将演示侧原型列为 P1–P8。本文档对其中**尚未启动、且为答辩主轴**的四个工具（P1–P4）做细化，落到接口、数据源、验收口径与复用既有代码；并在此基础上**发散**整体还能补充哪些辅助工具（§5，按价值/成本排序）。

四个工具共同构成答辩故事线：

```
P1 一键演示模式  —— 现场不翻车（稳定入口）
P2 失败注入演示  —— 断网自愈（可靠性卖点）
P3 分布式 benchmark —— 用数字说话（单机 vs 双机）
P4 集群拓扑可视化 —— 一眼看懂分布式（readiness 快照）
```

共性设计原则：
1. **复用既有代码，不重造轮子**（见 §2 已有基础清单）；
2. **可复现**：固定 seed、固定负载、输出 JSON+图表可 diff；
3. **不落凭据/绝对路径**：脚本一律走环境变量与脱敏输出；
4. **声称即证据**：每个原型独立提交，完成须附 `git status`/`git diff`/commit hash。

## 3. P1–P4 细化方案

### P1 一键演示模式（P0）

**目标**：`demo.sh` / `demo.bat` 一键拉起全栈（后端 + 前端 + worker），跑通预置对话/图像脚本，现场演示不翻车。

**细化**

1. **入口与流程**（对齐 `start_tui.sh` 成功范式）
   - `demo.sh`（Linux/macOS）/`demo.bat`（Windows）为唯一入口；
   - 流程：`setup`（检测/提示依赖缺失）→ `start-backend`（等 `/api/health` 就绪，超时提示中文）→ `start-worker`（本机 worker，读环境变量注入端口/模型）→ `start-frontend` → 打开浏览器 → 跑预置脚本；
   - 每步输出固定标记（`[QLH-DEMO] OK start-backend`），失败输出中文提示并以非零码退出，便于 CI 断言。

2. **预置脚本**（两个最小闭环）
   - **对话**：`POST /api/chat`，用固定 prompt + 固定小模型（如 `sshleifer/tiny-gpt2` 或仓库内置 Qwen-1.8B 量化档），断言返回非空文本；
   - **图像**：走 SD 1.5 或既有图像端点（如 `scripts/smoke_sd15.py`/`smoke_sd15_distributed_worker.py` 复用），断言生成文件存在。
   - 脚本放 `scripts/demo/`，输出统一 JSON（`{"step":...,"ok":true,"ms":...}`）。

3. **验收口径（对齐原计划）**
   - 干净环境一键启动 ≤ 2 分钟；
   - 预置脚本输出固定成功标记；
   - 任意一步失败有中文提示且退出码非零。

4. **复用与边界**
   - 复用 `start_backend.bat`/`bjtu` 的启动与健康等待逻辑；
   - 不引入架构改动；worker 用最小可跑配置，不要求双机。

---

### P2 失败注入演示（P0）

**目标**：断网 / `kill` worker → 自动重派恢复，一键演示「断网自愈」。

**细化**

1. **注入方式（3 种，脚本可参数化）**
   - `--kill-worker`：对 worker 进程发 `SIGKILL`/`taskkill`；
   - `--net-off`：阻断网卡/代理（本机用轻量方式，如停用 tailscale 接口或用 loopback 规则）；
   - `--pause-register`：模拟注册失败（对齐 `tcp_comm.py` 的注册失败路径，观察重连不孤儿化）。
2. **观测点**
   - 主节点日志（复用 `qlh_log.py 汇总`）：`下线` → `重编排/重派` → `恢复在线`；
   - 前端拓扑（P4 的画布）：节点状态从 `online` → `offline` → `online`；
   - 任务最终完成且旧 attempt 结果被丢弃（对齐《任务链计划》的 fencing 语义）。
3. **断言脚本**
   - `scripts/demo/failover_demo.py`：kill → 轮询日志/状态 → 断言「节点下线→重派→任务完成」三态，重复 3 次稳定。
4. **验收口径**
   - 演示脚本在 kill worker 后能观察完整重派恢复链路；重复 3 次稳定；
   - 不依赖第二台 CUDA PC（本机双进程模拟即可作为最小闭环，真机作为升级演示）。

> 注：`src/tcp_comm.py` 已修复注册失败/断开先栅栏线程再关 socket 的竞态（上一轮提交 `9bd43ea`），P2 直接以该路径做演示素材。

### P3 分布式 benchmark 工具（P0，等双机验收 A4）

**目标**：单机 vs 双机延迟 / 吞吐 / 显存对比，输出 JSON + PNG 图表。

**细化**

1. **负载口径（固定 seed，可复现）**
   - 固定 prompt 集 + 固定生成长度（token 预算）+ 固定 seed；
   - 度量：首 token 延迟（TTFT）、总延迟、吞吐（tok/s）、显存（若可读）、`nodes_participated` 参与节点数。
2. **两种形态**
   - `local_full_model`（单机）：主节点完整推理；
   - `pytorch_layer` / `task_graph`（双机）：分布式层拆分或远程 worker，记录实际参与节点。
3. **输出**
   - `build/benchmark-{ts}.json`：原始指标 + 归一化（转 tokens）；
   - `build/benchmark-{ts}.png`：并排柱状/折线（复用或新增轻量 matplotlib 脚本，无 matplotlib 则输出 SVG/CSV 供前端渲染）。
4. **验收口径**
   - 同负载下输出 JSON+PNG；数据可复现（seed 固定）；
   - 明确标注「单机 vs 双机」对比及 `nodes_participated`，避免口说无凭。

> 注：原计划要求 P3 等双机验收（A4）数据源就绪后做实测；本方案先落地**工具与输出格式**（用本机模拟数据源验证），真机数据就绪后填充实值。

---

### P4 集群拓扑可视化（P1）

**目标**：Web 前端绘制节点 / 层分配图（基于 readiness 快照），真实集群渲染节点 + 层段分配。

**细化**

1. **数据源**
   - 后端已有 `readiness`/`is_available`/`nodes_participated` 语义（见 `api_server.py` 的 readiness 门控与 `/api/status`）；
   - 新增或复用「快照端点」输出：节点列表（`node_id`/`role`/`state`/`is_available`）+ 每节点承担的层段标识 + 时间戳。
2. **前端渲染（复用既有画布）**
   - `ClusterConstellationCanvas.tsx` 已支持 `nodes` prop（master 居中、`is_available` 定金/铜色调、`data-node-count` 验证）；
   - 补充：层段分配标注（每节点旁的层段文本）、当前离线/重编排的动态状态色、展示数据的 `role`/`state`。
3. **脱敏**
   - 只暴露 `node_id`/`role`/`state`/层段；不暴露绝对路径、密钥、IP 直连细节（对齐项目脱敏纪律）。
4. **验收口径**
   - 真实集群渲染节点 + 层段分配；无绝对路径/密钥泄漏；
   - readiness 变更能反映为画布状态变化（配合 P2 失败注入可演示）。

> 注：`ClusterConstellationCanvas` 上一轮已接入真实节点拓扑（提交 `f769e9e`），P4 在其上补 readiness 快照数据源与层段标注。

## 6. 防扩张边界（不做什么，防止发散失控）

- ❌ 不把 A/B/C 系列工具接入安装包或业务 `src/` 主流程（开发期工具，与 `答辩演示与实用工具原型计划.md` §2 一致）；
- ❌ 不引入架构级工作（QW3.5 运行时、Gemma 4 真实标定、音频/8K、新多模态——登记未来工作）；
- ❌ 不依赖第二台 CUDA PC / Linux 真机 / 大显存才能完成的最小闭环（真机仅作为升级演示，最小闭环用本机模拟即可验证）；
- ❌ 不在工具脚本里落凭据、绝对路径、密钥、真实外网 URL（脱敏纪律贯穿所有原型）。
