## 1. 背景与目标

### 1.1 现状

- 安装包发布物为 Inno Setup 安装器（`QLH-Edge-Inference-Setup-vX.X.X.exe`），安装过程需要交互（向导、UAC、路径选择），无法由引导器免交互完成。
- [引导器方案](安装包自动更新引导器方案.md) 中 `install` 阶段的定位是"引导安装"——拉起安装器由用户点完向导，**没有实现"自己解压安装"**。
- 节点自动更新场景（多节点集群同步）要求：免交互、可指定安装目录、可覆盖旧版本、失败可回滚；现有 Inno 安装器不满足。

### 1.2 问题

1. 安装器交互打断自动化：集群内批量更新时每台机器都要人点向导。
2. 安装路径被安装器固定（`C:\Program Files\QLH-Edge-Inference`，需 UAC 提权），无法装到用户指定目录（如 `D:\QLH`、`%LOCALAPPDATA%`）。
3. 覆盖安装依赖安装器行为（文件占用、旧版本残留），无统一回滚保障。

### 1.3 目标

1. 引导器能够**自行解压安装包**到默认目录或用户指定目录，全程免交互。
2. 支持**覆盖安装**：检测已装版本 → 停止运行中实例 → 备份旧版 → 解压新版 → 校验 → 原子切换 → 失败回滚。
3. 数据目录（模型、聊天记录、节点配置、数据库）在覆盖安装中**必须保留**。
4. 首次安装/手动重装/卸载仍可走 Inno 安装器，两条路径并存不冲突。

> **非目标**：不做跨平台安装器（不实现自研 MSI）；不做安装包格式的向后兼容迁移（v0.1.x 旧版仍用 Inno 卸载）；Android 端仍走 APK 系统安装器，不涉及本方案。

## 2. 总体设计

### 2.1 发布物扩展：文件级安装包

在现有 Inno `exe` 之外，每个发布版本**新增**一个文件级安装包（引导器自动更新专用）：

```
QLH-Edge-Inference-vX.X.X-{cpu|cuda}-files.zip
```

- 格式：**zip**（Python 标准库 `zipfile` 即可解压，Windows/Linux 零外部依赖；压缩率略低于 7z，对 157MB~1.7GB 的包可接受）。
- 内容：与 Inno 安装目录布局**完全一致**的文件树 + 根级 `manifest.json`。
- 生成：发布流程新增脚本 `packaging/make-filepkg.py`，从 PyInstaller 输出目录（`dist/QLH-Edge-Inference/`）打包并计算全量文件校验（见 §7）。
- Inno exe 保留：首次安装、手动重装、卸载管理、不信任文件级安装的用户。

### 2.2 安装流程状态机

```
idle ──▶ resolve_dir（默认目录/用户指定/已装目录跟随）
        │
        ▼
   detect_existing（installed.json / 目录存在性）
        │
        ├── 无旧版 ──▶ extract ──▶ verify ──▶ finalize（写 installed.json）
        │
        └── 有旧版 ──▶ stop_services（停止运行中实例）
                        │
                        ▼
                 backup（目录 → install_dir.bak-<ts>，数据目录除外）
                        │
                        ▼
                 extract（解压到 install_dir.new-<ts>）
                        │
                        ▼
                 verify（manifest 交叉校验）── 失败 ──▶ rollback（恢复 .bak）
                        │
                        ▼
                 swap（rename .new → install_dir）── 失败 ──▶ rollback
                        │
                        ▼
                 finalize（写 installed.json，清理旧 .bak 保留 1 份）
```

### 2.3 与引导器（QLH-Updater）的关系

- 复用引导器现有 `install` 命令，扩展安装引擎；下载/校验/源切换逻辑不变。
- 新增参数：`--dir <目标目录>`、`--overwrite`（显式覆盖）、`--keep-data`（默认开启）、`--mode file|installer`（默认 file）。
- 配置文件新增字段：`install_dir`、`install_mode`、`keep_backups`。

## 3. 目标目录决策

优先级从低到高（后覆盖前）：

| 方式 | 示例 | 说明 |
|---|---|---|
| manifest 默认目录 | `%LOCALAPPDATA%\QLH-Edge-Inference`（Windows） | 用户级，免 UAC |
| | `~/.local/share/qlh-edge-inference`（Linux） | 免 sudo |
| 配置文件 | `{"install_dir": "D:\\QLH"}` | 持久化自定义 |
| 环境变量 | `QLH_INSTALL_DIR=D:\QLH` | 批量部署用 |
| CLI 参数 | `qlh-updater install --dir D:\QLH` | 单次覆盖 |

**跟随已装目录**：若检测到已安装（`installed.json` 或 Inno 注册的 `C:\Program Files\QLH-Edge-Inference` 存在），默认目标目录跟随既有安装位置，避免同一机器出现两套副本；跟随到 Program Files 需要提权时，用 `ShellExecute runas`（Windows）/ `sudo`（Linux）提示用户授权，或提示改用用户级目录。

## 4. 文件级安装包规范

### 4.1 manifest.json

```json
{
  "name": "qlh-edge-inference",
  "tag": "v0.1.8",
  "variant": "cpu",
  "platform": "windows",
  "arch": "x86_64",
  "default_dir": {
    "windows": "%LOCALAPPDATA%\\QLH-Edge-Inference",
    "linux": "~/.local/share/qlh-edge-inference"
  },
  "files": [
    {"path": "QLH-Edge-Inference.exe", "size": 157949378, "sha256": "…"},
    {"path": "_internal/api_server.pyc", "size": 123456, "sha256": "…"}
  ],
  "keep": ["models", "chat_history", "node_config.json", "*.db", "logs"],
  "executables": ["QLH-Edge-Inference.exe"],
  "shortcuts": [
    {"name": "QLH 边缘推理", "target": "QLH-Edge-Inference.exe"}
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` / `tag` / `variant` / `platform` / `arch` | 是 | 与引导器设备画像匹配（变体 `cpu`/`cuda`，不参与版本判断） |
| `default_dir` | 是 | 各平台默认目录模板（展开 `%LOCALAPPDATA%`/`~`） |
| `files` | 是 | **全量**文件清单（路径相对包根，正斜杠），供交叉校验与大小核对 |
| `keep` | 是 | 覆盖安装时**排除在备份/替换之外**的目录与文件 glob（相对安装根） |
| `executables` | 否 | 安装后需要可执行权限的文件（Linux chmod +x） |
| `shortcuts` | 否 | 桌面/开始菜单快捷方式定义（首期 Windows 创建 `.lnk`，Linux 创建 `.desktop`） |

### 4.2 zip 包内容约束

- 所有条目路径必须为正斜杠相对路径，**禁止**绝对路径、盘符前缀、`..` 越界（防 zip slip，见 §8）。
- `manifest.json` 必须为 zip 第一层根条目（`/manifest.json`）。
- 包内文件路径与 `files[].path` 一一对应；发布脚本生成时即交叉校验，不一致直接构建失败。

## 5. 覆盖安装详细设计

### 5.1 停止运行中实例

| 平台 | 检测方式 | 停止方式 |
|---|---|---|
| Windows | 端口 8000 探测（复用 launcher `_kill_port_8000` 思路）+ 进程名 `QLH-Edge-Inference` | `taskkill /PID <pid>`（普通权限可杀同用户进程）；进程退出等待超时 10s |
| Linux | pid 文件 `~/.local/share/qlh-edge-inference/run/qlh.pid` + `pgrep -f QLH-Edge-Inference` | `kill <pid>`，超时后 `kill -9` |

- 停止前记录"用户是否正在使用"提示（交互模式询问；`--yes` 静默停止）。
- 停止失败（权限不足/进程无法终止）→ 中止安装并回滚，不强行覆盖运行中文件。

### 5.2 备份

- 将现有安装目录重命名为 `{install_dir}.bak-{YYYYmmddHHMMSS}`（**同盘 rename，快**）。
- `keep` 列表中的数据（models/、chat_history/、node_config.json、*.db、logs/）**不随目录移动**：先拷入 `install_dir.new-<ts>` 对应位置，或留在原目录等待解压合并——实现选后者：备份时把 `keep` 项先移到 `install_dir.new-<ts>` 内，`.bak` 中不再保留副本（避免 1.7GB 模型被复制两份）。
- 磁盘空间预估：需 `新包解压后大小 + 旧目录大小(除 keep) + 少量余量`；不足则中止并提示（发布物内 `files` 清单可精确估算）。

### 5.3 解压与校验

1. 解压到 `{install_dir}.new-<ts>`（`zipfile` 逐条目解压，规范化路径）。
2. 校验：按 `manifest.files` 抽查（默认全量 sha256；`--fast` 仅比对 size），任何不匹配 → 整体失败。
3. 权限：Linux 对 `executables` chmod +x；Windows 无特殊处理。

### 5.4 原子切换与回滚

- 切换：`os.replace` 目录级不可用 → 用 `rename`（同盘原子性足够）；切换前确认 `.new` 完整。
- 回滚触发：解压异常 / 校验失败 / 切换失败 / 切换后启动冒烟（可选 `--smoke`：启动 exe 5 秒内退出码 0）。
- 回滚动作：删除 `.new`，`rename .bak → install_dir` 恢复，写 `installed.json` 旧版本标记。
- 清理：成功后保留最近 1 份 `.bak`（可配 `keep_backups`），其余删除。

### 5.5 数据保留（keep 清单落库到 installed.json）

覆盖安装后 `installed.json` 记录 `keep` 快照，供后续版本升级沿用；`node_config.json` 中的节点身份、`admin_email`（修复后）、数据库文件均保留，升级不影响集群注册状态。

## 6. CLI 与交互扩展

```
qlh-updater install [--dir PATH] [--mode file|installer] [--overwrite]
                    [--keep-data] [--fast] [--smoke] [--yes] [--force]

  --dir PATH      目标安装目录（自定义，覆盖默认/已装跟随）
  --mode file     文件级安装（默认，解压 zip）
  --mode installer 调用 Inno 安装器（保留旧行为）
  --overwrite     已存在安装时执行覆盖安装（默认询问）
  --keep-data     保留数据目录（默认开启）
  --fast          仅大小校验，跳过 sha256
  --smoke         安装完成后启动冒烟验证
  --yes           免询问
```

交互模式（Windows 对话框 / Linux zenity → CLI 回退）：

1. 展示检测结果：本机画像、目标目录（默认值可编辑）、已装版本 → 新版本。
2. 确认目录（支持输入任意路径，含中文路径）。
3. 确认覆盖（仅已装时）；展示将保留的数据目录列表。
4. 进度提示：停止服务 → 备份 → 解压 → 校验 → 切换（百分比进度条，沿用启动器 splash 风格）。

## 7. 发布流程改动

| 步骤 | 新增动作 |
|---|---|
| PyInstaller 打包 | 不变（`dist/QLH-Edge-Inference/` 输出） |
| **文件级包生成** | `python packaging/make-filepkg.py --variant cpu --tag v0.1.8` → 输出 `packaging/dist/QLH-Edge-Inference-v0.1.8-cpu-files.zip`（含 manifest 全量校验） |
| Inno 安装器 | 不变，继续产出 exe |
| 上传 release | exe + `*-files.zip` 同时上传；serve.py `/latest.json` 清单自动含 zip（按资产扫描规则，见引导器方案 §5.3） |
| 版本号清单 | 沿用打包 README 既有清单；`make-filepkg.py` 读取 `src/__init__.py.__version__` 避免手写不一致 |

## 8. 安全与健壮性

| 项 | 措施 |
|---|---|
| zip slip | 每条目路径 `posixpath.normpath` 后必须等于相对路径且不以 `..`/`/` 开头；越界条目整体拒绝 |
| 清单交叉校验 | 解压前校验 zip 条目集合 ⊇ manifest.files（缺失/多余均报错） |
| 校验失败 | 丢弃 `.new`，不触碰现有安装 |
| 数据保护 | `keep` 清单项绝不进入备份/替换路径；备份前对 keep 项做存在性复核 |
| 同盘要求 | 目标目录与临时目录必须同盘（rename 原子性），跨盘时提示用户先改 `--dir` 或由引导器复制 |
| 权限 | 用户级目录无需提权；Program Files 跟随需提权时显式请求（runas/sudo），不静默提权 |
| 杀软友好 | 解压用标准库；停止进程用 `taskkill`/`kill` 而非脚本化暴力扫描 |

## 9. 测试方案

`tests/test_updater_install.py`（pytest，构造小型 zip 夹具，不联网）：

1. 目标目录决策：默认（manifest）/ 配置 / 环境变量 / CLI 优先级；`%LOCALAPPDATA%`/`~` 展开。
2. 全新安装：解压 → 校验 → installed.json 写入；`--fast` 仅比对大小。
3. 覆盖安装：旧目录备份（rename）→ 解压 → 切换；keep 数据（models/node_config.json/db）原位保留且不被覆盖。
4. 回滚：注入解压失败 / 校验失败 / 切换失败 → `.bak` 恢复、installed.json 回写旧版本。
5. zip slip：构造 `../evil`、绝对路径、盘符条目 → 全部拒绝。
6. manifest 交叉校验：zip 缺文件 / 多余文件 / sha256 不匹配 → 报错归类。
7. 停止实例：mock 端口探测与 taskkill/pgrep；停止失败中止且不产生半成品目录。
8. `make-filepkg.py`：从夹具目录生成 zip，往返校验 manifest 与内容一致。

## 11. 风险与待确认

| 风险/事项 | 影响 | 对策 |
|---|---|---|
| 文件级包与 Inno 目录布局漂移 | 升级后行为不一致 | 发布脚本从同一 PyInstaller 输出生成两物，构建期 diff 校验 |
| 大包（CUDA 1.7GB）全量 sha256 耗时 | 安装慢 | `--fast` 大小校验 + 发布侧预生成校验；默认全量可关 |
| 旧节点无 installed.json | 无法判断已装版本 | 以目录存在性 + 目录内 `src/__init__.py`/版本标记兜底 |
| 覆盖安装时用户正打开界面 | 文件占用 | 停止流程先行 + 交互确认；占用无法释放则中止回滚 |
| Inno 与文件级安装混用卸载 | 卸载残留 | 文件级安装写独立卸载标记（installed.json + 卸载时删除自身目录）；README 说明推荐卸载路径 |
