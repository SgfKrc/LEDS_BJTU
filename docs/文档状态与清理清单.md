# 文档状态与维护规则

> 状态：**现行**
>
> 更新日期：2026-10-02
>
> 适用范围：`docs/` 下全部文档，以及仓库内其他随代码维护的说明文件的状态标注与维护纪律。
> 归档清单见 [archive/README.md](archive/README.md)。

## 1. 状态定义

| 状态 | 含义 |
|------|------|
| 现行 | 描述当前代码、协议或操作方法，随实现持续维护 |
| 规划 | 尚未全部实现的目标方案，不作为当前能力说明 |
| 部分实施 | 部分内容已落地，未完成部分明确标注与验收 |
| 历史参考 | 部分内容仍有参考价值，但状态、接口、行号或版本信息可能过时 |
| 废弃 | 已被其他文档、代码或测试取代；不再维护 |
| 已剔除 | 文件已不在仓库中，不恢复其链接或引用 |

文档中固定的模型、节点数量、网络环境和硬件型号，除明确标注为测试样例或历史条件外，不作为系统边界。设备范围包括 Windows/Linux 台式机、工作站、服务器、笔记本、Android 手机和平板，以及后续通过能力协议接入的其他边缘设备。

## 2. 维护规则

1. 新文档在标题后声明状态与更新日期，并写明适用范围；英文镜像文档用 `> Status:` 与 `> Updated:`。
2. 现行文档与当前代码、接口和测试保持一致；函数签名与行为以源码为最终依据。
3. 规划文档明确已实现与未实现边界。
4. 计划落地后更新为现行说明，或标记历史参考、废弃；不长期保留错误的"待实施"状态。
5. 废弃文档在开头注明替代入口和废弃原因。
6. 已剔除文件不出现在 README、文档索引或现行文档链接中。
7. README 只链接现行入口和仍在执行的规划。
8. 源码路径、接口名、测试路径、版本号或状态结论变化时，同一修改内同步文档。
9. 模型名称相同不代表模型工件、量化格式、tokenizer 或执行引擎相同；涉及分布式执行时描述实际 artifact 与 Provider 边界。
10. "分布式"不用是/否表示；说明实际执行模式、Provider、参与节点、故障边界和降级路径。
11. 历史计划中的源码行号、工时估算和设备条件不构成当前接口或性能承诺。
12. 文档不保存数据库密码、SMTP 授权码、集群密钥或其他真实凭据；发现泄露立即脱敏并轮换。
13. **归档约定**：`docs/archive/` 存放已完成使命的历史文档（历史参考、废弃或终态叫停）。移入后不再随实现维护，头部状态行保持不变；文内链接只做一次迁移修复（指向活跃文档加 `../` 前缀）；归档不删除；归档操作同批完成 `git mv` → 链接修复 → `python scripts/run_doc_checks.py` 全绿 → 提交。归档文档的检索入口是 [archive/README.md](archive/README.md)。
14. **裁撤约定**：非交付类文件（工具脚本、实验件）先归档后删 —— `cp <原相对路径> _archive/<原相对路径>`（`_archive/` 被 `.gitignore` 忽略，本地保留、不进仓库）→ `git rm` → 提交信息注明"已归档至 _archive/"。交付类文档走第 13 条的 `docs/archive/`；两者分工见 `_archive/README.md`。
15. **结论更替纪律**：文档只写当前成立的结论，不留"保留旧结论 + 划掉"的写法。被推翻或更正的结论登记到 [跨框架层接力-实验数据汇总](archive/relay/跨框架层接力-实验数据汇总.md) 的「已推翻结论」节，一行一条：`旧结论` → `推翻/更正依据` → `现行结论`。同理，已完成的待办直接从待办删除，历史留给报告 JSON 与 git。
16. **数值结论引用纪律**："A 比 B 快多少"必须单变量分离 + 重复测量 + 给出 std；跨报告、跨脚本的数字不构成对照（参照物、口径、环境必须写在同一处）；与环境相关的量（GPU 时钟、线程数、设备、dtype）在结论旁注明条件。
17. **写作口吻与文档职责**见代理本地规范 `.agents/doc-style.md`（不入库）；机器可检项与其对应关系见 `.agents/doc-audit.md`。
