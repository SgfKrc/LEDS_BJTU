# 文档状态与维护规则

> 更新日期：2026-09-19
>
> 状态：现行
>
> 适用范围：`docs/` 下全部文档以及仓库内其他随代码维护的说明文件的状态标注与维护纪律

## 1. 状态定义

| 状态 | 含义 |
|------|------|
| 现行 | 描述当前代码、协议或操作方法，需要随实现持续维护 |
| 规划 | 尚未全部实现的目标方案，不能作为当前能力说明 |
| 部分实施 | 部分内容已经落地，未完成部分仍需明确标注和验收 |
| 历史参考 | 部分内容仍有参考价值，但状态、接口、行号或版本信息可能过时 |
| 废弃（待手动删除） | 已被其他文档、代码或测试取代；不再维护，确认无必要引用后可手动删除 |
| 已剔除 | 文件已不在仓库中，不应恢复其链接或继续引用 |

文档中固定的模型、节点数量、网络环境和硬件型号，除非明确标注为测试样例或历史条件，否则不得视为系统边界。QLH 的设备范围包括 Windows/Linux 台式机、工作站、服务器、笔记本、Android 手机和平板，以及后续通过能力协议接入的其他边缘设备。

## 2. 后续维护规则

1. 新文档必须在标题后声明状态、更新时间和适用范围。
2. 现行文档必须与当前代码、接口和自动化测试保持一致；具体函数签名和行为以源码为最终依据。
3. 规划文档必须明确已实现与未实现边界，不得把预研结论或计划能力写成当前支持。
4. 计划落地后，应将文档更新为现行说明，或标记为历史参考、废弃；不得长期保留错误的“待实施”状态。
5. 废弃文档必须在开头注明替代入口和废弃原因；删除操作由维护者手动执行。
6. 已剔除文件不得继续出现在 README、文档索引或现行文档链接中。
7. README 只链接现行入口和仍在执行的规划，不把废弃或纯历史文档列为推荐阅读。
8. 文档中的源码路径、接口名称、测试路径、版本号和状态结论发生变化时，应在同一修改中同步更新。
9. 模型名称相同不代表模型工件、量化格式、tokenizer 或执行引擎相同；涉及分布式执行时必须描述实际 artifact 和 Provider 边界。
10. “分布式”不得只用是/否表示；文档和测试应说明实际执行模式、Provider、参与节点、故障边界和降级路径。
11. 历史计划中的源码行号、工时估算和设备条件不构成当前接口或性能承诺。
12. 文档不得保存数据库密码、SMTP 授权码、集群密钥或其他真实凭据；发现泄露后应立即脱敏并轮换对应凭据。
13. **归档约定（2026-09-14 新增）**：`docs/archive/` 存放**已完成使命**的历史文档——状态为「历史参考」「废弃」或「终态叫停」的计划（如已叫停的微服务改造、历史阶段快照、一次性准入报告）。规则：① 移入后**不再随实现维护**，头部状态行保持不变；② 文内链接只做**一次迁移修复**（指向活跃文档加 `../` 前缀，指向同目录归档文档保持原名），此后不再更新；③ 活跃文档指向归档文档的链接统一加 `archive/` 前缀；④ **归档不删除**——保留 git 历史的可检索性；⑤ 归档操作同批完成：`git mv` → 链接修复 → `check_doc_links.py` 全绿 → 提交。
14. **工具/脚本裁撤归档约定（2026-09-14 新增）**：工具脚本、实验件等**非交付类**文件裁撤时，先归档后删——`cp <原相对路径> _archive/<原相对路径>`（`_archive/` 被 `.gitignore` 忽略，**本地保留、不进仓库**）→ 再 `git rm` → 提交信息注明"已归档至 _archive/"。**禁止静默物理删除**；git 历史仅作最终兜底。交付类文档走第 13 条的 `docs/archive/`（随 git 分发），两者分工与登记见 `_archive/README.md`。
15. **结论更替纪律（2026-09-19 新增）**：文档**只写当前成立的结论**。
    **禁止**「保留旧结论 + 划掉」（`~~旧~~ ⇒ 新`）的写法 —— 读者被迫逐条比对才知道哪句有效，且旧的错句会随剪切粘贴继续传播。
    被推翻/更正的结论**不在正文保留**，统一登记到
    [`跨框架层接力-实验数据汇总.md`](archive/relay/跨框架层接力-实验数据汇总.md) 的「**已推翻结论**」节
    （**一行一条**：`旧结论` → `推翻/更正依据` → `现行结论`，**不复述原文**）。
    同理适用于「待办」：**已完成的条目直接从待办删除**（历史留给报告 JSON 与 git），
    待办只留**未完成**项。示例：本轮即据此把 A4「2.325×」、B6「static 最优」、
    B1「长序列劣化」、B10「仅 256 档分叉」等从正文移除，只留一行登记。
16. **数值结论的引用纪律（2026-09-19 新增）**：「A 比 B 快多少」必须**单变量分离 + 重复测量 + 给 std**；
    跨报告 / 跨脚本的数字**不构成对照**（参照物、口径、环境必须写在同一处）。
    与环境相关的量（GPU 时钟、线程数、设备、dtype）必须在结论旁注明条件；
    本机 GPU 时钟存在 210–780 MHz 波动，**未锁频**的性能数字只作方向性提示。
